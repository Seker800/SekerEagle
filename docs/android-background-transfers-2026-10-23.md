# 安卓统一传输列表（0.8.0）

用户修正：手动上传应与自动备份共用传输入口，在后台处理，进度页面不能阻挡相册使用。本版替代 0.7.1 的上传对话框和“离开页面停止上传”规则。

## 使用方式

- 图库右上角三点 → 上传：系统选择文件后直接加入任务，不再二次弹出确认／进度／结果窗口。提示“已加入传输列表，可继续浏览”。支持继续选择文件追加队列。
- 三点菜单、更多页、备份设置页和传输通知都进入同一个“传输列表”。这里同时查看自动备份状态、近期文件结果与手动上传批次；正在执行的任务排在前面。
- 普通返回关闭传输页；搜索、看大图、照片／素材切换、旋转、锁屏或切到其他应用不会取消已提交上传。每批目标在选择时冻结，切模式不改变队列目标。
- 可以暂停正在上传／排队的批次、继续、只重试未完成项或移除非执行中记录。移除记录不会删除手机文件或服务器资源。已成功的文件在重试中不再读取。
- 自动备份目录与 Wi-Fi／电量等原有策略仍在“备份设置”，手动选择不隐式开启或修改自动备份。

## 实现与边界

图库 ViewModel 只观察 `NativeTransferManager`。应用作用域管理器持有手动队列，私有 dataSync 前台服务管理后台生命周期、通知和执行时限；Compose 的 `NativeTransferScreen` 将手动批次和原 Java 备份服务的进度装配到同一正常导航页面。自动备份与手动队列各自保留原有执行及认证适配，业务上传均复用 `BackupEngine`、`MultipartTransport` 和服务端入库规则，不复制两套照片／素材逻辑，不改网页或 API。

队列元数据保存在应用私有空间；分片检查点复用既有 SQLite 实现，使用手动批次命名空间。手动任务不创建、继承或读取可用于释放手机空间的备份回执。恢复时已确认副本也重新查询服务器，避免服务端资源已删除却因本地确认而跳过；未完成分片仍可接续。已完成的 URI 和计数随队列保存。

任务受 origin／deployment／owner 和固定模式约束；实际传输前重新核验认证主体。注销、换账号会停止旧工作并清理队列／手动检查点；普通 Activity 销毁和模式切换不清理。任务完成时刷新当前图库，正在看大图或多选时延后刷新，避免切图和选择丢失。

系统授予的持久 URI 权限尽力保留。进程被杀后，未完成任务恢复为待继续状态，用户在传输列表继续；系统或来源提供方已撤销文件访问时明确失败，需要重新选择原文件。前台服务并不绕过小米／Android 的网络、电量、强制停止或执行时间限制；系统超时后停止并保留可继续的任务，不承诺永久后台唤醒。每批最多 100 个文件，最多保存 20 个批次，可移除旧记录后继续追加。

## 验证

结构门禁检查图库不创建上传 worker、不装配阻挡式上传进度、后台服务不导出；并加入三类违规装配反例。真实隔离 API 回归覆盖选择器、两种模式上传、重复跳过、原件字节、失败后只重试未完成项及自动备份配置不变。

后台设备测试通过受控本机 HTTP 端点验证实际分片 PUT 和最终确认：上传与排队期间切模式、打开／返回传输页、重建 Activity，然后将 Activity 移至停止状态，两种目标仍分别完成传输；同时验证暂停执行中／排队批次、移除排队记录和继续上传。SQLite 回归验证手动检查点跨实例读取及与自动备份回执隔离；空队列前台服务自动退出，防止移除任务后遗留空通知。仅使用合成文件、隔离临时服务和模拟器，未连接生产或群晖。

最终验收：完整模拟器 45／45 项通过，无失败、无跳过；44 项 JVM 单测通过，原生结构门禁 11／11 通过。全仓库 lint、typecheck、unit test、build、format:check、architecture:check 通过，安卓编译、lint 和构建通过。已检查统一传输页截图；小米实机后台策略、通知权限及系统强制停止后的实际表现仍需实机验收。新版调试包不含测试账号或测试媒体资源。
