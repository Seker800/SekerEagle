# ADR 0004：素材与照片的独立图库作用域

日期：2026-10-18。状态：接受；配套照片路由、工作区与隔离验证已实现，尚未部署到现用实例。

## 决策

使用不可变的 `LibraryScope { ownerId, libraryMode }`，模式为 `MATERIAL` 或 `PHOTO`。owner 来自认证主体，模式来自经过验证的路由，资源归属创建后不可变。旧 `/eagle`、插件和迁移入口固定为 MATERIAL；新照片入口使用显式作用域，不能通过缺省参数获得全库访问。

复用资源、标签、处理和媒体底座；摄影元数据、人物与照片组作为独立领域扩展。禁止双重归属与原地修改模式；2026-10-19 用户明确新增「发送到」移动：通过独立目标资源及文件、源项回收和持久化幂等计划实现，普通接口仍不可跨模式访问。相同字节跨模式独立导入。

应用服务显式传递作用域；不得使用可变的全局 currentMode，也不得在请求执行中从当前页面推导上传目标。后台全库维护与按资源执行的工作任务有单独的系统职责，不借用户页面作用域运行。

## 数据约束

- 主资源、分类、设置、上传、导入和分析记录持久化模式。关联记录携带并校验同一模式，使用复合外键拒绝跨模式关联。
- 历史资源、软删除记录、任务和未完成上传回填 MATERIAL；保留 ID 和原对象键。
- 标签名称唯一性、导入幂等、去重和并发锁包含模式。原图分别保存，暂不实现跨模式物理去重。
- 资产 ID 全局唯一不代表允许跨模式访问。详情、媒体、批量和旧路由都校验 owner 与模式；错误模式返回 404。
- 创建后的模式变更由数据库拒绝；不能用 updateMany 或原生 SQL 绕过。

## 实施与发布顺序

先加入未暴露的作用域基础和 schema，再逐一完成服务边界，最后开放照片页面和写入口。数据库新增字段默认 MATERIAL 仅用于历史兼容；应用创建照片必须明确传入 PHOTO。旧 API 与旧 worker 不得在开放照片后混跑。当前只写迁移文件并在隔离测试实例演练，不部署或迁移现用实例。

只在后端的全部读写／媒体／后台隔离验收通过后，启用双模式 UI；不能以隐藏按钮代替后端边界。每个代码里程碑执行 lint、typecheck、unit tests 和 build，保存结果后提交并推送。

## 性能验证

复用现有 100k 图库性能与媒体内存验证作为基准；同数据规模下保持既有 DOM、瓦片与媒体缓存硬上限。模式切换不应保留双份无界列表或触发另一模式全库请求。地图、人物和照片组单独定义有界分页与任务并发预算后再启用。

## 取舍

共享表加模式边界便于保持通用行为一致，但要求全部入口与关联显式校验。复制两套表、服务与页面会产生长期漂移；将照片只作为标签或前端筛选无法满足隔离。基于完整独立相册服务的集成也不符合本次在 SekerEagle 内发展照片功能的路线。

## 当前不决定

切换 UI 的具体位置、照片默认时间线、格式扩展、地图供应方、人脸模型、照片组阈值、质量算法和是否写回 EXIF。保持已确认业务边界，提供可审阅的实现提案；未决项不阻止不依赖它的底座开发。
