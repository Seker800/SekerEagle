# ADR 0005：能力归属与运行时边界

日期：2026-11-01。状态：接受。部署状态见[现用运行](../current-runtime.md)。本决策修订历史共享规则对新增provider的笼统限制；现行契约见[架构](../architecture.md)与[门禁](../library-sharing-gate.md)。

## 决策

共享能力登记provider、持久模型、可用模式与能力依赖，由同一登记生成两种模式的装配。模式token为必需依赖，漏装配启动失败。拥有表不等于独占所有读取；生命周期和写事务仍由既有权威入口维护。

按职责拆分可独立使用的实现。资源数据库投影与公开序列化从应用服务提取，查重读取卡片不再依赖整个资源应用服务。服务内原始SQL并非错误，不为统一文件形状引入通用仓储、复制回收事务或改写成熟的权限与版本守卫。

任务种类、车道与持久处理器标识从纯规则包导出，Prisma枚举用契约测试对照。JS和SQL确实需要两种执行表达，以真实数据库的时段等价测试保持一致；非法时段两边均拒绝执行。

缓存键的生成与识别放在同一工厂，先收拢资源列表、库计数和操作回执。保持原键形状、owner／mode／隐私修订与已加载分页；这一改动不引发数据迁移、额外SQL／S3调用或整列表刷新。

## 门禁的能力与限制

静态门禁覆盖共享provider归属、登记依赖环、模式token与包／进程依赖方向，识别静态及动态导入。运行时装配契约验证身份和漏装配失败，隔离数据库测试验证读取与发布语义。OpenAPI生成差异检查进入CI；已有响应schema覆盖仍需按真实接口逐步补齐。

不把文件长度、原始SQL数量、模式字面量数量或新增抽象数量作为架构正确性的证明。静态登记无法证明任意SQL的可见性，职责提取也不等于运行提速。本次保留原权限、版本、租约、幂等、outbox和独立执行器；后续拆大页面或worker调度须围绕独立责任及可验证行为，避免只搬代码。
