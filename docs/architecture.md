# SekerEagle 架构现状与边界

本文描述当前代码的稳定契约。部署镜像、机器、进程和模型位置由[现用运行状态](current-runtime.md)单独记录；历史决策保存在[归档](history/architecture-through-2026-11-01.md)，不将当时的“本地候选”当成当前发布状态。新增功能先明确能力归属及写入入口，再修改实现。

## North star

SekerEagle是单owner、自托管的个人图片工具，规模锚点为约六万份照片／素材和单张最高6100万像素，默认服务网页与桌面。产品取舍与真实资源预算分别由[产品边界](product-frame.md)和[性能预算](performance-budget.md)维护。

素材和照片是导入托管、业务隔离的两个模式，共用图库与基础能力。认证主体推导ownerId，模块注入不可变libraryMode，资源不能同时属于两个模式。跨owner统一404；私密访问、当前媒体版本及租约守卫在读取和发布时复核。认证、数据正确性和不丢数据优先于吞吐，产品不设置防想象中用户滥用的配额。

共享约束保护的是唯一事实来源和写入语义，不是文件数量或类的名字。允许按能力拆目录、应用服务和模块；拆分后仍须复用原权限、版本、事务及队列原语，不能派生出照片版上传、删除或选择系统。API的Prisma／SQL是现有持久化适配实现，资源读取投影与对外序列化由`eagle-asset-projection.ts`独立维护，查重不再为读取卡片依赖整个EagleService；不为形式上的四层图增加转发端口或通用仓储。

## 能力归属

共享能力由`apps/api/src/eagle/library-capabilities.ts`登记并装配；同一provider只归属一个能力，模式差异显式登记。摄影专属服务在`apps/api/src/photos`装配。能力拥有自己的表与写入入口，引用EagleAsset不等于拥有其生命周期。

| 能力                   | 权威入口与状态                                                     | 依赖与执行位置                             |
| ---------------------- | ------------------------------------------------------------------ | ------------------------------------------ |
| 资源、标签、可见性     | EagleService／EaglePrivacyService及既有资源事务                    | API读取／接收修改，固定owner／mode         |
| 上传与导入             | EagleUploadService、原上传会话；导入应用服务和适配器               | 认证直传S3，原发布事务                     |
| 发送                   | EagleLibraryTransferService／EagleLibraryTransfer                  | 独立operations；创建独立目标，成功后源退役 |
| 操作进度与回收         | EagleAssetOperationService及operation／item                        | 独立operations；复用原回收与租约事务       |
| 查重                   | EagleDuplicateService、指纹／分组／忽略表                          | 原操作队列；严格原图证据，批量回收         |
| 搜索与索引             | EagleImageSearchService／EagleVectorService及原索引                | API读取；模型与索引计算在独立worker        |
| 人物、地图、统计、整理 | PhotoManagement／PhotoMap／PhotoStatistics／PhotoAgent服务及各自表 | PHOTO专属；沿用共享资源和发布守卫          |
| 媒体处理               | 原EagleMediaJob与library-core任务规则                              | 独立worker；Mac／NAS位置以运行文档为准     |

新能力必须登记所属provider、持久表及依赖；新增共享模块不自动被禁止，也不能因为“两个模式都注册了”就默认通过。通用控制器继承只用于复用同一路由实现，摄影专属入口应明确自己的业务边界。

所有Prisma模型必须恰有一个归属：共享能力在上述登记中声明，认证、部署与摄影专属领域在`apps/api/src/model-ownership.ts`声明。门禁双向检查登记与schema，新增表、漏登记、重复归属和不存在的模型均失败；领域登记不参与共享provider装配，不将认证或摄影服务塞入通用模块。

## 进程与写入

2026-11-01 常用信息读取候选：正式数据仍由原表与写事务拥有。共享列表可选择独立 `library-reader` 宿主维护可重建的内存投影；HTTP 进程只调用有认证的内网查询协议，候选 ID 仅按页返回，随后用原权限与筛选条件读取当前页。筛选直接解释已有 `AssetSearchWhere`，与 SQL 适配共用字段／关系登记，采用 Eagle 已核实的数组遍历、短路判断和标准排序；不新增位图或自创排名算法。语义等未支持能力完整回退 SQL。

投影更新通过原事务内的语句级变更记录交接，owner／mode 修订行保证提交水位不跳过晚提交事务；独立读取宿主批量追赶，不在 API 放后台轮询。修订和日志是可丢弃的派生交接状态，不是业务事实或第二条业务写入口。实例重启先一致性重建，日志缺口重新重建，未就绪或资源不足时继续原读取。上线与预算须由隔离数据库、最终镜像和双端测试另行证明，本段不表示已部署。

API负责认证、受理、持久化意图和查询，不执行后台业务轮询。上传终结恢复、对象清理发现和全局维护由独立operations宿主显式装配、启动与排空；API注册的领域provider保持惰性，构造与模块生命周期不得自行启动业务定时器；operations为PHOTO装配原摄影修订observer，为MATERIAL保留通用上传语义。原上传会话、发送journal及对象删除outbox继续保存事实，不为迁移宿主复制队列。独立operations负责主动批量操作和查重；独立业务worker领取唯一持久媒体队列，媒体节点按固定能力执行有界计算。暂停／时段、模型兼容、资源版本、租约和隐私是执行条件，进度展示不替代这些条件。

发送允许在同owner的两个模式间显式移动：新建独立目标业务记录，在同一发布事务移交不可变对象所有权并退役源项，源不进回收站。历史复制计划保持可恢复，物理删除通过唯一outbox，不能删除已由目标接管的对象。

删除／恢复／查重调用共享回收事务，不因拆能力另写版本或实况组件校验。永久删除受确认与备份保护；普通删除立即更新界面，后台回执局部对账，进度不得裁剪已加载分页或重置滚动。

元数据操作的领取、批次事务、主体／私密／租约守卫和终态回执由 `EagleAssetOperationService` 统一拥有。删除、恢复与查重清理共用 `publishMetadataBatch`；能力处理器仅在传入的事务内执行业务规则，查重的 `applyCleanupBatch` 不另开事务或发布队列状态。复用现有元数据批量配置，失败的批次完整回滚后隔离冲突项；事务预算不足时自动逐项退化，不把整个健康批次一起标为失败，也不提高用户操作上限或事务时限。发送的对象移交／journal、扫描的有界原图计算仍沿用各自发布规则和同一持久操作队列，不能套入持锁的元数据事务。

新增后台能力须在真实数据库集成测试中验证一次领取及一次发布的事务成本、SQL／对象存储次数、部分失败与租约接管；测试入口为 `test:library-integration`，已由 CI 执行。唤醒路径的维护查询必须按实际待处理集合访问，不能因为重复调用一个共用函数就反复扫描无关历史。失败依赖传播使用仅包含待处理依赖边的覆盖索引；零依赖积压的回归约束数据库读取量，而不是依赖机器速度的毫秒阈值。当前验收和仍存成本见 [后台处理性能修复](background-processing-performance-2026-11-01.md)。

## Dependency direction

| 层／包                      | 可依赖                                 | 约束                                   |
| --------------------------- | -------------------------------------- | -------------------------------------- |
| library-core                | 纯类型、规则与算法                     | 无Node IO、Prisma、S3、API或worker依赖 |
| photo-render-core浏览器入口 | library-core及纯像素实现               | 浏览器不得导入独立`/server`入口        |
| photo-render-core/server    | Node worker、Sharp／Canvas及纯渲染规则 | 明确的服务端适配入口，不进浏览器包     |
| media-core                  | library-core与Node媒体工具             | 是服务端媒体适配包，名称不代表纯函数   |
| library-persistence         | library-core、Prisma                   | SQL编译和既有事务原语，不反向依赖应用  |
| API、业务worker             | 上述包及各自适配器                     | 彼此无源码依赖，共用规则从包导出       |
| web                         | 浏览器规则、契约与API适配              | 无数据库、S3 SDK或服务端入口           |

JS与SQL表达同一时段规则时以真实数据库等价测试保持语义；任务种类、车道和处理器版本从同一规则包导出，Prisma枚举由契约测试对照。包依赖门禁覆盖动态导入和相对路径，不能仅换import写法规避。

## 前端工作区

唯一LibraryWorkspaceProvider携带owner、mode及其API适配。共享页面装配能力；资源列表、计数和操作回执的查询键由同一工厂创建与识别，回执刷新不再各自猜数组位置。其他摄影查询仍按实际资源逐步归并，不声称所有查询已迁移。列表、计数、操作与摄影查询按其实际权限范围隔离；私密撤权清理对应数据、实体和blob。

按职责提取hook／组件应减少页面直接拥有的状态；保持同一选择、卡片、查看器与上传实现。摄影扩展可提供只读数据及动作槽，不能在通用布局中复制模式分支。已有大页面仍须继续按有验证的能力边界收拢，文件变短本身不是验收标准。

工作区选择由`useEagleSelectionController`统一管理选中项、范围锚点、选择模式和右键菜单；预览由`useEagleAssetPreview`管理互斥的图片／视频／连拍会话与权限作用域，图片资源生命周期沿用共用实现。元数据草稿由`useEagleMetadataDraft`管理字段与保存修订，后台刷新不能覆盖未保存输入，过期回执不能清除新草稿。页面负责装配动作，不再逐项清理这些内部状态。

图库与摄影查询键的构造、隐私位置识别集中在`eagle-query-keys.ts`；收拢保持现有键形状，人物选项与目录的隐私位置差异由工厂识别。JSON请求统一使用`api-client.request`，模式API仅适配路径、时限和错误文案。列表、详情、回收站和操作回执发布具名OpenAPI响应，资源投影与控制器受DTO类型约束，网页直接消费生成类型；其余端点按实际需求补齐，不把生成差异检查等同完整契约覆盖。

## Invariants

- ownerId由认证主体推导；跨owner404；上传DTO不接受ownerId。
- 数据库和对象存储与SekerChat隔离，测试／迁移／导入／恢复前运行安全目标检查。
- 原图不可变；编辑生成独立成片和原片参数关联，不覆盖源内容。
- 缩略图LRU当前为每工作区512项／128MiB；限额和到顶行为由实际代码及性能预算维护，不另设冲突数字。
- 私密投影、版本、租约、幂等、outbox和备份保持唯一写入语义。
- 每项批量改动说明SQL／S3／事务／前端刷新的端到端成本，不以文件移动声称运行提速。

## 页面读取效率

人物目录的照片数负责全局排序，先得到当前页，再为当页人物选择代表人脸；两步在原查询快照中执行，代表人脸仍校验主体、模式、私密、回收和媒体版本。统计在同一语句内先聚合同日、设备的频数，再按频数计算筛选和图表，原设备选项仍覆盖整个可见图库，不创建独立统计事实或失效系统。

智能文件夹相关度读取复用共用筛选SQL适配器，将完整筛选放在排名分页之前，仅为当页候选读取卡片。颜色仍使用原调色板计划，卡片读取再次校验原条件；并发变更导致候选失效时才继续补齐。语义与普通成员混合、快照绑定、原游标和照片堆叠规则保持。成本、前后样本及限制见[页面读取优化](read-path-efficiency-2026-11-01.md)。

## 基础颜色筛选

颜色规则与 MMCQ 量化由 `library-core` 共用，API 和 worker 不各自维护提取算法。基础匹配采用实测 Eagle 4.0 Build 23 的普通筛选默认规则：前两主色、25% 主色门槛、常规主色 >33%、白底 >50% 时次主色 >8%，CIEDE2000 <20 且 CIE76 <70；保留前两色号完全相等的例外。未新增精度滑块或手动标主色。调色板版本为 `color-v4-eagle-basic`，旧结果不能混充新版。

`AssetSearchWhere` 为内部查询树；颜色是显式 `colorMatch` 叶节点，由共用 SQL 适配器执行，不能直接交给 Prisma。布尔组合、计数、普通列表、语义查询候选和照片堆叠沿用同一判定。普通颜色分页在数据库中按 Eagle 的 CIE76 匹配分数排序，距离为0时保留 Eagle 的100回退分数（精确HEX为0.01），同分以原日期和 id 稳定排序；游标绑定 owner、模式、筛选上下文与权限。API 仅返回当页资源，不在 Node 中收集整库匹配 id。量化仍沿用现有 sRGB、最长边192像素的有界缩略图采样；规则和原始像素回归不等于与 Eagle 不同缩略图编码逐图一致。

新版迁移只把已有当前缩略图且缺少新版结果的图片加入既有后台媒体队列，并退役旧颜色处理任务；原件、用户暂停／时段与计算策略保持。部署前须排空并停止旧业务 worker，再迁移入队，并配套升级 API、业务 worker 和媒体节点；远端结果需证明当前调色板版本后才能发布。运行状态仍以 `current-runtime.md` 为准，本节不表示已经上线。

## 验证与变更

[共享门禁](library-sharing-gate.md)检查装配、能力归属和依赖方向；运行时契约和真实数据库测试检查权限、版本及发布语义。静态检查不声称证明任意SQL正确性，也不靠匹配“isPrivate:false”的次数证明隐私安全。

每个里程碑运行lint、typecheck、单测、build、架构和契约检查。最终API镜像发布前必须启动成品镜像验收；完整恢复使用隔离目标。历史ADR描述当时决策，后续生效修订应在原ADR标记并链接当前契约，部署状态不写回多个文档。

## 清空回收站的有界协议

清空入口只持久化原EMPTY_TRASH操作，独立operations通过emptyTrashBatch按冻结cutoff执行有限步骤；不再在API或一个事务内处理整库。原purgeAfter／任务是唯一续做事实，不增加队列或检查点表。每批标记／任务／事件原子提交，失败保留先前成功批次，仅合法空步骤发布命令完成。原回收／恢复／发送退休边界保持；API兼容变化、资源预算及自动反例见[后续修复](architecture-efficiency-review-followup-2026-11-01.md)。
