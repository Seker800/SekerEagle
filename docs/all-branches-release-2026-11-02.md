## 驱动升级联测发现与修复

真实扫描复现Prisma7对VALUES内无显式类型的数值按text处理，指纹批量写入出现integer=text错误；现对id／revision／hash显式标为text／int／text，已用真实双模式扫描回归验证。

Prisma7客户端query日志没有BEGIN，单靠旧日志会把事务数误报为零。成本夹具改为包装公开驱动协议记录queryRaw／executeRaw和已成功开始的事务，完整计入BEGIN、COMMIT与savepoint；不修改产品驱动或私有pg方法，不增加SQL。

同一100项发送夹具用原refresh正式镜像与新驱动对比：旧3500SQL／50执行事务；升级初值4200SQL／50，差异为原本无父记录仍查询的7层空标签／颜色子关系。共用发送事实投影改为按已有父关联集合读取子事实，空集合不发SQL，保留原锁与事务，恢复3500SQL／50事务及零对象复制；沿用原3800SQL回归预算。缺失当前关联仍冲突回滚。查重单页的空标签嵌套读取在新驱动多1SQL，六万项回归预算明确记为13（含事务控制），不按资源逐项读取。其他成本由完整数据库门禁继续验证。

新版驱动还把语句超时SQLSTATE放进driverAdapterError.cause。共用持久层现在同时识别旧meta.code和新驱动cause，上传发布与清空回收站恢复原可重试503／TRANSACTION_TIMEOUT语义；真实锁等待和整批回滚／同命令重试回归通过，唯一冲突23505仍按原错误失败。另以32764个IN项实测，新编译器在32766绑定后隐式拆两次查询；原内部协议预算修正为32766，用户仍可一次提交全部资源，由原自动分批执行，默认500／512工作批次不变。
