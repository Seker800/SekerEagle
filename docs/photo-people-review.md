# 人物确认体验修订

2026-10-30，本地整合候选；网页与桌面共用页面。用户要求本地完成后停止，后续自行统一push；未部署生产，也未修改真实人物归属。

人物确认同时展示两张未经裁剪的完整照片预览、人脸特写、人物名称和可见照片数量；点击任一照片仍进入共用查看器。这里的整图使用当前版本浏览预览，不强制下载 RAW 原件。代表人脸按现有浏览图可用像素面积选取，不能凭放大让低清人脸变清晰。

确认成功并刷新人物与隐私投影后自动进入下一题；失败保留当前题，提交期间禁用操作。双击的后续点击和按键长按不继续合并下一组，保留已有命名人物的名称规则。

候选由新增的摄影只读接口生成，独立于人物列表分页。服务端统计全库当前可见、未删除、PHOTO 模式、当前媒体版本且有可用浏览图的人物照片数，每张照片只计一次。从照片数最多的至多 400 个人物中比较同版本模型的有效 128 维原型，余弦相似度至少 0.25 才进入人工确认；这是人工复核候选阈值，不改变 worker 的自动归类阈值 0.45。排除已在同张可见照片中出现的组合。按双方照片数之和降序、较小一方照片数降序、相似度降序及固定 ID 排序，最多返回 100 题；不是全库所有人物组合的穷举列表。跳过仅在本次页面会话内有效，重新比较可重置，不写入“不同人物”的永久事实。

全库计数仍需读取当前可见照片事实，400／100 限制的是参与配对的人物和返回问题，不是全库计数的读取行数。计数直接沿现有索引关联基础表，避免物化全库事实后出现无索引的嵌套扫描；相似度只在 API 内对最多400份归一化原型计算，同框与代表图读取以候选 ID 明确限定；读取事务明确限制15秒，仍短于客户端30秒请求超时。

查询与代表照片装配使用同一 RepeatableRead 快照。owner 来自认证主体，私密权限来自现有授权，照片模式由摄影接口固定；不返回原型、embedding 或对象存储键，不新增队列、provider、数据库结构或自动合并行为。

回归覆盖整图展示、自动进入下一题、防重复提交、失败重试、服务端候选顺序、空候选和既有人物隐私操作；真实 PostgreSQL 覆盖照片计数、相似度、同框排除、旧版本、删除、私密与跨 owner 隔离。浏览器使用合成图核对布局与连续确认，不操作真实人物。

整合时保留既有“不同人物”持久判断与版本确认接口；优先候选读取使用独立的review-priority只读路径，避免与既有可分页review路由冲突。优先窗口耗尽后可继续遍历原全库分页，客户端按人物对去重，不把400人窗口当作全库结束。确认成功自动接续，失败留题；两个路径都排除已保存的不同人物组合。
