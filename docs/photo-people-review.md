## 何时询问

优先推荐与全库分页两个现有入口复用 `photo-person-review-evidence`，不能在优先窗口耗尽后退回宽松规则。当前 YuNet/SFace 128 维原型余弦至少 0.40 仅用于候选检索，不是提问许可。

每组最多读取三张不同照片的当前人脸：同一 owner／PHOTO、未删除、当前媒体版本、当前模型、READY 普通预览、检测置信度至少 0.90、预览中的脸宽高分别至少 48 像素、合法框与向量。重复照片不能充当多份证据。

- 双方各只有一份可用证据：余弦至少 0.60。
- 有多份证据：最佳配对至少 0.55，双方分别至少两份（只有一份的一方须该份）在对面找到至少 0.50 的匹配；双向最佳匹配的平均分取较小值，仍须至少 0.50。
- 排除同框人物、已经否定的组合、不兼容模型和双方都已命名的组合。多图冲突或低清人脸不会仅凭一个偶然命中进入提问。

这些是偏保守的工程阈值，不是身份概率，尚未以用户全库人工标注校准，不能保证零误判。[OpenCV 官方 SFace 示例](https://docs.opencv.org/doc/doxygen/html/d0/dd4/tutorial_dnn_face.html) 的基准阈值也不是私人图库准确率保证。此处宁可少问，不能为填满问题而放宽。

## 排序与显示

优先窗口沿原索引读取最多 400 个可见人物原型；先按相似度、再按照片数及稳定 ID 排序。每个人物最多进入四个待核验组合，总检索上限 800；避免一个大组占满窗口。核验证据后按双向匹配分数排序，每个人物在一批题中只出现一次，最多 100 题。分页入口仍每批 16 个未命名锚点、各两个候选，沿原绑定账号／权限的游标遍历，不把首窗口当全库终点。

确认页同时展示**实际匹配的两张脸**和各自完整预览，而不是另外选一张最大脸。没有合格组合时标题为“相似人物确认”，不空挂一道问题；可继续有界查找，不制造配对。

已命名人物保持原目录。未命名目录显示“待整理分组”，明确计数来自自动分组，同一个人可能占多个分组，这不是实际人数。统计排除只剩旧媒体版本人脸的空组。不会为把 2800 压成某个数字而批量合并真实身份；历史归属、人工命名与 worker 的自动归类阈值 0.45 本轮保持。

## 安全与验证

生物向量只在 API 内使用，不返回客户端或外部服务；现有 owner、PHOTO、私密、同框、人工否定、双方版本及合并锁继续生效。优先读取保持 RepeatableRead 快照，分页读取遵循原事务和 8 秒语句上限，不增加 schema、模型或工作队列。

单元回归覆盖低相似度、高照片数抢排、单例、多图冲突、独立照片支持、模型／异常向量与展示脸一致。真实 PostgreSQL 覆盖两个入口、低置信度／小脸、旧版本、同框、否定持久、跨 owner／私密、过期合并及两千人物／万张照片规模；网页回归覆盖人数说明、无候选不提问、提交与连续确认。测试使用合成身份，不能冒充真实图库识别准确率。
