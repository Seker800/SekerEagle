# 架构报告核验与修复记录

核验对象是用户提供的旧架构报告与当前代码。HTTPS 和备份按用户要求排除。旧报告中的生产 SQL 数字不是本次查询结果；本次没有连接生产数据库、执行真实清空回收站、迁移现用数据库、轮换现用凭据或部署。

## 已确认并修复

| 报告问题                                                    | 核验与处理                                                                                                                                                                                               |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 清空回收站先删对象、再被上传／采集 RESTRICT 外键阻断        | 确认。资产及任务加锁，在同一事务解除三类引用、写独立对象删除 outbox、删除资产；提交后才删对象。对象删除失败持续重试，事务失败不会删原图。                                                                |
| 清空隐藏私密项、PURGE 唯一键复用                            | 确认。按当前私密可见范围清空；复用已完成／失败任务时重新入队并更新租约。                                                                                                                                 |
| 依赖失败后子任务永久排队                                    | 确认。终态失败递归传播至依赖链，周期补偿，手动重试恢复同资产当前版本的失败链。                                                                                                                           |
| tag build 被杀后永久 PROCESSING                             | 确认。续租、过期回收、次数上限，候选快照退休；创建候选和发布结果均先锁定并验证租约。快照版本按全部历史版本递增，失败重试不会撞旧版本。                                                                   |
| 唤醒异常后没有兜底                                          | 确认。空闲、未来任务和异常路径都保留 30 秒轮询。                                                                                                                                                         |
| 语义构建阻塞预览、维护饥饿                                  | 确认。语义构建使用独立计数；媒体解码仍受原内存并发上限约束，后台／维护按配额优先领取，删除 outbox 独立推进。没有提高大图解码并发。                                                                       |
| 补齐任务只检查 job 是否存在                                 | 确认。按当前媒体版本读取预览、缩略图、颜色、金字塔、向量和 AI 分析事实；已保留结果不因 job 裁剪而重建，已完成 job 缺结果则重排。该核验检查数据库 READY 事实，不是逐对象 HEAD 校验。                      |
| 回收站中跳过的任务恢复后不继续                              | 确认。跳过原因持久化；恢复时只重排被回收站中断的工作，正常已完成工作继续复用。                                                                                                                           |
| 上传过期与最终失败对象不回收                                | 确认。24 小时未完成会话持久化为过期，清理 multipart 与临时对象；最终失败会话持久化清理意图，失败不确认；恢复循环防重入并捕获周期异常。                                                                   |
| manifest 接受上传侧拒绝的大小                               | 确认。manifest 与共享相机媒体能力使用相同图片／视频上限；无效大小按不支持项跳过，不进入永久 STAGED。                                                                                                     |
| 导入对账器未调度                                            | 确认。接入现有 maintenance，投影终态进度并对账已完成上传。                                                                                                                                               |
| 并发替换及旧分析／金字塔残留                                | 确认。原图替换事务加资产行锁；旧任务租约、颜色、向量、AI 标签及建议同时失效，旧金字塔前缀进入独立 outbox。迁移退休历史陈旧事实，不重跑全库。                                                             |
| API inspect 无资源上限                                      | 确认。两个模式共用一个检查信号量，串行执行，队列最多 32、每 owner 最多 4 项；Sharp 缓存 64 MiB、内部并发 1。超额返回可重试错误，后台恢复继续推进。                                                       |
| API／worker 使用 MinIO root                                 | 确认。仅 init 持有 root，应用使用独立随机凭据及单 bucket 最小策略；强制 bucket 私有。部署工具原子升级旧占位配置，保留有效的应用凭据，不轮换 root。                                                       |
| MinIO 必须添加 AbortIncompleteMultipartUpload lifecycle     | 原报告表述不准确。固定镜像的独立验证不接受该 lifecycle 配置；MinIO 自身已有 stale multipart 清扫。显式设定 24 小时过期、1 小时清扫，并配合应用会话 GC；没有配置会误删已完成对象的过期规则。              |
| MLX 继承整个 .env 并执行 source                             | 确认。只解析所需 MLX 键的字面值，子进程环境使用白名单，支持私有 token 文件；不执行 shell 配置。                                                                                                          |
| logout 与 refresh 竞态、访问 token 退出后仍可用、旧查询缓存 | 确认。前端认证 epoch、等待刷新、请求超时／取消、清理 QueryClient；服务端 token family 加事务锁，退出吊销整个 family，访问令牌也检查会话有效性。其他设备的独立登录不受影响。                              |
| Origin／PAT 权限靠逐路由记忆                                | 确认。浏览器已认证写方法默认检查 Origin；PAT 缺 scope 声明默认拒绝。公开登录／刷新保留原有 Origin 保护。                                                                                                 |
| ingestion 按裸 ID 更新、旧 finish 信任客户端 assetId        | 确认。ingestion 更新带 owner 与模式；旧 finish 返回 410，只保留服务端上传会话推导的正式完成链路。                                                                                                        |
| 主组修改丢失其他分组                                        | 确认。只移除旧主组成员关系，保留独立次级分组；membership 是分组集合，groupId 是所选主组，回填遗漏的主组 membership。                                                                                     |
| 状态指针未受 owner／模式 FK 保护                            | 部分已修复。dependsOnJobId 早已有复合 FK；本次补 activeUploadSessionId、currentSnapshotId、acceptedSuggestionId 的复合 FK，删除只置空可空指针，不置空 owner／模式；增加建议表外键查找索引。              |
| 向量不同空间混用、upsert 重写模型身份                       | 确认。空间身份不允许原地改写，不兼容配置明确失败；标签中心／建议／成员距离按空间与当前媒体版本匹配，补齐检查只承认当前空间；host 状态核对 revision。更换模型仍须另做显式空间迁移，不会自动重建既有图库。 |
| OpenAPI 缺查询参数与认证定义、只生成不消费                  | 确认。补完整列表查询参数、cookie/PAT 定义与媒体更新响应；Web 消费生成的更新契约；CI 检查生成漂移。未把全项目一次性换成新客户端生成器。                                                                   |
| 列表直接展开数据库对象                                      | 确认。资产公开字段改为显式投影，不返回存储 key、哈希、owner 及 purge 控制字段。                                                                                                                          |
| 领域筛选目录带中文且英语显示中文                            | 确认。展示标签移至 Web i18n，领域目录只保留字段、运算符、选项值及规则；英文覆盖字段、运算符、单位和选项。                                                                                                |
| mediaRevision 更新缺失                                      | 仍存在。更新接口和实体合并一起传播版本号，避免替换原图后用旧版本筛新 rendition。                                                                                                                         |
| 搜索 offset 翻页漏项／重复                                  | 确认。改为 tier、similarity、libraryAddedAt、id 的 keyset；游标绑定 owner、模式和条件。删除锚点不影响继续读取，不依赖锚点行仍存在。排名被用户编辑时仍属于实时搜索，不承诺冻结快照。                      |

## 不是当前缺陷或不适合并入此次修复

- 「照片仍只是规划」「schema、缓存和查询没有模式」已过时：当前有不可变 libraryMode、复合外键、模式作用域及共用逻辑门禁。不能按旧报告再实现第二套图库。
- PAT 永久有效是已有明确产品决定；撤销不存在或他人的 PAT 返回相同成功结果可避免泄漏归属，均保留。lastUsedAt 的写入频率是可优化项，不改变鉴权语义。
- RAW／相机视频已有共享能力与尺寸／时长预算，不按旧版仅常规图片的白名单回退。
- 巨型 service／页面仍有维护成本；本轮把新增恢复、空间校验、媒体事实与资源预算放入窄模块，没有为整齐行数进行大范围搬家。
- 单机无故障切换、不可变镜像发布与完整 typed client／统一错误 envelope、metrics／告警、SBOM 是独立工程方案，报告没有证明当前边界下的功能错误。本轮不切换部署拓扑、发布体系或重写所有客户端。
- 历史 migration 由校验和管理，不修改已发布 SQL 来重复执行；已有迁移重放、历史升级和原生 FK／索引检查在真实 PostgreSQL 测试中验证。Prisma 不能完整表达的列级 SET NULL 和部分索引以 migration 为准。

## 验证与生效范围

- `npm run ci:check`：共用门禁、lint、类型、各工作区单测、构建、格式和开源检查。
- `npm run contracts:check`：生成契约与提交版本一致。
- `npm run test:library-integration`：一次性独立数据库；覆盖事务回滚、删除 outbox 重试、替换失效、依赖失败、refresh/logout、数据驱动 reconcile、搜索删除／新增后的翻页，以及全库恢复。
- `SEKEREAGLE_TEST_STORAGE_POLICY=1 node --test scripts/testing/storage-policy.test.mjs`：独立 MinIO 验证私有 bucket、应用读写、跨 bucket 拒绝及管理权限拒绝。
- 页面验证：无照片月份的刻度留白，实际月份仍按日历跨度定位，保留动态放大和直接跳转。

数据库、安全和部署修复需要随正常发布流程迁移／重启后在现用实例生效；本次只提交代码并验证独立测试环境。

MinIO 命令与行为参考：[官方 policy attach](https://min.io/docs/minio/linux/reference/minio-mc-admin/mc-admin-policy-attach.html)、[官方 stale upload 配置源码](https://github.com/minio/minio/blob/master/internal/config/api/api.go)。本记录的权限结论以仓库固定镜像的独立运行测试为准。
