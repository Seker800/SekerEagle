# 图片向量搜索

2026-10-31 本地候选：主搜索继续精确且完整分页，筛选条件下推数据库，去除整库 ID 的 Node 往返；名称与标签使用保留字面匹配含义的 LIKE／ILIKE。明确标为样例的语义文件夹预览才采用 HNSW，已在六万条合成向量上验证实际执行计划使用索引；这不代表主搜索改成 ANN，亦不证明 NAS 上的延迟或模型召回质量。资源预算、对照数据和发布边界见 [本轮核查](search-query-2026-10-31.md)。下文 10 月 19 日为历史初次实现说明。

2026-10-19：普通搜索停止使用 AI 标签候选及标签向量，语义召回直接读取已有图片向量。本轮限代码与隔离测试；不部署现用实例，不重新嵌入真实图库，不调整用户已配置的后台 AI 打标开关。

## 搜索行为

- 名称和人工标签文字匹配保留；其后按图片与搜索词的余弦相似度排列。AI 标签不参与普通搜索召回，显式 AI 标签筛选与标签编辑仍可使用。
- 新搜索词只调用本地 Qwen3-VL-Embedding-2B 的文字嵌入接口，不调用 8B，不重新读取原图。模型、固定修订、1024 维、归一化、image-retrieval-v1／preview-webp-v1 空间必须与图片向量兼容。
- 同一账号、模式、空间和搜索词共用最多 128 项、5 分钟的文字向量缓存；进行中的相同请求合并。缓存不保存图片结果，翻页仍校验当前可见性。前端保留停顿后搜索。
- 默认最低相似度为 0.25，可由 `EAGLE_IMAGE_SEARCH_MINIMUM_SIMILARITY` 调整。它是初始工程值，不代表已经在真实中文图库上校准过。
- 模型离线、冷启动超过请求期限或配置不兼容时，返回 UNAVAILABLE，页面提示当前仅匹配名称和人工标签；不会悄悄改用标签语义搜索，也不启动补跑。缓存不保留失败结果。
- 原有 AI 打标任务配置保持独立；这次替换搜索链路并不等于关闭后台 8B 打标。

## 数据与分页边界

只比较指定空间中 READY、isCurrent、非空且对应当前 assetRevision 的图片向量；过期、失败、其他账号或其他模式的向量不能参与召回。SQL 参数化绑定文字与向量，私密和回收边界在候选查询与最终资源查询中均校验；最终复用统一筛选与智能分类条件。

分页使用 `(tier, similarity, libraryAddedAt, id)` 排序位置游标，删除上一页锚点或插入更靠前资源不引起 offset 位移；这是实时结果，不冻结用户编辑后的排名。游标绑定 owner、模式、查询、筛选、私密可见性、回收状态、搜索可用状态与空间。旧标签搜索游标不兼容，切换筛选或模型状态后需重新搜索。照片组投影仍使用相同可见条件。

当前使用精确余弦排名以避免全局 top-K 截断后丢掉筛选命中项。数据库已有向量索引，但本实现不据此宣称所有查询都能走 HNSW；六万级真实图库的端到端延迟及召回质量仍需后续实测。从标签召回切换到图片召回本身不要求重建图库向量；整体版本升级仍须执行仓库 migration，不能据此跳过迁移。缺失向量仍可通过名称或人工标签找到，补齐向量由原有独立任务流程负责。

## 验证

单元测试覆盖文字向量缓存、并发合并、空间修订不匹配、直接向量 SQL 与隔离谓词。独立 PostgreSQL 测试使用合成向量验证跨 owner／模式、私密内容、过期图片版本、组合筛选、分页和模型离线回退；合成向量测试验证检索链路，不证明模型对真实图片的语义准确率。

初次搜索改造时的历史证据（不代表当前测试总数）：根目录 lint、typecheck、unit test、build、format、compose config 和 OSS 检查通过；API 220 项、Web 267 项测试通过；24 项独立 PostgreSQL 集成测试及完整数据库恢复通过。实际公开照片上传／处理测试仍通过。浏览器确认共享搜索框、无 AI 标签扩展提示，以及本地模型未连接时保留名称匹配和照片组折叠；截图在 `.omx/artifacts/image-search-fallback.png`。这里没有执行真实 2B 推理质量评估或六万级生产图库延迟测试。

当前执行入口、隔离范围及验证缺口见 [测试覆盖与执行](testing.md)。空间身份不可原地改写；当前只提供兼容性拒绝，不包含自动模型升级流程。
