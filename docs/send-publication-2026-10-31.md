# 发送发布效率核查与本地候选

本轮没有 push、生产部署、生产迁移、数据库重启或参数变更。代码与隔离验收不能冒充生产性能改善。

## 诊断核实

- 只读检查确认现用 PostgreSQL `shared_buffers=128MB`、容器内存上限 3 GiB、共享内存 256 MiB；HNSW 索引约 985 MB。索引块读约5555万、命中约1.718亿，PostgreSQL缓存命中约75.6%。这里的读不等于物理盘读，操作系统还有页缓存。
- 当前发送计划采用 HANDOFF，独立目标接管原对象及 READY 派生物的独占生命周期；正常发送不需要 S3 COPY／HEAD／GET。历史未标记复制计划仍按原校验安全恢复。
- 原代码在两个 owner／模式隐私排他锁内写入 READY／current 向量，并立即匹配智能文件夹；四个发送发布事务争同一隐私锁。原队列严格选择最老操作，后来操作等待旧操作全部完成。这两条已通过隔离回归复现。
- 本轮生产采样时没有活跃 advisory 等待，不能重新证明过去三条等待、每张1.5～4.8秒或特定失败来自30秒超时。最新五笔单张操作从创建到更新约2.32～4.42秒，包含排队，并非纯插入时间。不承诺增加缓存后必然降到几十毫秒或提升一个数量级。

## 实现

1. 正常领取4项仍是自动内部批次，用户不拆批、不限制总量。并行准备 journal，单个发布事务一次取得隐私锁，逐项校验冻结版本并原子提交源退役、独立目标、对象所有权与完成回执。每项保持原 journal ID，崩溃后重放不生成第二目标。旧复制计划某项失败不影响准备成功的其他项；事务冲突仍隔离到单项处理。
2. 兼容向量以 PENDING、非 current 保存，不进入 HNSW。原独立 worker 按原暂停／时段／类别／租约规则领取 GENERATE_EMBEDDING，核对 owner、模式、活跃资源版本、当前空间全量模型身份与归一化条件，直接激活保存的向量。无对象下载、无重复模型推理；索引、智能文件夹匹配与任务完成同事务。激活前照片可浏览，语义搜索／语义智能文件夹等待后台完成，不把未索引向量冒充可搜索。
3. lastClaimedAt 落在原操作表；每次 SEND 领取按最久未服务排序，新任务在当前批次后获得机会，重启不丢轮转位置。元数据／扫描通道规则保持。
4. 事务超时保存 TRANSACTION_TIMEOUT，并在任务中心说明未提交项可重试；后台日志记录操作／项目ID、错误类型和数据库错误码，不输出原始异常消息、SQL参数、对象键或秘密。其他未知错误仍保守标记 OPERATION_FAILED。
5. 移除 transfer 内残留100张选择／200组件数量墙，重复ID归一化；HTTP入口仍进入独立队列，实际发布自动分批。

## 成本与资源

正常4项：1个领取事务＋1个发布事务，共2个，而非原1＋4＝5个；两个隐私锁各取得一次。每个目标仍有独立资产、必要关联及独立journal／回执，这是双模式隔离和安全重试所需写入，不能改成共享同一资源。复制标签／EXIF等关系投影仍按事实写入，本轮没有声称消除全部逐标签SQL。

向量激活后移到原 worker 的独立事务，每个保存向量一次HNSW激活，不是取消总数据库工作。普通推理路径多一次安全的缓存检查；没有缓存时继续原推理。前端回执／局部投影协议不变，未新增主图库分页重取或滚动重置。

内部批次由现有 EAGLE_OPERATION_SEND_CONCURRENCY（默认4）调整，约束每批事务时长、数据库连接／内存和旧复制计划存储压力；到批次边界自动继续并轮转，用户总选择不受限。发布预算保留30秒，超时回滚未提交事实并给出可重试回执。

## PostgreSQL缓存维护候选

`deploy/nas/postgres-cache.yml` 是可选覆盖文件，默认不会被加载；尚未在线应用。维护时只能追加到现场完整Compose链，保留当前连接、卷、镜像及其他覆盖。候选 shared_buffers=1GB／effective_cache_size=2GB／容器3GiB／shm512MiB；后者为规划器估计值，不分配2GB。索引约985MB不代表它能连同堆表／其他索引全部常驻1GB。

真实资源是NAS及PostgreSQL容器内存。上限不足可能导致OOM与服务中断，不能通过无限增大缓存提速；用户看到连接失败，应回退原覆盖并核查内存。用 EAGLE_POSTGRES_SHARED_BUFFERS、EAGLE_POSTGRES_EFFECTIVE_CACHE_SIZE、EAGLE_POSTGRES_MEMORY_LIMIT、EAGLE_POSTGRES_SHM_SIZE 显式调整。应用需独立维护窗口、备份和重启后只读复核；本轮不重启生产。

- RED 回归先复现：4项原为5事务，新操作进度为0；内部101项重放错误及同步索引路径也复现，再做实现。
- 隔离 PostgreSQL 的100张空白元数据合成场景：旧执行3750条SQL／125个事务，新执行3500条SQL／50个事务；入队均10条SQL／1事务，S3操作均0。新执行一次样本约2.07秒，旧样本约2.82秒，运行负载不同，不能当严格耗时A/B，更不能冒充NAS真实带EXIF／标签／大索引p95。
