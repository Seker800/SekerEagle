# 安卓固定测试图库

本机交互测试统一使用 <http://localhost:49813>。这是独立的持久测试服务，不是群晖生产，也不是每次回归创建的临时工作台。模拟器已经登录；账号与密码保存在本机私有的 `.local/android-lab/login.json`，不提交、不复制到日志或安装包。

## 下次继续测试

在仓库根目录运行 `npm run android:lab:preview`，恢复模拟器到同一个图库。入口无法访问时，先运行 `npm run android:lab:status` 检查原服务，确认 Docker 已启动，再运行 `npm run android:lab` 启动或复用服务，最后恢复预览。错误应在原环境中排查，不换端口、新建图库或删除持久卷。

筛选为空时先检查当前模式、所选条件和用户手工修改；不要重新铺数据或用新环境掩盖问题。自动化回归完成后也要恢复此固定预览，避免把临时测试账号或临时图库留给用户。

## 数据和使用方式

初始样本来自此前从用户图库只读抽取的 27 张 JPEG。原样本另存于私有 `sources/`；测试副本去掉来源元数据后，重新编码并补入测试 EXIF，通过现有认证上传与媒体处理流程生成真实缩略图／预览。没有写回生产图库，也没有把来源目录当外部图库。

初始照片、素材各 72 项，两个模式拥有独立资源、对象、标签与智能文件夹。标签包括旅行、人像、风景、城市、随手拍、收藏、精选；智能文件夹按同一标签查询，另外有高分收藏。副本包含三组相机／镜头、JPEG／PNG／WebP、未评分及一至五星、有／无 GPS 和跨多年的日期。城市、拍摄参数、标签、评分和日期均是测试信息，不能当作来源图片的事实。初始日期锚点保存在 `seed.json`，不会每天重写。

可直接测试的组合：照片选择「日常分类 / 旅行」＋「精选」标签＋JPEG＋至少四星＋Canon EOS R5＋RF 24-70mm＋有 GPS，能够得到结果。各筛选也可单独使用。互相排斥的组合仍会正常为空，验证器不会制造假响应。

`npm run android:lab` 启动／复用同一套服务，仅在尚未完成首次初始化时续接进度；初始化完成后立即跳过，不覆盖用户的改名、评分、标签、删除等操作。没有自动重置／重新铺数据的命令。用户修改导致某个预置案例为空时，先核对操作，不得为了校验变绿而补回用户删除的数据。

| 操作                            | 命令                          |
| ------------------------------- | ----------------------------- |
| 启动或复用                      | `npm run android:lab`         |
| 查看存活状态                    | `npm run android:lab:status`  |
| 只重启应用服务                  | `npm run android:lab:restart` |
| 校验预置筛选案例                | `npm run android:lab:verify`  |
| 安装当前调试 APK 并恢复固定预览 | `npm run android:lab:preview` |

预览脚本只接受一台模拟器，拒绝实体手机；通过正常登录界面连接固定图库，不写应用内部偏好或绕过认证。已安装 APK 另有私有缓存，清理构建输出后仍可恢复预览。重启服务时身份、密码及 JWT 配置保持不变，现有有效会话继续工作。

## 持久化和运行边界

- 用户级服务为 `com.sekereagle.android-lab`，登录后启动，异常退出由 launchd 重启；Docker 尚未就绪时保留数据并等待下一次重试。
- 容器为 `sekereagle-android-lab-db`、`sekereagle-android-lab-storage`；数据分别在同名前缀的 `postgres`、`objects` 命名卷，容器不使用 `--rm` 或临时内存数据盘。
- 数据库名仅为 `sekereagle_test`，数据库／存储仅绑定 loopback，使用独立随机凭据。启动和铺数据先执行安全目标检查，并核对容器／卷的独有标签；不匹配就停止，不接管或清空其他服务。
- 固定端口为网页／手机入口 49813、API 54991、数据库 55438、存储 59090；均不对局域网开放，模拟器通过 ADB reverse 访问。API／worker 复用当前构建产物，服务端代码更新后先 build 再 restart，不需要重新导入数据。
- `.local/android-lab/config.json`、`seed.json`、`runtime.json`、`verification.json`、`persistence-verification.json` 和有界日志分别保存凭据、一次性数据清单、进程、筛选及重启验证。读实时状态使用命令与这些检查点，不把文档里的初始数量当实时数量。
- 测试服务不调用现用 Mac 模型，不伪造语义向量；预置智能文件夹使用已有规则查询。未接入的语义推理／视频样本不能视作已经验收。

## 自动化与人工体验分开

自动化设备回归仍只允许随机命名的临时工作台；固定图库的容器名不能通过设备测试目标检查。测试结束后，如果本机已有固定图库，`verify-device.mjs` 会恢复模拟器到固定预览，不能把人工体验继续留在回归用的假图片／空库中。直接用 Gradle 跑定向设备用例时，结束后也必须执行 `npm run android:lab:preview`。

不要清理 `.local/android-lab`、上述卷或用户级服务，不要拿 `.omx/artifacts/photo-workbench.json` 当固定图库的身份清单。原模拟器临时工作台已归档到私有 `previous-temporary-preview/` 并退役，其他任务工作台保持原样。
