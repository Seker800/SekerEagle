# 编辑照片保存故障修复与验收

2026-11-01。生产保存失败已复现并修复。网关原来把对象存储请求的Host固定为loopback身份，而现用API按公开HTTPS地址签名；MinIO正确返回403 SignatureDoesNotMatch。编辑器又把上传阶段的错误覆盖成“照片保存失败，请重试”，导致看不出问题发生在上传。

## 修复

NAS网关生成函数显式接收实际S3_PUBLIC_ENDPOINT，只把经过校验的HTTP／HTTPS根地址host写入上传转发块；默认暂存环境仍使用原localhost身份。拒绝带凭据、路径、查询或片段的配置。转发身份来自部署配置，不使用客户端任意Host，原有签名、资源路径、owner和过期校验保留。打包器从同一API环境读取签名地址，避免两个配置分别写死。

生产只替换现有上传块Host并nginx校验／原地reload，完整旧配置和容器／Compose快照保存在NAS维护目录`maintenance/photo-save-20261101/`；不修改API环境或对象存储凭据。网页更新为`sekereagle/web:photo-save-c7643383a7d9`，固定源码c7643383a7d9dc52758c2767070a012ac99de22e。API保持87b73b650960，独立operations保持9de9bb766fb0，Mac原业务worker及模型、用户暂停时段、数据库均保持。

共享编辑器区分本地导出与上传保存阶段，上传失败显示已有具体原因；失败重试继续复用同一输出File及上传会话，导出错误仍不泄露内部异常。没有新增SQL、S3请求、事务或队列，也未扩大上传预算、增加限流或放宽签名。
