# 素材／照片双模式修改计划

日期：2026-10-18。状态更新于 2026-10-19：双模式、摄影功能及架构修复已有代码与隔离测试。下文阶段保留原计划结构，不表示仍需从阶段 0 重做；当前能力见验收记录。范围仍限代码与测试，真实图库导入和正式部署暂不执行。

## 1. 需求与决策效力

本文服从 [架构北极星](architecture.md#north-star) 与 [AGENTS.md](../AGENTS.md)。确定需求可以直接作为后续实现约束；技术方案是计划建议，实施前需用实际设计验证；待定事项不能由 agent 当成用户已经确认的需求。

### 已确定

1. 采用导入路线，由数据库记录业务信息、MinIO 托管原文件和派生媒体，不兼容群晖相册文件夹，不开发外部目录图库及双向同步。
2. 提供素材／照片切换入口，切换整个工作空间。现有素材模式保持原用途，新增照片模式。
3. 资源只能属于一种模式，业务完全隔离；无双重归属；2026-10-19 用户新增单选／多选右键「发送到」跨模式移动，成功后只在目标普通图库显示，源项进入原模式回收站；不原地修改已有资源的模式。
4. 相同文件分别导入两边时是独立资源，不共享编辑、评分、分类、替换、回收状态。
5. 共用上传、存储、预览、标签、筛选、权限、任务等底层能力，不复制两套系统。共用能力在两边具备一致的基本语义。
6. 照片新增人脸识别、GPS 地图、连拍／相似照片分组及清晰度选片建议、相机／镜头等摄影参数筛选。
7. 照片时间线采用等高横排与右侧年份／月份跳转刻度（2026-10-19 用户更新，替代竖向布局约定）。共享布局 hook 支持 justified 策略，卡片、虚拟化、缩放、查看器与操作继续共用；素材保持竖向瀑布流。日期索引覆盖全库，通过 scoped cursor 直接跳转，无需顺次下载前面的照片。固定高度的刻度以可见图库实际最晚／最早照片月份作为上下端点，按月份时间跨度定位，不延伸到空白年份；空月份不绘制刻度，位置留白。
   照片模式默认首页为按拍摄日期排列的时间线；无拍摄时间时回退至导入时间，在详情中标记。
8. 用户已授权后续实现细节由 agent 自行决定，连续完成可用功能和验证，不再等待产品选择回复。
9. 当前实施范围限代码修改与测试，可下载少量公开照片作为测试样本；群晖真实图库导入暂不执行。本文区分确定边界、原始计划与实施日志；已交付能力以验收记录及对应测试为准。

### 2026-10-18 验收修正

- 相机、镜头、GPS、人物筛选扩展原有共享筛选字段、快捷筛选和智能分类，不保留第二排摄影筛选或独立状态。
- 两种模式的共享筛选菜单默认收起，展开／收起按钮放在现有顶部工具栏；收起时整排筛选栏不渲染，不保留空行、高度或边框。收起保留已选条件，在顶部按钮显示生效数量及清除入口。重新进入工作区或刷新时默认收起，不持久化展开偏好。
- 素材／照片切换放在左侧栏顶部，替换图标与 SekerEagle 品牌区域；不单独占用全宽顶栏。窄屏侧栏收起时仍保留该切换区。
- 照片时间线、地图、人物依次放在左侧；移除中间重复导航和独立照片组页面。
- 导入后的摄影分析自动查找保守相似组，时间线只显示主图及张数。打开组内照片可按钮／键盘／触屏左右切换并指定主图，也可取消分组；所有原片保留。
- 分组封面和可见成员遵循当前搜索、规则、智能分类、owner、模式及私密边界。分页仍按原片游标推进，在展示层跨页折叠；统计含义保持原片数量，不能把折叠卡片数量当成原片总量。

### 2026-10-19 共用逻辑门禁

- 使用 TypeScript AST 检查通用页面装配、共享卡片、模式无关布局／查看器、摄影扩展依赖方向及通用 Controller／服务继承。
- 以故意制造分叉的反例验证检查器，覆盖率最低 80%；API 运行时检查继承处理方法与注册服务身份，Web 检查请求方法、载荷、凭据及返回行为一致。
- 接入 `architecture:check`、`npm test` 与 `ci:check`；允许差异及边界调整流程见 [共用逻辑门禁](library-sharing-gate.md)。

### 2026-10-19 相机格式兼容

- RAW／TIFF、MOV／AVCHD／MXF 等相机格式进入共用格式目录；真实内容经 LibRaw／FFprobe 校验，worker 生成统一预览，不改动原文件。
- 同时更新上传预算、任务调度、浏览器视频／悬浮预览、Range、镜像依赖及隔离上传验收。具体支持边界和性能限制见 [相机媒体兼容](camera-media.md)。

### 2026-10-19 实况照片

- 共享媒体链路支持 Apple 图片／MOV 标识配对及单文件 Motion Photo，使用同一查看器播放动态副本；不通过文件名猜测，不跨账号／模式关联。原件、权限、版本与删除恢复语义见 [实况照片](live-photos.md)。

### 当前实施范围与数据边界

- 可以编写和修改业务代码、数据库 schema 与 migration 文件、API 契约、测试和相关文档，并在隔离开发／测试环境验证。
- 可以在通过安全目标检查的隔离测试实例中执行 migration、seed、上传／导入和备份恢复测试；这不代表获准对现用图库执行迁移或修改。
- 暂不连接或扫描群晖真实相册，不从群晖取样，不导入部分或全部真实照片，也不创建定时扫描、同步或批量导入任务。代码测试完成不自动触发真实图库导入。
- 不向现用生产实例部署，不对现用数据库和对象存储执行迁移、回填、导入、清理或恢复。正式部署、现用数据迁移和群晖真实图库导入留待用户后续明确安排。
- 可以从公开、允许下载用于测试的来源获取少量照片文件，记录来源、许可和校验信息；样本下载不等于用户授权真实照片迁移。样本只上传到独立测试实例，不混入现用素材库或照片库。

- 临时下载样本和生成物使用被 Git 忽略的测试目录；只有许可明确允许再分发、确有回归价值的小型固定 fixture 才可随测试提交，并保留来源与许可说明。不提交真实私人照片或不明授权数据集。
- 公开小样本只能证明已覆盖的功能链路，不能据此宣称完成真实图库验收、识别准确率评估或大规模性能验证；测试缺口必须如实记录。

## 3. 建议的目标架构

### 3.1 共用底座与业务作用域

- 建议定义模式值 `MATERIAL`／`PHOTO`，组合为显式应用作用域 `ownerId + libraryMode`。名称与物理表设计在阶段 0 的 ADR 中落定。
- ownerId 继续只由认证主体推导；模式可以来自明确路由／经过验证的入口参数，但必须与目标资源持久化归属匹配，不能作为绕过授权的声明。
- 资源、分类、用户处理设置、导入来源与幂等记录具有明确模式；派生媒体、分析结果、组成员等通过受约束的资源关系继承作用域。
- 共用账号、认证、部署、存储适配器、模型运行时和宿主级资源限制。用户可编辑的标签、分类、建议和业务状态不共享。全局管理员任务视图可以明确分模式展示，不得静默聚合成当前模式的数据。
- 是否对纯技术对象做物理去重不是本轮目标；默认独立保存跨模式导入的对象，避免引入共享文件删除生命周期。
- 不把模式字段撒进所有函数临时拼条件。集中构造作用域，并通过窄应用服务、repository 条件与数据库关系约束维护边界；数据库约束不能仅靠调用方约定。

### 3.2 照片领域扩展

- 摄影元数据作为资源的独立扩展，保存提取来源、版本和可查询字段，不把全部 EXIF 无限制塞进列表返回。
- 人脸、人物、照片组、组成员和质量分析分别建模；照片组不等于版本，不改变成员原文件身份。
- 摄影模块调用共用媒体读取与任务端口，不能直接依赖 Web 页面，亦不能让共用媒体处理反向依赖人物或地图模块。
- 地图提供方、模型实现与质量算法通过适配器接入，供应方不成为领域规则。具体选型需先核查许可证、资源需求与运行环境。
- 数据库是事实源；模型结果是可版本化、可纠错、可重算的分析结果，用户确认与修正不能被重跑覆盖。

## 4. 分阶段实施

### 阶段 0：作用域设计与契约冻结

范围：审计 `apps/api/src/eagle/`、`apps/api/prisma/schema.prisma`、`apps/worker/src/`、Web 与桌面缓存；在 `docs/adr/` 新建双模式 ADR。

任务：

- 绘制全部读写入口清单：列表、详情、媒体、批量修改、标签、私密规则、智能文件夹、推荐、队列、回收站、清理、上传、导入、浏览器采集、Eagle 插件和迁移器。
- 明确 API 作用域编码、数据库约束、分页游标、缓存身份、导入幂等与迁移顺序。
- 旧客户端和旧路由继续只操作素材；照片使用明确的作用域契约。旧的按 ID 媒体／批量接口不能因此成为读取照片的旁路。
- 列出全局设置与按模式设置，区分宿主处理容量与用户业务运行开关。
- 对第 7 节待定项给出具体设计提案，涉及产品选择时再与用户确定，不能静默写成既定需求。

出口：每个入口都有作用域规则、兼容策略和对应测试位置；ADR 解释共享表与领域扩展的取舍，无未定义的跨模式读写通道。

### 阶段 1：数据模型与无损升级

主要位置：`apps/api/prisma/schema.prisma`、`apps/api/prisma/migrations/`、`apps/api/src/eagle/eagle-privacy.service.ts`、`apps/api/src/eagle/eagle-vector.persistence.ts`。

任务：

- 为资源、标签／分组、AI 标签、智能文件夹、私密规则、处理设置与导入身份建立模式作用域，调整唯一键、复合外键和索引。
- 对标签关系、组关系、规则依赖和向量建议，防止同 owner 下的跨模式关联；审核 SQL、触发器与事务锁，不能只改 Prisma 查询。
- 所有历史资源及相关数据明确回填 MATERIAL，包含软删除记录、待处理任务、导入记录和未完成上传；PHOTO 初始为空。
- 采用扩展、回填、验证、约束收紧的部署顺序，明确新旧 API／worker 是否允许并存。已有照片写入后不得用删除字段的回滚方案假装无损。

出口：隔离恢复库中验证历史 ID、标签关系、评分、对象键与状态保持一致；两模式同名标签可共存，非法跨模式关系被拒绝；迁移可重复核验，失败不删除原图。

### 阶段 2：API、上传与来源隔离

主要位置：`apps/api/src/eagle/eagle.controller.ts`、`eagle.service.ts`、`eagle.dto.ts`、`eagle-upload.service.ts`、`eagle-upload.dto.ts`、`eagle-media.service.ts`、`eagle-media-capability.service.ts`、`eagle-import.service.ts`、`import/`、`eagle-browser-capture.service.ts`。

任务：

- 集中落实读写作用域，覆盖详情、列表、搜索、计数、分页、批量操作、替换、回收、恢复和最终清理。
- 去重、并发锁、导入幂等和恢复均绑定模式；同一文件分别导入两模式产生不同资源和独立对象生命周期。
- 上传会话创建时冻结目标模式；暂停、断点续传、重试和页面切换不改变归属。拒绝同 owner 跨模式替换和绑定标签。
- 标签目录、分组、私密分类、智能规则与向量搜索都按模式查询；不存在跨模式标签中心或建议污染。
- 原图、预览、瓦片、媒体 capability 与桌面下载链接统一审计，404 行为覆盖同 owner 错模式访问。
- 保持浏览器采集、Eagle 插件与迁移器默认落入素材，不擅自扩展为照片采集入口。

出口：通过 owner × 模式安全矩阵，包括混合 ID 批量请求、重放上传、伪造模式、游标复用和媒体授权旁路；旧客户端仍可正常管理素材。

### 阶段 3：后台任务、AI 与维护隔离

主要位置：`apps/api/src/eagle/media-job-plan.ts`、`eagle-processing.service.ts`、`eagle-ai-tag.service.ts`、`eagle-vector.service.ts`、`eagle-maintenance.service.ts`、`apps/worker/src/job-claim.ts`、`main.ts`、`ai-tag-completion.ts`。

任务：

- 通用预览、颜色、向量与 AI 标签能力复用，不复制 worker；补齐模式归属校验与处理状态统计。
- 待处理、标签中心、建议审核、成功证据、回填、重试、暂停与维护清理保持模式隔离。
- 处理规则以资源模式和版本为依据；照片专属任务不能作用于素材。用户设置按模式生效，宿主容量可以共用。
- 新摄影任务不得阻塞现有交互式预览；定义并发、优先级、重试、取消、版本失效与错误展示。

出口：切换或暂停照片处理不污染素材业务状态；任务崩溃重启后可恢复，无跨模式分析写入或重复完成证据。

## 5. 核心验收矩阵

| 场景                           | 必须观察到的结果                                                         |

- 备份／恢复测试使用隔离实例；禁止连接、迁移或修改 SekerChat 数据。
- 下载样本简单测试仅在隔离实例执行；测试报告分别说明样本来源、真实／合成条件、实际覆盖范围和未验证内容。不得为了完成验收而擅自访问群晖真实图库。
- 每阶段检查依赖方向、共享代码和模式条件分布；不得靠复制现有巨型服务／页面或隐式全局 currentMode 推进。
