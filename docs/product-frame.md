# 产品定位与取舍（SekerEagle）

> 这份文档是 `AGENTS.md`「产品定位与取舍」的展开。目标：当需求没写全时，所有 agent 默认选择「个人自托管、效率优先」的实现，而不是多租户 SaaS 的防御式默认值。

## 1. 使用者与部署形态

- **单 owner、自托管、个人使用**；默认使用者只有本人。
- 不是对外注册的 SaaS，**不存在「其他合法用户」这个产品威胁模型**。
- 但服务仍通过公网 HTTPS 暴露（网页、桌面、安卓、下载站）；匿名访问、自动化扫描、误操作、数据损坏都是真实存在的。因此**认证、ownerId 隔离、跨 owner 404、输入边界、备份必须保留**——它们防的是匿名访问和意外，不是「多租户防滥用」。
- 默认使用端：网页 + 桌面。安卓只在用户明确提到时纳入范围。

## 2. 规模锚点

- 1 个 owner；约 6.4 万张照片/素材（现用库以 `docs/current-runtime.md` 的实时核验为准，不把快照当实时值）。
- 单张输入边界按 `packages/library-core/src/media-formats.ts`：图片 500MB / 1.2 亿像素，视频 5GB / 4 小时；常见高像素照片按数千万像素估算。
- API 单实例（同一进程含 MATERIAL / PHOTO 两个 module）、NAS 上的 PostgreSQL + MinIO、Mac 业务 worker 与媒体节点。
- 所有成本估算按这个规模，**不按「成千上万并发用户」算**。

## 3. 非目标

- 多租户 SaaS、公开注册、按用户计费/配额。
- 以「防滥用」为目标的产品级限流、配额、单次数量上限——除非它对应真实的内存/磁盘/请求体/时间边界。
- 外部目录图库、双重归属、仅靠前端过滤实现隔离（见 `AGENTS.md`「产品边界」）。
- 为了「看起来安全」而重复校验、重复 HEAD、重复读同一份数据。
- 为了「可能的客户端错误」而静默截断或静默禁用；应返回明确错误。

## 4. 冲突时的优先级

1. **不丢数据**：删除、发送、迁移的不可逆性，备份，outbox。
2. **不越权 / 不泄露**：认证、ownerId 推导、跨 owner 404、私密授权。
3. **结果正确**：事务、幂等、租约、版本守卫。
4. **吞吐与延迟**：用户等待时间、前台流畅度。
5. **防滥用 / 防御性重复**：没有真实威胁时优先级最低。

## 5. 必须保留 vs 可以去掉

**必须保留：**

- 认证、会话、PAT 保护；
- ownerId 从认证主体推导，DTO 不接受 ownerId，跨 owner 404；
- 上传/请求体的真实资源边界（内存、磁盘、像素、分片、请求体大小）；
- 不可逆操作保护（确认、回收站、outbox、备份）；
- 数据完整性（事务、幂等、租约、版本守卫）。

**可以去掉：**

- 只为「很多并发用户」存在的配额、限流、单次数量上限；
- 因为「可能有别的 owner」而给单次操作加的数量上限（owner 隔离已由 ownerId 保证）；
- 不防真实竞争的重复校验、重复 HEAD、重复读；
- 静默截断 / 静默禁用；
- 放在 API 进程里的「后台」任务；
- 进度更新时重置用户分页/滚动/选择。

## 6. 决策规则

1. **上限规则**：任何上限必须同时写清三件事——防的是什么真实资源、到顶时用户看到什么、如何用环境变量调整。写不出「防谁」就不加。超过请求体边界时，上限应小于该边界，并给出明确文案。
2. **后台规则**：「后台」= 独立进程或队列，不是 API 进程里的 `setInterval`。如果暂时只能在 API 进程里跑，必须有并发上限，并证明不会拉低前台 p95。
3. **前端上下文规则**：进度更新不得重置分页、滚动位置或选择。优先局部更新受影响项，或等整批结束再刷新。
4. **成本规则**：每个用户操作必须能回答端到端成本（SQL、S3、事务、前端刷新次数），参照 `docs/performance-budget.md`。
5. **默认简单规则**：不确定时选更简单、更快的实现；只有涉及数据安全、权限或不可逆操作时才加防护。
6. **文案规则**：错误信息必须说真实原因。超量不能写成「重复」；到上限不能静默无反应。

## 8. 评审问题清单

改动涉及批量操作、后台任务、进度刷新或新上限时，必须回答：

1. 这个限制防谁？到顶时用户看到什么？能否用环境变量调整？
2. 一条/一批数据的端到端成本是多少（SQL、S3、事务、前端刷新）？
3. 后台任务在哪个进程？会不会拉低前台 p95？
4. 失败/超时/部分成功后，用户的分页、滚动、选择还在吗？
5. 错误文案说的是不是真实原因？
6. 有没有 UX 不变量测试（不跳页、不静默、错误可见）？
7. 是否与 `AGENTS.md`「产品边界」「数据安全」冲突？

## 9. 如何修改这份文档

- 修改优先级、必须保留项或非目标时，同时更新 `AGENTS.md` 的对应摘要，并在提交说明里写清原因。
- 预算数字由 owner 在 `docs/performance-budget.md` 调整；不要为了通过评审而放宽预算，除非记录真实测量和取舍。
- 新反例只追加，不删除；它是对下一次实现的约束。
