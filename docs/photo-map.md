# 照片夜间地图

2026-10-19：移除浏览器直接请求 OpenStreetMap 海外瓦片的实现。默认地图改为应用自身静态资源提供的本地概览，以确定运行时不依赖国内访问海外地图的网络条件。

## 显示与使用

- 海洋／背景使用网站 `--eagle-bg`，陆地使用 `--eagle-panel-raised`，照片标记及交互控件使用 `--eagle-accent`，目前为炭黑／琥珀黄。城市标签、缩放按钮和弹窗同样适配深色。
- 本地数据提供陆地轮廓与城市名称，包括中文城市名；城市标签按优先级避让，每次最多 60 个。底图仅在进入地图时按需加载，不进入主 JS 包。
- 默认取全库有效位置范围，支持拖拽、缩放、点击位置组浏览照片，以及「显示全部照片位置」复位。切换选择或打开详情不会重新创建地图；容器尺寸变化会刷新画布。
- 明确显示「离线概览 · 不含街道级细节」。该数据集不是街道导航地图，也不能据此宣称具有高精度道路、实时交通或国内完整行政边界。
- 地图脚本、样式和数据均从本应用加载，无外部瓦片、字体、定位、坐标转换或地理编码请求，无需第三方地图 Key。应用服务器本身仍须可访问；资源首次加载需要能连接应用服务器，不能据此声称整个应用具备断网安装／缓存能力。
- 资源加载失败时保留照片位置交互并提示重试，不偷偷切回海外瓦片。照片 EXIF 坐标保持 WGS84；不套用高德／百度底图的偏移坐标。

## 数据来源与更新

Natural Earth 官方说明其矢量数据属于公有领域，允许修改与再分发：<https://www.naturalearthdata.com/about/terms-of-use/>。

提交的数据是 1:50m land 与 1:10m populated places 的精简版本，去除无关属性，保留地图几何、城市名称／坐标／人口和标签缩放级别。固定上游修订、下载地址、SHA-256 与处理过程记录在 `apps/web/src/components/photos/basemap/sources.json`，许可也记录于根目录第三方声明。

维护者可运行 `node scripts/maps/build-basemap.mjs` 从固定修订重新生成；它是显式维护命令，正常 build 和运行地图都不会访问该上游仓库。提交的两个数据文件未压缩合计约 2.1 MB。

街道级地图如后续需要，应独立接入天地图、高德等正式授权国内服务，并处理相应坐标系；本轮不添加未授权瓦片、不代申请或嵌入他人 Key，也不假装已经完成国内运营商连通性实测。本地资源方案通过移除外部地图请求消除翻墙依赖。

根目录 lint、typecheck、unit test、build、format 和 OSS 检查通过；最终 Web 回归为 49 个文件、271 项测试通过。新增测试覆盖仅请求同源打包数据、不创建外部瓦片层、照片名作为纯文本、失败提示与重试、回调更新不重建地图、城市标签可见性与数量限制。浏览器实看中文城市标签、黑黄配色、缩放、照片范围复位与深色弹窗，截图位于 `.omx/artifacts/night-map.png` 及 `night-map-popup.png`；独立测试页面仍在原本地地址，未部署现用实例。

## 2026-10-23 全库聚合与位置选片

这次修正首页分页造成的地图缺片：地图不再读取首页已经加载的资源，也不再提供「载入更多照片」。服务端聚合当前账号 PHOTO 库中所有已记录的有效位置，不依赖首页页数和封面是否已生成。GPS 缺失且没有已接受补充位置的资源仍不出点；原片中尚未提取的位置，需要现有元数据任务完成后才会出现在统计中。

### 聚合语义

- 初次查询覆盖全世界，返回全库有位置照片数与范围，前端自适应后按当前视口查询。计数包含单张资源，不以折叠后的照片组封面数量代替照片数。
- 使用随缩放细分的 Web Mercator 网格：缩小时是区域／城市尺度，放大后细分附近位置组，查询最大缩放 16，最细网格约为赤道附近 38 米（2026-10-24 从 level 14 细化至 20）；实际视口仍受 1024 个理论网格预算约束。不是行政区边界或城市识别，不能承诺每座城市恰好一个点；相邻城市在较远视角可能合并，城市在近处可分多个组。
- 标记放在网格代表点，属于模糊分组位置，不冒充每张照片的精确拍摄位置。2026-10-24 起采用真实照片缩略图与数量角标，标记落在本组照片最密集区域的代表坐标；网格仅用于聚合身份，不再将可见标记固定在网格中心。
- 一次最多覆盖 1,024 个网格位置。对不合理的「高缩放＋全世界」请求降低聚合精度，保持完整统计，不用 LIMIT 截断坐标。跨日期变更线的视口可查询两侧。
- 计数覆盖完整网格，选点成员使用同一投影与网格规则，避免视口边缘出现「圈内 20 张、打开 30 张」的差异。地图平移／缩放不改变已经打开的位置组，重新选点才改变照片范围。

### 查询与复用边界

`PhotoMapService` 是摄影专属聚合适配器。原始 GPS 仅使用当前媒体版本的元数据，缺失时回退当前版本的已接受城市级补充位置；不改写 EXIF 或写回推断坐标。所有查询在服务端限制 owner、PHOTO、未删除和私密可见性，来源关系同样匹配 owner／模式／版本。

接口：

- `GET /api/photos/photography/map`：`west/east/south/north/zoom`；返回全库总数、全库范围及当前网格计数。
- `GET /api/photos/photography/map/:cell/photos`：选点后按 chronologicalAt 和 ID 降序取成员，每页最多 60 张。游标绑定账号、PHOTO、私密状态和网格，不能跨作用域继续翻页。

点内分页是照片面板的浏览方式，不影响地图完整性。桌面显示右侧照片面板，窄屏改为上下排列；复用 `EagleAssetThumbnail`、共用有界加载服务和原查看器。打开当前页任意照片时，查看器使用该页的上下文，照片不在首页已加载列表中也能显示详情、翻片和视频。上下文绑定账号／模式／私密作用域，变化时清理。

地图明确展示全库位置，因此不再展示仅影响首页列表的搜索／快捷筛选控件，避免出现筛选了列表却误以为地图也已筛选的情况。本轮没有添加另一套通用筛选器。

### 验收与发布状态

本轮只在本机实现和验证，尚未部署群晖。没有重启群晖服务，也没有修改正在运行的独立封面复制任务。新增接口已更新 OpenAPI／生成契约。

`npm run test:photo-map` 生成客户端并构建工作区后，创建独立、仅 loopback 暴露、内存临时存储的测试 PostgreSQL；安全目标检查通过后执行测试 migration 与合成数据验证，最后移除该临时容器。它不会连接现用图库，也不挂载现用原片或数据库目录。回归包含跨 owner／模式／私密、过期坐标、补充位置、全库计数、完整成员三页无遗漏／重复、放大细分、极区／日期变更线及数据库坐标约束。

浏览器使用单独的本机合成数据页面检查实际 Leaflet 聚合、选点和缩放；实看桌面并排面板及 390×844 竖屏滚动，页面宽度没有超出视口。预览图来自仓库测试夹具，不是用户照片。此验收没有读取或修改生产图库数据，不替代发布后的真实图库抽查。

最终验证：API 单测 328 项通过、1 项既有条件测试跳过；网页单测 657 项通过。地图与成员面板行覆盖率 93.75%、分支覆盖率 83.33%；地图服务／网格单测及真实 PostgreSQL 集成验证通过。lint、全工作区类型检查、构建、共用架构门禁与反例、契约生成、格式和空白检查通过。

### 2026-10-23 城市名称

位置圆圈内增加城市名，选点后的照片面板显示完整位置名称。沿用同源打包的 Natural Earth 地名目录，不发送照片坐标给第三方，不受底图城市名称避让／最小缩放级别影响。地名是附近位置参考，不是行政区归属。没有可靠匹配时显示「附近区域」，不强行指定远处城市。

命名输入取自本组照片最密集的细分位置区域，避免用网格中心或把威海／北京取平均后落在中间城市。命名细分不改变地图分组、成员与计数；仍复用原有 owner／PHOTO／私密／媒体版本过滤。原始 GPS 和补充位置不改写。附近地名采用 60 公里搜索上限；照片覆盖范围对角线超过 60 公里时，短标签显示「城市名等」，完整名称为「城市名周边 · 多地合并」，不能把整个分组数量理解成该城市的精确统计。

本轮测试包括威海与烟台邻近、网格中心偏离实际照片、跨区域主位置选择、跨日期变更线、地名缺失／过远、城市标签不受底图缩放阈值影响，以及选点面板名称联动。标签解析器行／分支覆盖均为 100%；真实 PostgreSQL 验证主位置来源及原分组数量／成员不变。网页 662 项、API 328 项通过（1 项既有条件测试跳过）。本机截图仍为明确标注的合成数据；未查询用户威海照片的真实数量，本轮尚未部署生产。

## 2026-10-24 Dark 2D 风格与 Apple 式照片标记

用户选择 [Mapbox Dark 2D](https://www.mapbox.com/gallery) 的深色视觉与 [Apple 照片地图](https://support.apple.com/guide/photos/pht4c00b8ddc/mac) 的照片呈现方式，并明确选择自托管高精度底图。这里实现设计方向，地理数据来自 Protomaps／OpenStreetMap，不使用 Mapbox 服务。

### 底图与覆盖范围

- 自托管 PMTiles 归档由同源 `/maps/basemap.pmtiles` 提供，支持 HTTP Range；浏览地图不会向第三方发送查看区域或照片数据。下载维护是单独执行的操作。
- 本轮固定 Protomaps `20261023` 数据：全球 z0–7 概览；经度 73–136、纬度 18–54 范围的 z8–14 详细地图。可放大至 16，超过原始数据级别为矢量放大。范围外保持概览，不承诺全球街道覆盖。界面明确说明覆盖范围。
- 本机归档位于忽略目录 `.local/maps/data/basemap.pmtiles`，来源、范围、SHA-256 记录在同目录 `sources.json`。约 6.7 GB，不进入源码或应用镜像。本机可用空间不足以容纳约 139 GB 的全世界详细数据，因此采用区域提取。
- `node scripts/maps/prepare-map-archive.mjs` 使用 `.local/maps/tools/pmtiles` 显式提取并合并不重叠的缩放级别；临时目录完成后替换归档，失败保留原归档。工具来自官方 go-pmtiles v1.31.2；上游来源日期过期时需更新固定日期并重新审核覆盖与磁盘预算。
- 渲染层封装在 `self-hosted-basemap.ts`，复用现有 Leaflet 与 protomaps-leaflet 5.1；Canvas 字体使用系统字体，无远程字体、sprite 或地图 SDK 请求。该 Leaflet 适配库处于维护模式，单独封装使未来更换渲染器不影响照片查询、标记或查看器。
- 开发工作台直接读取本机地图目录；生产网页 Nginx 已预留只读文件路径 `/usr/share/nginx/maps/basemap.pmtiles`，部署时需单独挂载地图目录。本轮未挂载或部署群晖。无归档时保留原有 Natural Earth 概览，并显示“详细地图尚未安装”，不把它冒充高精度地图。
- 保留可见的 Protomaps／OpenStreetMap 署名。地理数据按 ODbL 发布，来源和许可见第三方声明。

### 标记密度与身份

照片使用 52px 方形真实缩略图、细浅色边框和数量角标，多张保留轻微叠层，地名在悬停／聚焦／选中时显示。位置采用组内最密集照片区域的代表坐标，网格中心不再决定可见位置；不随机移动照片、不改写 GPS。

原先横向 82px、纵向 92px 内都合并，导致地图过早只剩少量大组。现改为横向 42px、纵向 48px 的重叠判断，近景服务端网格从 zoom+2 改为 zoom+4，并将查询缩放上限从 12 提升至 16，避免底图已到街区但照片仍停在城市尺度，保持最多 1024 个理论网格的完整计数边界。页面没有 2–4 组限制；测试覆盖 48 个分布位置全部显示、计数守恒、确定性及当前版本封面权限。完全相同坐标或远景仍合理聚合，不能将少量实际拍摄地点伪造成更多地点。

点击视觉合并组放大两级；单一服务端组打开原成员面板。视觉合并不改变成员身份和游标，不将多个网格的合计数量当作单网格成员查询。缩略图复用共用加载调度、认证媒体和缓存，选片与大图复用既有组件。

单元回归覆盖 48 个位置的渲染、实际坐标、计数守恒、同源归档与概览退回、Range／HEAD／非法范围／非公开路径／写操作拒绝；真实 PostgreSQL 回归覆盖 owner、PHOTO、私密、媒体版本、完整计数与成员分页。工程门禁和本机浏览器验证结果以本轮实际日志为准。测试工作台复用先前 27 张只读群晖样本，带 GPS 样本本身只分布在少量地点；密集分布通过明确的合成测试验证，不篡改真实样本位置。
