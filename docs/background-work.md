# 后台工作与任务中心

任务中心集中查看当前模式、当前账号可见的后台工作。素材与照片共用页面、接口和调度规则，执行仍由原有 worker、上传恢复及业务模块负责。数据库中的原任务与派生事实保持权威，不另外复制一套任务状态。

## 使用

主导航进入「任务中心」；原待处理区域保留快捷入口，原「AI 内容识别」设置进入同一中心。默认按用途汇总，展开「查看处理步骤」才显示细项。统计单位为处理步骤，同一张图片可能包含多个步骤；已完成任务不等于所有派生事实都完整，缺失事实仍由原补齐机制修复。

卡片统一用实际操作命名，并精简列出「依赖／运算／执行」。运算标注计算位置与定性负担，不承诺耗时；时段取当前模式的已保存设置，单类或全局暂停直接显示「已暂停」。不受时段控制的工作写明上传、位置变化、确认删除或人工审批等触发条件。模型计算读取预览图，颜色提取读取缩略图；人脸使用图库服务器的 YuNet／SFace，已有向量索引不依赖 Mac 在线。

总览与卡片突出「剩余 X 项」，包含等待、运行和失败步骤，审批另列。没有剩余工作的类别显示「已就绪」，历史已完成数量仅在展开步骤后显示。

- 后台安排可选择随时、每日时段或暂停，时间使用北京时间，支持跨午夜。
- 图片内容搜索、颜色、人物、高清／动态组件、视频、语义文件夹和标签推荐索引可独立暂停或优先处理。
- 全局暂停与单项暂停都停止领取下一项／下一批，当前步骤正常结束，已有结果和断点保留。单项继续不会绕过全局暂停或部署禁用。
- 基础浏览、地图索引和必要清理继续自动维护。旧版 AI 标签生成已移除；已有标签仍可读取和筛选，2B 向量搜图不受影响。
- 优先级在数据库候选窗口之前应用；媒体领取每四轮保留一轮普通顺序，原通道配额继续防止后台与维护长期得不到执行机会。
- 前置未完成、前置失败、等待时段、暂停、部署未启用、处理服务离线、模型离线及模型配置不匹配分别解释。模型就绪检查不读取用户图片，模型断连不消耗图片或索引的业务失败重试预算；标签索引与已保存查询向量的智能文件夹可继续使用已有数据，只有需要新推理的步骤等待模型。
- 失败按类别重试，复核当前版本与可见范围。人工审批始终跳转到原审核流程，调度器不能代替用户同意。

## 任务来源

| 工作                               | 事实来源                           | 触发与运行边界                                                       |
| ---------------------------------- | ---------------------------------- | -------------------------------------------------------------------- |
| 入库浏览、图片分析、视频与高清派生 | EagleMediaJob                      | 上传、替换或显式补齐；共用媒体领取及发布                             |
| 上传入库                           | UploadFinalizationJob              | 上传恢复模块；不受分析时段阻断                                       |
| 批量导入                           | EagleImportRun                     | 原导入客户端与恢复流程                                               |
| 智能文件夹                         | EagleSmartFolderSemanticSnapshot   | 修改意图、模型空间变化与图片向量增量发布                             |
| 标签推荐索引                       | EagleTagSemanticBuild              | 标签／配置变化及显式重建                                             |
| 地图索引                           | EaglePhotoMapState                 | 变更合并后由原地图构建器分批处理                                     |
| 存储清理                           | EagleMediaJob、EagleObjectDeletion | 已确认删除后的可恢复清理；无私密权限时不暴露已脱离资源的对象清理数量 |
| 整理审批                           | EaglePhotoAgentSuggestion          | 仅显示仍可审核的当前版本可见照片；执行沿用原浏览器授权               |

手机上传仍由手机系统持有生命周期。宿主备份及一次性独立封面维护尚无此接口的实时报告，页面明确说明，不将其计为完成或混入总进度；本轮不修改群晖容器、挂载、DSM 或手机运行设置。

## 实现边界

- 共用 `EagleTaskCenterController` 提供 `eagle/tasks`；照片仅继承路由为 `photos/tasks`，固定模式。
- 普通浏览器主体可查询及管理自己的安排，写操作校验 Origin，DTO 不接受 ownerId；任务汇总不返回名称、内部错误、对象键或全局执行器负载。
- `library-core/task-scheduling` 提供分类、契约及时间窗口纯规则；`library-persistence` 提供同语义的数据库时钟领取条件和策略查询。
- `EagleTaskPolicy` 只保存账号／模式／类别的暂停和优先级。复合主键、模式不可变触发器与严格类别／优先级约束保护作用域；变更通过原 PostgreSQL 通知唤醒执行器。
- worker 心跳只报告执行能力及模型可用性。旧执行器没有能力字段时按未知处理，不凭空显示为部署禁用。
- 查询在数据库聚合，候选选择在限制条数前应用作用域、依赖、时段、单项策略和部署白名单；媒体发布仍校验原租约与资源版本。

## 验证

任务中心网页用例覆盖分组、等待解释、展开步骤、普通用户暂停、单项继续与优先、失败重试、人工审核入口、空状态、失败反馈和未保存草稿保护。服务用例覆盖权限装配、作用域、脱敏、各类等待原因和恢复断点；双模式客户端与架构反例门禁覆盖新增路由。

真实 PostgreSQL 回归验证当前版本、owner／模式／私密隔离、失败重排、SQL 时间窗口、索引断点保留、跨账号领取、优先顺序及暂停后的唤醒候选。原历史升级和完整恢复校验继续执行。

`PHOTO_WORKBENCH_TASK_CENTER=1 PHOTO_WORKBENCH_BASIC=1 node scripts/testing/photo-workbench.mjs --serve` 启动仅合成图片的独立本机验收，验证普通账号的真实 HTTP、未登录拒绝、Origin、严格 DTO 和模式隔离。任务中心使用独立 loopback 地址避免不同测试工作台的 Cookie 相互覆盖，状态记录为 `.omx/artifacts/task-center-workbench.json`；运行时需配置已安装的真实 ExifTool，不连接群晖或现用 Mac 模型。

## AI 标签生成退役

不再显示生成卡片或设置，不再提供扫描、启用和重试接口，上传及补齐不再创建此类工作，worker 移除 Ollama 标签推理与定时补队列。领取、唤醒、统计与重试均排除历史生成任务。升级迁移关闭历史开关，将未完成任务标记为退役失败并撤销租约；保留旧标签、关联和分析历史，不删除用户数据。当前仅本机验证，未修改生产。
