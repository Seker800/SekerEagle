# 后台工作与任务中心

任务中心默认汇总当前账号可见的素材和照片工作，可筛选全部／素材／照片。每张卡片标注所属库。素材与照片共用页面、接口和调度规则，执行仍由原有 worker、上传恢复及业务模块负责。数据库中的原任务与派生事实保持权威，不另外复制一套任务状态。

## 使用

主导航进入「任务中心」；原待处理区域保留快捷入口，原「AI 内容识别」设置进入同一中心。纵向按「立即处理／按时段处理／已暂停」展示，内部按系统固定顺序列出用途卡片，展开「查看处理步骤」才显示细项；审批单列，不能混入自动执行任务。统计单位为处理步骤，同一张图片可能包含多个步骤；已完成任务不等于所有派生事实都完整，缺失事实仍由原补齐机制修复。

卡片统一用实际操作命名，并精简列出「依赖／运算／执行」。运算标注计算位置与定性负担，不承诺耗时；时段取当前模式的已保存设置，单类或全局暂停直接显示「已暂停」。不受时段控制的工作写明上传、位置变化、确认删除或人工审批等触发条件。模型计算读取预览图，颜色提取读取缩略图；人脸使用图库服务器的 YuNet／SFace，已有向量索引不依赖 Mac 在线。

总览与卡片突出「剩余 X 项」，包含等待、运行和失败步骤，审批另列。没有剩余工作的类别显示「已就绪」，历史已完成数量仅在展开步骤后显示。

2026-10-25 状态修订：任务卡片醒目显示「计算ing／排队ing／已停止（X项失败）／已完成」。有实际运行步骤时优先显示计算中，暂停或部署停用不遮盖正在收尾的工作；没有运行时，有可等待任务显示排队，停止后有失败显示失败项数。计算中直接展示当前步骤，不必展开详情。任务中心在固定高度工作区中独立滚动，支持触摸、滚轮及键盘到底部，不靠整页溢出。

- 后台安排可选择随时、每日时段或暂停，时间使用北京时间，支持跨午夜。
- 图片内容搜索、颜色、人物、高清／动态组件、视频、语义文件夹和标签推荐索引可独立暂停。
- 全局暂停与单项暂停都停止领取下一项／下一批，当前步骤正常结束，已有结果和断点保留。单项继续不会绕过全局暂停或部署禁用。
- 基础浏览、地图索引和必要清理继续自动维护。旧版 AI 标签生成已移除；已有标签仍可读取和筛选，2B 向量搜图不受影响。
- 不提供人工优先级。固定规则在数据库候选窗口之前应用：同一可执行通道先做轻量缩略图颜色分析，再做向量、人物和重型原件派生；向量先于依赖它的语义索引。依赖、部署能力、时段和暂停先过滤，模型离线先跳过；媒体按本次入库时间优先新图，历史照片按拍摄时间从新到旧；每个资源每十六轮保留一次历史机会，无历史可做则立即回到新图。同一时间点内保留通道及任务类别的公平轮次。卡片顺序是偏好，不是必须清空一类才开始另一类。
- 地图保持原有每十五秒一步及媒体执行间隙限制，待执行入库积压不再无限阻止地图构建。当前运行中的媒体工作仍受保护。
- 部署停用的类别即使只剩失败记录也放在暂停栏，显示「服务器未启用」，不给无效继续按钮。模型／服务暂时离线、前置等待和自动重试仍显示在原执行栏目，不冒充用户暂停。
- 全部范围保存时段会分别更新两个库；原设置不同则先提示，部分保存失败会显示错误并重新读取两库真实设置，不承诺跨库事务。按单库筛选时只更新该库。
- 前置未完成、前置失败、等待时段、暂停、部署未启用、处理服务离线、模型离线及模型配置不匹配分别解释。模型就绪检查不读取用户图片，模型断连不消耗图片或索引的业务失败重试预算；标签索引与已保存查询向量的智能文件夹可继续使用已有数据，只有需要新推理的步骤等待模型。
- 失败按类别重试，复核当前版本与可见范围。人工审批始终跳转到原审核流程，调度器不能代替用户同意。

## 任务来源

2026-10-25 本地修复候选：Eagle 批量导入没有导入端实时心跳协议，因此导入历史不进入实时任务统计；RUNNING 仅是持久历史状态，不构成正在执行的证据。原记录、计数和续传断点继续由导入端管理。该修复按用户要求暂缓发布，现用生产状态见运行文档。

| 工作                               | 事实来源                           | 触发与运行边界                                                       |
| ---------------------------------- | ---------------------------------- | -------------------------------------------------------------------- |
| 入库浏览、图片分析、视频与高清派生 | EagleMediaJob                      | 上传、替换或显式补齐；共用媒体领取及发布                             |
| 上传入库                           | UploadFinalizationJob              | 上传恢复模块；不受分析时段阻断                                       |
| 批量导入                           | EagleImportRun                     | 原导入客户端与恢复流程                                               |
| 智能文件夹                         | EagleSmartFolderSemanticSnapshot   | 修改意图、模型空间变化与图片向量增量发布                             |
| 标签推荐索引                       | EagleTagSemanticBuild              | 标签／配置变化及显式重建                                             |
| 地图索引                           | EaglePhotoMapState                 | 变更合并后由原地图构建器分批处理                                     |
| 存储清理                           | EagleMediaJob、EagleObjectDeletion | 已确认删除后的可恢复清理；无私密权限时不暴露已脱离资源的对象清理数量 |
| 整理审批                           | EaglePhotoAgentSuggestion          | 仅显示仍可审核的当前版本可见照片；执行沿用原浏览器授权               |

手机上传仍由手机系统持有生命周期。宿主备份及一次性独立封面维护尚无此接口的实时报告，页面明确说明，不将其计为完成或混入总进度；本轮不修改群晖容器、挂载、DSM 或手机运行设置。

## 实现边界

- 共用 `EagleTaskCenterController` 提供 `eagle/tasks`；照片仅继承路由为 `photos/tasks`，固定模式。
- 普通浏览器主体可查询及管理自己的安排，写操作校验 Origin，DTO 不接受 ownerId；任务汇总不返回名称、内部错误、对象键或全局执行器负载。
- `library-core/task-scheduling` 提供分类、契约及时间窗口纯规则；`library-persistence` 提供同语义的数据库时钟领取条件和策略查询。
- `EagleTaskPolicy` 保留账号／模式／类别的暂停；旧 priority 列和输入仅兼容历史客户端，写入归零、领取忽略，不再提供人工调度入口。复合主键、模式不可变触发器与严格类别／优先级约束保护作用域；变更通过原 PostgreSQL 通知唤醒执行器。
- worker 心跳只报告执行能力及模型可用性。旧执行器没有能力字段时按未知处理，不凭空显示为部署禁用。
- 查询在数据库聚合，候选选择在限制条数前应用作用域、依赖、时段、单项策略和部署白名单；媒体发布仍校验原租约与资源版本。

## 验证

任务中心网页用例覆盖分组、等待解释、展开步骤、普通用户暂停、单项继续、固定顺序、失败重试、人工审核入口、空状态、失败反馈和未保存草稿保护。服务用例覆盖权限装配、作用域、脱敏、各类等待原因和恢复断点；双模式客户端与架构反例门禁覆盖新增路由。

真实 PostgreSQL 回归验证当前版本、owner／模式／私密隔离、失败重排、SQL 时间窗口、索引断点保留、跨账号领取、固定顺序与旧人工优先级失效及暂停后的唤醒候选。原历史升级和完整恢复校验继续执行。

`PHOTO_WORKBENCH_TASK_CENTER=1 PHOTO_WORKBENCH_BASIC=1 node scripts/testing/photo-workbench.mjs --serve` 启动仅合成图片的独立本机验收，验证普通账号的真实 HTTP、未登录拒绝、Origin、严格 DTO 和模式隔离。任务中心使用独立 loopback 地址避免不同测试工作台的 Cookie 相互覆盖，状态记录为 `.omx/artifacts/task-center-workbench.json`；运行时需配置已安装的真实 ExifTool，不连接群晖或现用 Mac 模型。

## AI 标签生成退役

不再显示生成卡片或设置，不再提供扫描、启用和重试接口，上传及补齐不再创建此类工作，worker 移除 Ollama 标签推理与定时补队列。领取、唤醒、统计与重试均排除历史生成任务。升级迁移关闭历史开关，将未完成任务标记为退役失败并撤销租约；保留旧标签、关联和分析历史，不删除用户数据。当前仅本机验证，未修改生产。

## 2026-10-24 本地三栏修订

本轮仅本机合成图库修改与验证，不访问或更新群晖生产、独立封面复制、Mac 模型或线上时段。卡片复用现有处理器与队列；固定领取顺序不代表把原件分析全部塞进同一个任务，缩略图输入的颜色分析仍有独立失败恢复。未接入的外部维护保持明确说明，不编造计数。

## 2026-10-25 两路处理与 RAW 浏览分离

- 群晖处理队列与 Mac 向量队列分别占用有界槽位；默认群晖 1、Mac 1，可以同时推进。复用原 EagleMediaJob 和租约，不复制业务队列或另建状态库。语义描述推理也使用 Mac 的同一槽位。
- 两路都优先最近 24 小时入库的图片，依据资源 libraryAddedAt，不依据任务 createdAt。刚编辑保存的独立副本有新的入库时间，继承的老拍摄日期不会压低优先级。历史照片按 chronologicalAt 从新到旧；素材按入库时间从新到旧。每个资源第十六轮尝试历史工作，再恢复新图；正在执行的一张正常完成，不强杀重做。
- RAW 先从经过尺寸、方向、比例验证的相机 JPEG 生成普通预览及缩略图，JPEG 不足或损坏才显影回退。完整上传／格式探测仍 unpack 验证传感器；快速浏览仍完整读取原件并校验已知 SHA，不拿小图冒充原图。
- 原 photo-source-details-v1 后台步骤负责 6000 像素无损编辑图、照片清晰度和相似特征、动态组件；它受后台时段及暂停控制，失败不撤销可浏览结果。普通相机 JPEG 和真正的 RAW 显影来源不会混用作编辑图。
- 补齐检查分开浏览与高清事实；缺编辑图不能导致基础浏览重复建队。当前版本浏览派生完整的普通修复任务直接复用既有结果，显式刷新请求仍执行。
- 日志按任务记录 resource、elapsedMs，以及 IMAGE／RAW_EMBEDDED／RAW_DEVELOPED 来源类型，不输出原始文件名或凭据。颜色提取与向量仍独立读取，本轮不做切片复用或全量共享解码。
- 验证仅在本机隔离 PostgreSQL、合成图片及模拟模型／对象存储进行，没有更新群晖或 Mac 推理服务。

## 2026-10-25 本地减少重复读取

- 浏览预览与 256／512 缩略图共用一次源图解码，后续编码读取最长边 1600 的有界原始像素，不拿有损 WebP 反复压缩。
- 普通照片的独立分析步骤保留，但改用当前浏览预览计算清晰度和相似特征，不重复读取拍摄 EXIF，不用小图尺寸或哈希覆盖原文件事实。使用小图不代表自动减少一个任务。
- JPEG 动态组件通过受校验的 Range 读取：只读元数据段和明确有效的视频部分；元数据不在头部时按 JPEG 段定位，避免丢失 Apple 配对标识。HEIC 为保留完整动态识别仍读取原件，但不再重复全尺寸解码。
- RAW 可复用长边至少 1024、比例匹配的相机内嵌 JPEG，小于 1600 时保留实际尺寸；原片上传验证不变，高清编辑仍走显影。RAW 工作目录不再生成无人使用的 camera-thumbnail。
- 替换原图按当前文件的已完成上传时间参与新图优先；不改变图库添加日期，也不让旧文件上传或补建任务冒充新版本。

后台时段和暂停规则未改变，新图向量仍遵守已保存的安排。RAW 编辑和大图切片仍保留现有触发方式；本轮不自动开启生产中的停用任务。
