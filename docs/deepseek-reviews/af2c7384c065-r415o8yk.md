## 问题 1（中，证据缺口）：文档中的“可覆盖安装、保留账号与缓存”缺少可核验证据

- **位置**：`docs/android-production-release-2026-10-31.md:11`；`docs/android-client.md:5`
- **触发条件**：用户手机已装有 0.9.12，按文档直接安装新 APK，不卸载旧版。
- **证据**：
  - 文档只断言“签名与 0.9.12 一致”“可覆盖安装，不必卸载旧版本”，没有记录签名证书摘要，也没有记录一次实际的 0.9.12→0.9.13 覆盖安装结果。
  - 同仓库以往版本对这类结论有实际升级证据（如 `docs/android-client.md:39` 的 0.9.9→0.9.10 覆盖安装读回旧缓存；`:27` 的 0.9.10→0.9.11 覆盖安装），旧版还记录过“签名摘要”（`docs/android-native-plan.md:37`）；本次记录没有对应项。
  - 固定预览脚本确实用 `adb install -r` 安装当前 APK 并检查登录是否保留（`scripts/testing/android-lab-preview.py:63,90-94`），但发布记录没有说明本次是否在已装 0.9.12 的模拟器上执行过该路径，也没有说明“缓存”是否验证保留（该脚本只检查账号/图库仍在）。
- **实际影响**：若构建机 debug keystore 与 0.9.12 不一致，用户会遇到 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`；版本号虽更高，但签名不同仍会拒绝覆盖。文档把“不必卸载”写成确定操作指引，目前证据不足。
- **修复方向**：补充 `apksigner verify --print-certs` 的证书 SHA-256（与 0.9.12 对比），或记录一次真实覆盖安装（保留登录与缓存设置）的结果；若未单独实测，应把措辞改为“预期可覆盖，未单独验证”。
- **待验证**：快照中没有 APK 文件，无法复核签名、字节数与 SHA。

- **位置**：`docs/android-production-release-2026-10-31.md:8-9,19`；`docs/android-client.md:13`
- **触发条件**：用户用 `sha256sum -c SekerEagle-0.9.13.apk.sha256` 校验，或任何客户端/脚本读取 `latest.json`。
