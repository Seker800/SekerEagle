# 向量搜索核查与效率修订

日期：2026-10-31。范围：两模式共用的网页／桌面搜索 API、智能文件夹样例预览。状态：本地候选，未 push／部署，没有操作生产索引、数据库缓存或模型。

## 判断与取舍

报告中主搜索按相关度精确扫描、组合筛选先搬运全量 ID、`strpos` 不适配既有 trigram 索引的代码判断成立。日期排序已有按索引窗口逐项核验的专用路径，不能概括成所有搜索都先全表排序。原报告提供的 NAS 耗时不作为本轮实测。

“精确搜索不符合行业实践”不成立。pgvector 官方默认就是精确搜索；ANN 换取速度时会牺牲召回。将主搜索改成固定 top-1000 候选，再在该集合分页，会截断其余匹配项；迭代扫描能缓解筛选后的不足，不保证全量成员和精确召回。项目要求完整浏览，因此主列表继续保留原精确排序与完整游标，只有原本就明确为样例的预览使用 ANN。这是按产品契约选择，不是声称 ANN 没有价值。

“每次必从磁盘读 280 MB”“改后必快一个数量级”“删除索引即可使发送百毫秒完成”均证据不足：1024 维的逻辑体积不等于物理 I/O，还受候选范围、TOAST、PG／系统缓存、磁盘及查询计划影响。已有 HNSW 仍有其他调用者，不能仅因主列表精确检索就直接删除。

官方依据：[pgvector 精确／近似、索引查询与迭代扫描](https://github.com/pgvector/pgvector)、[PostgreSQL trigram 的 LIKE／ILIKE 支持](https://www.postgresql.org/docs/16/pgtrgm.html)。短文本无足够 trigram 时仍可能扫描，不能将 SQL 可用索引说成每次必用索引。

## 已修订

1. 组合筛选留在数据库执行，不再 `findMany(select: {id:true})` 拉出整个符合条件的集合后塞回排名 SQL。已有规则引擎仍是唯一规则定义；适配器只接受白名单字段、关系和参数，不接受用户 SQL，不支持的结构拒绝执行。
2. 主搜索名称与人工标签改为 LIKE／ILIKE，普通搜索中的 `%`、`_`、反斜杠仍按字面匹配；结构化规则维持原 Prisma 行为。原字段索引、排序层级、离线降级与游标不变。
3. 样例预览内层只按原始余弦距离升序取样，外层做阈值过滤、确定性同分排序；事务局部启用 HNSW 迭代扫描。六万向量实际执行计划确认使用 `EagleAssetEmbedding_hnsw_idx`。预览仍无总数承诺，最终复核当前版本、私密及规则；保存后的文件夹完整成员仍由原独立 worker 精确构建。
4. 主列表没有全局 top-K 数量墙。超过 1000 个匹配结果的真实数据库回归逐页遍历完成，顺序一致、无重复、无截断。
5. NULL、缺失关联与否定条件分别处理，避免把 UNKNOWN 错变成命中。134 组规则／运算及否定对照原 Prisma；覆盖全部非语义字段，语义快照和嵌套关联另测。

尝试过将精确分数强制物化以减少重复计算，但隔离同 SQL A/B 的五次样本中位数约 586／260 ms（物化／不物化），结果完全相同。该写法已撤掉，不因局部表达式看似更省计算而保留更慢的查询。

发送关键事务的向量维护不在本次重复实现：分支基于上一轮发送候选，兼容向量先存 PENDING，由原独立媒体 worker 激活，不下载、不重复推理。总 HNSW 工作没有消失，也没有在 API 新建定时任务。参见 [发送候选](send-publication-2026-10-31.md)。

## 资源预算与用户表现

仅样例预览新增事务局部设置，不改变主搜索总量或数据库全局参数：

| 环境变量                                 | 默认  | 真实资源／范围                                     | 到顶时表现                                         |
| ---------------------------------------- | ----- | -------------------------------------------------- | -------------------------------------------------- |
| `EAGLE_IMAGE_SEARCH_PREVIEW_EF_SEARCH`   | 200   | ANN 候选搜索宽度及 CPU／内存，pgvector 接受 1–1000 | 样例召回可能减少，不声明完整数量；主列表不受影响   |
| `EAGLE_IMAGE_SEARCH_PREVIEW_SCAN_TUPLES` | 20000 | 迭代索引扫描工作量，接受正 int32                   | 样例可能不足，仍可保存后构建完整文件夹             |
| `EAGLE_IMAGE_SEARCH_PREVIEW_TIMEOUT_MS`  | 15000 | 单个预览事务占用连接的毫秒预算                     | 原预览错误流程显示失败，可重试；不回退全库 ID 搬运 |

非法配置在进入事务前明确报错。`SET LOCAL` 随事务结束恢复，回归验证连接后续查询没有设置泄漏。既有样例窗口及页面卡片数维持原值；它们不限制主搜索或保存文件夹的总匹配数。

## 端到端成本

- 客户端一次搜索仍为一个列表 HTTP 请求，缓存查询词的向量无需再推理；冷词按原流程多一次空间读取及一次本地文字嵌入 HTTP，没有原图 S3 读取。
- 相关度每轮一个排名 SQL，再对最多一个内部候选窗口批量读取资产与关联。去掉原来额外一次全量候选 ID 查询及其结果传输，不增加写事务或 S3。Prisma 的关联读取仍可能展开为多条 SQL，不能把整个列表说成只有一条 SQL；并发删除／权限变化导致候选失效时仍自动继续取下一窗口。
- 日期排序每窗口一条核验 SQL，继续走到填满一页或穷尽；不是最多只查 1000 个。照片组额外按当页组读取及复核；颜色覆盖度仅首屏两条聚合，均非本轮新增成本。
- 样例 ANN 段是一笔只读显式事务：BEGIN、一个设置 SQL、一个候选 SQL、COMMIT。普通条件样例、精确阈值复核和最终关联读取沿用原流程，无对象存储调用。没有对每个候选逐项事务。
- 前端只收到该次查询结果，不新增进度轮询、全列表失效或刷新；没有更改分页、滚动、选择或工作区恢复。

隔离素材列表实测：已准备文字向量、40 项首屏、无颜色／智能文件夹／照片组时，完整 `listAssets` 为 6 条 SQL、0 个显式事务、0 次 S3。包含一条排名、资产与关联批量读取；不是每张 6 条。认证、冷词空间查询与其他选项成本按上面条件另加，不能将这个夹具数字概括成所有请求。

## 验证与限制

只使用安全目标检查通过的 loopback `sekereagle_test` 临时数据库；保留固定图库、用户数据和其他任务工作区。对照使用合成 owner、照片与 1024 维向量，不包含真实照片或真实模型质量评估。

两模式 owner／私密／回收／媒体版本隔离、文字字面值、规则等价、完整分页与预览设置恢复均有真实 PostgreSQL 回归。新谓词及预览模块行覆盖率 98.67%、分支 87.72%、函数 100%。

最终源码的规模对照：loopback PostgreSQL 16／pgvector 0.8.6，六万条密集 1024 维归一化合成向量，其中三万符合相机条件；交替运行旧版和候选各六次，同一查询、相同首屏 ID。包含旧版全量 ID 读取，不包含模型推理、HTTP／客户端、资产详情序列化。六次样本中最后一对受到其他回归负载影响；报告中位数，不当作生产 p95 或稳定冷缓存结果。

| 项目                    | 旧版           | 最终候选   |
| ----------------------- | -------------- | ---------- |
| 六次查询中位耗时        | 407.50 ms      | 263.16 ms  |
| 排名 SQL 参数序列化体积 | 1,354,414 字节 | 4,600 字节 |
| 首屏匹配及顺序          | 对照           | 完全相同   |

此样本约减少 35% 查询耗时、99.66% 排名参数体积。旧版另有 ID 查询结果传输，上表没有将该额外流量计入体积收益。样例预览同库真实 HNSW 执行计划暖缓存 2.607 ms；它只测候选 SQL，不能冒充预览 HTTP 全链路或 NAS 冷读时间。中途曾测得含物化方案约 400→309 ms／2.5 KB，最终已撤掉物化，上表覆盖那个中间结果。

主搜索仍需要对符合条件的向量计算精确相似度，未将该 O(N) 成本消除。NAS 上的真实冷／热延迟、搜索质量、模型首词推理和未来更大库仍需实际测量；当前不能承诺“搜索和发送都快十倍”。若后续需要增加“最相似的少量结果”独立入口，可为该明确契约用 ANN，不静默替换完整搜索。

最终验证通过：根目录 lint、typecheck、unit test、build、format；共用架构门禁与客户端／控制器契约、OpenAPI 契约检查；完整图库集成、历史升级及全表摘要一致的备份恢复；最终独立 API 镜像的迁移、就绪、未认证拒绝和无 API secrets 的 operations 启停验收。新数据库夹具串行复用规范向量空间，避免与原隔离测试竞争唯一 current 空间；覆盖率门禁已加入默认集成入口。运行期间曾因并行构建清空 dist 导致集成导入失败，已在稳定成品上完整重跑通过，没有将该失败当作业务通过。

本轮没有新 migration，没有改生产缓存／内存配置，没有删除生产索引、重算真实图库、切换后台开关或更改部署。代码保存在 `codex/search-query-efficiency`，基于上一轮发送候选；另一个工作区尚未提交的人物功能修改没有合并、覆盖或代替验收。用户要求暂不发布，故未 push、未部署，也未触发仅 push 时启动的 DeepSeek 后台审核。
