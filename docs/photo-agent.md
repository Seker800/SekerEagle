# 照片智能整理本机使用与验证

照片模式左侧新增“智能整理”。可以按日期创建最多 200 张照片的任务，让支持 MCP 和图片输入的 Agent 读取任务、查看缩略图和提交建议，再在网页中逐项或批量审核。当前交付的是本机代码及隔离验证，尚未部署，也未连接真实个人图库做模型质量评估。

## 本轮提供的能力

- 城市补充：保存独立的城市级位置与来源，已接受推断和人工纠正均可查询、展示及撤销；原始 GPS、原片和时间线不改。共用筛选器中的“城市（已确认补充）”查询已接受的补充城市，不表示已经对所有原始 GPS 完成城市反查。
- 保守候选：有时区的拍摄时间被前后两个 GPS 锚点夹住、两端各在 20 分钟内、锚点相距不超过 5 公里，且对应唯一的候选城市代表点 30 公里内时，才给出时间匹配候选。这些是待校准工程规则，不是位置准确率承诺。非零时钟偏移必须指定相机型号，且仅作用于本次调用；同型号多台设备仍可能混淆，应分开建立任务。
- 城市由用户或 Agent 提供明确的城市身份、行政区和代表坐标，供 GPS 邻近核验。当前不接入外部地理编码，不用最近城市中心证明行政归属；跨城、边界和稀疏证据由 Agent 复核或保留未知。
- 非照片候选：查询返回截图命名线索；按任务范围调用既有 2B 文本／图片向量进行排序。Agent 应比较多个候选类别和真实照片描述，并查看当前缩略图，再提交画面复核声明与理由。2B embedding 不是对话分类模型，相似度不是分类概率。服务不自动打开 8B、补跑全库向量或将未命中视为真实照片。
- 审核：接受城市、人工改城市、接受回收、拒绝、批量处理、取消任务和逐项撤销；批量部分失败显示错误，成功项刷新，重试不重复应用。修改城市后只能单项接受，避免批量忽略修改。任务 24 小时后拒绝新应用，已经应用的项目仍可安全撤销。
- 保护：冻结资源版本、业务版本和摄影元数据提取时间。素材、其他账号、无权访问的私密照片不能进入任务；证据重提取、照片替换和后续编辑会阻止旧建议或不安全撤销。替换原片会清除旧补充位置。人工拒绝或撤销后，相同媒体版本不重复提议。

首轮不通过 MCP 暴露“发送到素材”、永久删除或清空回收站；需要保留到素材时，使用图库已有的显式“发送到”入口。RAW、视频和实况组件不进入非照片剔除建议。MCP PAT 不能读取私密照片，也不能接受、拒绝、取消或撤销；浏览器保持原有私密授权机制。

## 接入 MCP

在本机独立测试服务中打开设置的连接管理，选择“照片整理 Agent”用途创建可撤销 PAT，权限仅为 `photo:read` 和 `photo:suggest`。真实 PAT 只放入本机 Agent 的受保护配置，不提交仓库或写入聊天。

在支持 stdio 的 Agent 客户端中配置：

```json
{
  "mcpServers": {
    "sekereagle-photo-agent": {
      "command": "node",
      "args": ["/absolute/path/to/SekerEagle/apps/photo-agent-mcp/main.mjs"],
      "env": {
        "SEKEREAGLE_AGENT_URL": "http://127.0.0.1:YOUR_TEST_PORT",
        "SEKEREAGLE_AGENT_PAT": "YOUR_TEST_PHOTO_SCOPED_PAT"
      }
    }
  }
}
```

替换为当前机器的 Node 22、仓库路径和独立测试站点端口。入口直接运行 Node，避免 npm 启动信息混入 stdio 协议。MCP 只接受无凭据、无路径的 loopback origin，禁止重定向；图片限制为当前派生缩略图及 1 MiB，JSON 返回限制为 4 MiB。它不自行读取 `.env`，不直接连接数据库、MinIO 或模型服务。

可用工具：`photo_list`、`photo_preview`、`photo_task_create`、`photo_task`、`photo_city_candidates`、`photo_visual_scores`、`photo_propose`。没有修改照片的 MCP 工具。连接外部 Agent 意味着它的模型可能读取返回的元数据和预览；实际本地或云端推理由该客户端配置决定，本地 2B 检索不保证 Agent 也在本地运行。

在网页创建任务后，将任务编号交给 Agent，例如：

> 只分析这个任务。参考原始 GPS 和拍摄时间，提出缺少位置照片的城市建议；先查看画面并列出依据。无法确定就保留未知，最后提交建议供我审核。

或：

> 只检查这个任务中的明显截图和设计素材。结合文件名、多个类别的向量排序与真实照片对照，查看缩略图后再提交建议。模糊、翻拍和摄影成片保留给我判断。

## 本机隔离验证

读取 [环境边界](environment-model.md) 和 [测试指南](testing.md)。不要在生产实例运行迁移或测试命令，也不要把本机正在运行的正式库当作测试库。

```sh
npm run db:generate
npm run test:library-integration
```

隔离测试入口自行新建带随机名称、仅回环端口的临时 PostgreSQL，显式覆盖为 `sekereagle_test` 并先执行安全检查，迁移、回归及数据库备份恢复完成后清理。不会使用当前 `.env` 的数据库作为目标。

纯单元测试前也须通过 `npm run db:guard`；为其显式设置允许的隔离测试数据库与对象存储目标，不直接加载生产配置。工程检查包括 `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`、`npm run architecture:check`、`npm run test:architecture` 和 `npm run contracts:generate`。

需要浏览器临时站点时，先构建相应 workspace，再使用已有测试入口：

```sh
PHOTO_WORKBENCH_BASIC=1 node scripts/testing/photo-workbench.mjs --serve
```

它创建独立 PostgreSQL、MinIO 与合成图片，输出本次端口，不切换现用服务。测试站点只用于验收，结束后通过原进程的 SIGINT／SIGTERM 清理本次实例；不要操作其他容器。合成照片和人工构造建议证明审核链路，不代表模型识别准确。

## 验证结果与剩余工作

2026-10-20：lint、typecheck、全仓 unit test、build、架构门禁、契约生成和全仓格式检查通过；63 项本机真实数据库及 HTTP 回归通过，并覆盖任务范围、城市接受／撤销、共用筛选、回收恢复、重试幂等、版本冲突、元数据证据失效、过期取消、跨主体与模式、私密访问、PAT 禁止审核及数据库约束；历史升级和完整数据库恢复通过。MCP 使用官方 SDK 完成真实内存传输及 stdio 握手测试，覆盖预算、类型、错误返回、严格输入和能力范围。审核界面测试覆盖逐项、批量、冲突刷新、手工城市更正、过期撤销与取消；另用一次性本机站点验证合成建议的回收和撤销。

待进行：用户选定 Agent 客户端与模型后的实际接入；授权真实出游和非照片正反例的准确率／误报评估、阈值校准；权威城市反查与同型号多设备识别；真实图库规模性能。当前未启动生产服务、未做生产迁移或发布、未对真实个人照片自动整理。

本轮覆盖率：整理应用服务行 99.80%、分支 86.08%、函数 98.04%；审核界面行 95.98%、分支 82.82%、函数 86.36%；MCP 服务行 100%，并通过分支与函数至少 80% 的门槛。覆盖率证明测试执行范围，不代替真实模型质量评估。
