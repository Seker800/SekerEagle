# 批量发送、删除与浏览连续性

2026-10-31，本地候选，未部署。本记录按单owner、6万项、最高6100万像素、API单实例＋NAS＋Mac worker评估；不按多租户SaaS假设增加配额。保留认证、主体owner、跨owner 404、隐私、不可逆保护与备份。

## 已确认与修复

- 1000项选择和20个活动操作确为代码限制，已移除。相同ID自动归一化，不能用“请选择不重复的资源”误导用户。
- 新旧发送HTTP入口均入原持久操作表；旧入口改为202操作回执，不再等同步复制完成。当前网页／安卓主路径原已使用操作回执。旧接口的外部调用者须按回执查询状态，不能再假定响应包含新目标ID。
- 原HTTP服务生命周期内执行操作，现独立operations进程复用相同领域服务；不新增业务队列。媒体业务worker保持原独立角色。
- SEND原每次只领取一项，现默认四项并发；每个回执仍独立重试和取消，不把一个坏项变成全批失败。
- 新HANDOFF计划不做S3 COPY／HEAD／GET：在同一发布事务内交接不可变原件、当前READY预览和切片所有权，创建独立目标记录并退役源。源历史保留键作审计、但不拥有文件；部分唯一索引和退役约束保证同一键只有一个存储owner。源READY派生行在原事务内移交为独立目标行，历史计划记录来源。其他旧派生进入既有删除outbox。
- 旧COPY计划仍按持久计划续传和校验，不能用新策略改变历史幂等；旧计划过期只删独立复制目标，HANDOFF过期只废弃日志、不登记源文件删除。
- 删除时已失效的项单独跳过或报告不可访问；入队后消失也可幂等跳过。当前仍存在但被修改／隐私变化的项继续严格校验。跨owner不进行无作用域补查，纯不可访问选择保持404。
- 发布进度不重拉图库、不截断已加载页、不移动滚动位置。原工作区提示“后台内容已更新”，用户按“加载更新”主动刷新；过期标记覆盖同主体／模式的相关读取，后续导航可正常读取新内容。
- 智能规则31组／每组30条的静默限制已移除；相机／镜头500项截断已移除；审批前端每五条拆请求已移除。

派生输出另外完成不可变约束：图片、视频、切片和缓存预览导入均使用执行独立目录。PUT前由既有删除outbox登记未发布目录，发布事务同时核验当前源与租约并消费清理意图；失败只提前原意图，不在不确定提交后重建可能已发布对象的删除意图。旧执行者晚到写入自己的目录，不能覆盖接管目标。后台派生完成只更新HANDOFF实际采用的READY结果，不放宽原件／rowVersion快照；COPY历史计划不改变。

发送到照片时，只要现有浏览预览可用就直接READY，缺失EXIF／分析按原详情阶段补齐；不为缺失EXIF重做浏览图。原件哈希未知时详情任务读取原件完成真实校验，不冒用预览哈希。大选择的成员集合、派生选择数据和菜单键作工作区内记忆，进度重渲染不再反复排序整份选择或逐卡扫描选择数组。

## 资源预算与到顶行为

| 配置                                   | 默认       | 保护对象与用户表现                                                                                                                              |
| -------------------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `EAGLE_OPERATION_BODY_LIMIT`           | `32mb`     | HTTP解析内存和请求体；超过返回413。包含两个模式的新旧发送入口，其他接口保留自身字节预算；增加时也须同步上游代理请求体预算                       |
| `EAGLE_OPERATION_DB_BATCH_SIZE`        | `512`      | SQL协议参数及单次落库内存；自动继续下一批，用户不拆选择；启动时拒绝超过32767参数的保守换算预算                                                  |
| `EAGLE_OPERATION_ADMISSION_TIMEOUT_MS` | `120000`   | 冻结选择的事务与锁时间；超时回滚并提示重试，相同操作ID不会重复入队                                                                              |
| `EAGLE_OPERATION_SEND_CONCURRENCY`     | 每模式`4`  | 独立执行器数据库／旧COPY连接压力；多余项可见地排队，不拒绝选择                                                                                  |
| `EAGLE_OPERATION_METADATA_BATCH_SIZE`  | `32`       | 单次删除／恢复锁占用；自动领取后续批次                                                                                                          |
| `EAGLE_OPERATION_DB_CONNECTIONS`       | `6`        | Compose中独立进程数据库连接池；工作等待空闲连接，不扩大API池                                                                                    |
| `EAGLE_OPERATION_S3_MAX_SOCKETS`       | `8`        | Compose中独立进程旧COPY存储连接池；请求自动等待，新HANDOFF不使用存储连接                                                                        |
| `EAGLE_OPERATION_MEMORY_LIMIT`         | `512m`     | Compose中独立进程内存；异常退出后按原租约恢复，API进程独立；须按实机观察调整                                                                    |
| `EAGLE_MEDIA_OUTPUT_RETENTION_MS`      | `86400000` | 未发布输出的崩溃清理保留期；正常失败立即提前回收，已发布意图在同一事务消费；过期产物不能再发布，源原件保留，可调同名Mac worker环境或Compose参数 |
| `EAGLE_OPERATION_POLL_MS`              | `1000`     | 跨进程队列发现的数据库读频率；仅影响开始等待时间，不改变操作选择                                                                                |

这些是处理资源预算，不是产品级数量配额。协议规定的对象存储删除每请求至多1000键继续由系统自动分批；不能把上游协议批次等同于用户最多删除1000项。

删除outbox的到期插入／提前可用时间使用独立固定通知，同事务多项会合并；未来意图、领取与心跳不唤醒媒体候选扫描。复用原PG连接及原30秒断线兜底，没有新增后台队列或API定时器。该通知不改变用户列表状态。

## 审查范围与剩余成本

本轮修复常用发送／删除路径、规则静默截断、面板选项和审批前端拆批。其他DTO中的100／200／1000不能仅凭数字判断：部分是前端自动分块协议，部分仍是可见产品限制，必须分别追踪调用链后处理，不声称全仓已经没有数量限制。确认仍需进一步处理的有旧摄影Agent创建任务的200张范围墙、人物手工分配500项、统计设备筛选50项、通用与媒体请求频率配额。它们不在本记录冒充已修复。上传分片、编解码内存与SQL协议预算属于真实资源边界，不能整体删除。

执行阶段仍逐项复制标签和事实并在发布事务内校验授权／版本／租约，100项仍有3725条SQL，表明事实复制还存在摊销空间。正常完成回执已与资源发布合并为同一事务，只有历史已完成结果的回执补写需要独立事务；旧COPY在复制前保留授权检查。除去零复制路径的重复预校验和幂等日志重复读取，100项少1700条SQL、400个事务。实质收益是移除存储复制、复用已计算结果、分离HTTP执行与保持浏览连续性；不把并发四路或消除S3复制宣称为已完成全部数据库批量化。
