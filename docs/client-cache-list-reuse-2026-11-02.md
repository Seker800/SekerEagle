# 列表驱动的桌面磁盘图片复用

> 后续发布状态：本页候选已于2026-11-02晚整合到main并配套上线；实际版本、双端验收、备份及限制以[本轮生产发布](main-production-release-2026-11-02-evening.md)和[现用运行状态](current-runtime.md)为准。下文保留原本地测量及其当时限制，不把本机数字改称生产性能。桌面能力需手动更新0.1.9客户端。

状态：2026-11-02，本地候选，桌面 0.1.9，分支 `codex/client-cache-experience`。延续[首轮缓存修复](client-cache-experience-2026-11-02.md)，没有替换安装客户端、发布网页、修改 NAS 或删除用户缓存。

## 结果与边界

正常素材／照片列表与资源详情经桌面主进程向原服务器读取一次。主进程从真实认证响应提取非私密、未删除、当前媒体修订的派生图片信息，再把原 JSON 交给页面。已有匹配磁盘文件直接返回 `LOCAL`，不再每张图片请求一次 304；第一次下载、私密图片、没有列表依据及不匹配的文件保持原媒体路径。普通浏览器与旧客户端保持原请求方式。没有新增服务端接口、数据库迁移或磁盘授权租约。

这覆盖普通图库、照片时间线、搜索、文件夹等共用 `/assets` 列表及详情中的缩略图／预览图。金字塔 tile、独立地图／查重接口等没有经该列表建立依据的路径继续在线校验，不把不完整覆盖说成所有图片都免联网。原图不进入本功能。

## 授权来源与失效

- 主进程只接受明确白名单中的相对 GET：两模式 `/assets`、资源 UUID 详情、`/trash` 和原 `/api/library/changes`。preload 与主进程复用同一白名单，拒绝原图、任意网址和路径穿越；不接受页面传来的 owner、列表 DTO 或“允许访问”标志。服务器仍执行原认证、主体、模式和私密过滤。
- 暂存依据按 deployment、认证 owner、模式、asset ID 隔离；派生文件 ID、种类、当前修订、内容类型及字节长度匹配。数据库的派生文件 ID／storageKey 对应独立产物；原素材缓存键和照片隔离键保持，旧文件无需重新下载或迁移。
- 同一资源后来的私密／空派生列表替换旧依据。在途列表按开始顺序保护，早发晚到不能覆盖后来的资源投影。
- 页面写请求先撤回依据，再发送原写操作；登出／登录立即推进页面会话世代。cookie 变化、唤醒、联网恢复、换服务器和整页导航／关闭也撤回。会话主体读取新增在途世代隔离，旧 `/auth/me` 回应不能覆盖新主体。
- 原共享变化检查中的 epoch、ASSETS、LABELS、PEOPLE 修订发生变化时，先清除依据，再把变化响应交给页面执行原刷新。失败、超时或取消检查也撤回；不把“没收到变化”当成新的授权。资源主动失效同时撤回对应依据，并保留原磁盘失效流程。
- 失效会挡住已经发出但尚未结束的旧列表，它们不能重新登记依据。读失败不偷偷再发一份页面列表；保留原查询重试。用户取消通过 IPC 传到主进程请求。

新鲜度与**服务器列表快照和原页面刷新周期**一致，不承诺其他窗口的删除／私密变更瞬间撤回已经显示的图片。现有变化检查在可见页面通常每 60 秒执行，focus／online 会唤醒；没有把它升级成实时推送或强一致撤权。若要求改变提交时立即让其他窗口撤权，需要另一个明确的同步契约，本轮不以逐图确认掩盖该问题。

## 端到端成本

| 场景               | HTTP／本机 IPC                                                          | SQL、S3、事务及页面刷新                                               |
| ------------------ | ----------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 一页列表           | 原列表 HTTP 1 次；桌面增加 1 次列表 IPC、主进程 JSON 解析及元信息登记   | 服务端原列表 SQL／事务不变，零新增 S3；不重复拉同一页，不改分页或滚动 |
| N 张已有对应磁盘图 | 原 N 次媒体条件请求变成 0；本机原 utility acquire／文件流／release 保留 | 每张媒体 SQL 0、S3 0、业务写事务 0；既有会话及变化检查另计            |
| 首次下载或无依据   | 每张仍走原认证媒体请求                                                  | 原权限读取及对象 GET 不变，不声称能加速新图片下载                     |
| 写操作             | 新增 1 次失效 IPC，原业务 HTTP 次数不变                                 | 业务 SQL、事务不变；继续原查询失效与刷新，不新增全列表重放            |
| 会话／变化检查     | 保留原短期 `/auth/me` 合并和共享变化检查                                | 不给每张图新增认证接口；owner 的独立检查不能宣称为永久零联网          |

暂存依据最多保留 12,000 个资源投影，保护主进程内存；LRU 淘汰只使相应文件退回原在线校验，不限制图库、操作数量或列表分页。启动环境变量 `SEKEREAGLE_DESKTOP_SNAPSHOT_ENTRIES` 可调整为正整数。只保留 ID 与派生文件元信息，不保存名称、标签或原图。列表 IPC 沿用网页默认 30 秒读请求期限，防止已关闭页面的挂起 HTTP 长期占用资源；用户取消可更早终止。

## 实测：真实 Electron 的受控对照

运行 `npm run test:desktop-cache:list`：独立临时 profile／缓存、loopback HTTP、真实 preload／受信 IPC、真实 utility process／SQLite／文件流，WebP 实际解码并等待两帧。两模式使用相同 ID、不同内容；每页 200 条含标签／摄影元数据的合成资源，只展示其中 24 张，磁盘预热后每种网络延迟各 5 组交替先后对照。

旧流程由页面直接请求列表并逐张重验；新流程才经过主进程列表 IPC。每组断言列表恰好 1 次、图片正文下载 0 次，旧流程 24 次重验，新流程 0 次且全为 `LOCAL`。不会用服务器延迟虚构生产 p95。

| 单次请求人为延迟 | 模式       | 旧流程整屏中位数 | 新流程整屏中位数 |   节省 |
| ---------------- | ---------- | ---------------: | ---------------: | -----: |
| 0 ms             | 素材／照片 |            30 ms |            30 ms |   0 ms |
| 30 ms            | 素材       |           190 ms |            60 ms | 130 ms |
| 30 ms            | 照片       |           180 ms |            60 ms | 120 ms |
| 80 ms            | 素材／照片 |           440 ms |           120 ms | 320 ms |

列表自身的两模式合并中位耗时：0 ms 网络时约 3.1→4.6 ms；30 ms 时 33.7→35.9 ms；80 ms 时 84.7→87.7 ms。额外解析／IPC 确有约 1–3 ms 成本，收益来自省掉排队的媒体往返，并非凭流程图推断。纯本机几乎没有可见收益。

这些是**合成 64×64 WebP 的隔离对照**，不是用户图库、NAS 压力、完整 React 页面、进程冷启动或公网实测。真实安装客户端尚未更新，所以不能声称用户现用端已经节省这些时间。原轮现场样本只说明优化对象存在；最终实际收益需配套发布后的同场景测量。
