# 照片模式代码验收记录

本文保留各阶段的历史验收记录，测试数量不是当前总数。当前测试入口、CI 范围与未覆盖边界见 [测试覆盖与执行](testing.md)。

本轮交付范围是代码、测试和独立测试页面。没有连接群晖，没有向现用数据库或对象存储迁移、导入或部署。

## 可验收功能

- 左侧栏顶部切换素材／照片，进入独立工作区。资源、标签、智能分类、去重、上传会话、处理设置、回收站、私密显示授权和缓存分别隔离；同一文件导入两边形成独立资源。
- 照片时间线通过共享布局 hook 的 justified 策略按原图比例等高横排，素材沿用竖向策略；缩略图卡片、缩放、虚拟化与操作继续共用，不在照片卡片覆盖日期。最右侧固定高度尺规按全库最早／最晚照片月份定界，分年月大小刻度；空月份留白，不绘制刻度；悬停放大邻近刻度并显示具体年月，不弹出月份选择窗口，点击 scoped cursor 跳至目标月，顶部箭头回到最新；日期缺失回退导入时间。拍摄日期在详情中查看。照片默认按拍摄日期倒序显示，缺失时使用导入日期。EXIF 保留相机、镜头、焦距、光圈、曝光、ISO、GPS 与时区是否已知。相机／镜头可从已提取型号中选择筛选，也可通过统一筛选器输入型号关键词。
- 地图展示当前已载入且含 GPS 的照片，可继续载入；标记可打开照片。底图改为随应用打包的 Natural Earth 陆地／城市概览，使用黑黄夜间配色；无外部瓦片或 CDN 请求，地图浏览无需翻墙。不含街道级道路细节，详见 [照片夜间地图](photo-map.md)。
- 本地 YuNet／SFace 检测人脸并建议人物分组，可命名、合并人物，以及分离误认面孔。模型有固定版本、校验和、进程超时与输入输出大小限制；浏览器不获得人脸特征向量。模型安装见 [本地人物运行环境](../services/photo-face/README.md)。
- 照片组保留每张原片。worker 在导入摄影分析后自动查找相似照片，时间线折叠为一张主图并标注张数；打开后可左右按钮、方向键或触屏滑动浏览组内照片，设置主图或取消分组。人工主图与取消决定会保留。保守条件仍是同相机、十分钟内、感知哈希距离不超过 8；缺少拍摄时间时不自动推断。手动建组、合并和成员调整 API 保留，当前界面不提供独立组管理页。
- 替换原图通过窄的版本事件通知摄影模块，失效旧摄影元数据、人脸当前标记与自动组，保留人工人物记录。共享上传实现不依赖人物识别算法。

## 当前默认值与边界

- 没有 EXIF 时区时，拍摄钟面时间用于排序并明确标为时区未知，不声称已经推算出准确时区。
- 相似组使用相同相机型号、十分钟内、64 位感知哈希汉明距离不超过 8 的保守候选；三秒内标记为连拍。缺少拍摄时间不强行按导入时间认定连拍。
- 清晰度参考分来自固定尺寸灰度图的 Laplacian 方差，只作同组比较参考，不是美学评分；不分析闭眼、表情，不自动删除或覆盖原片。
- 人物自动合并阈值为余弦相似度 0.45，同图中的不同面孔不会自动归为同一人物。公开小样本仅证明链路，不代表识别准确率基准。
- 人物目录按创建时间＋ID 游标分页，每页 200 人，可继续加载；私密人物设置沿用相同分页。每人提供 20 张面孔用于快速纠错；“查看此人物的照片”使用正常分页图库。人物页和任务中心可幂等补排全库当前可见、具备 READY 默认浏览预览且尚未处理的当前版本照片，进入持久后台队列；只有获准显示私密照片时才包含私密范围，不再有每次 500 张上限；关闭页面后继续，暂停／时段仍生效，失败任务通过任务中心重试。任务中心固定显示未扫描数量，不能把没有任务当作完成。
- 初版自动照片分组每次分析最近 2000 条摄影记录，组页面最多显示 200 组。更大图库的全量分组调度仍需后续扩展；不能将本轮小样本验收当成真实全图库验收。
- 桌面照片预览和下载使用经过授权的同源 HTTP。旧素材专用的原文件原生拖出协议暂不用于照片；浏览器基础管理能力可用。
- 本地人物模型是可选运行环境，正式实例默认不会静默下载或启用。独立测试环境已经安装并验证；生产启用仍须按文档配置和部署。

## 重现独立测试页面

在本开发 worktree 内执行，要求 Docker、Node.js 22 和 Python 3.11。以下命令只安装测试运行环境并创建新的临时数据库／对象存储，不复用现用实例。

```bash
python3 -m venv .omx/photo-face/venv
.omx/photo-face/venv/bin/python -m pip install -r services/photo-face/requirements.txt
node scripts/download-photo-face-models.mjs .omx/photo-face/models
npm run test:photo-workbench
```

成功后终端显示独立 loopback 测试地址，测试入口登录的是一次性合成测试账号。停止测试进程会清理其临时容器，数据不持久保存。只运行并自动清理则使用 `npm run test:photo-smoke`。数据库矩阵、完整恢复与双 100k 测试使用 `npm run test:library-integration -- --scale`。

## 验收修正：导航、筛选与折叠照片组

- 摄影筛选统一使用共享规则引擎与快捷筛选的清除／固定机制，智能分类同样支持摄影字段；素材模式不提供或接受摄影规则。旧命名查询参数仅作兼容转换。
- 主导航只有左侧照片时间线、地图、人物；中间不再显示重复的导航和摄影筛选栏。
- 组封面仅从当前筛选命中且可见的成员中选取。私密、回收或不匹配的成员不进入封面、数量或组内导航；过滤后只剩一张时作为普通照片显示。
- 分页继续遍历原片，以服务端按当前查询返回的组投影跨页折叠。每页不拉取整个图库或所有组；封面批量获取，组内大图按需读取。
- 增量分组每次查询同相机前后十分钟内最多 500 个候选；人工组、已取消的组与人工主图不会被覆盖。不会把两个既有自动组擅自合并，避免连续相似照片链式扩张。

本轮修正验证：根目录 lint、typecheck、unit test、build 通过；最终 Web 回归 47 个文件、266 项测试通过；23 项真实数据库测试及完整恢复通过，其中新增统一摄影规则／智能分类、跨页照片组投影和增量自动分组人工主图保护检查。公开照片实际上传、自动分组与本地人脸链路仍通过。浏览器验证左侧导航、统一添加与清除筛选、组内切换和修改主图后封面更新，截图位于 `.omx/artifacts/corrected-photo-workspace.png` 和 `.omx/artifacts/corrected-stack-preview.png`。独立验收地址继续为 `http://localhost:57894/`；未部署现用实例或导入群晖真实照片。本轮未重新测量十万照片基准，前述性能数值为上轮结果。

## 拖入归属与跨模式发送（2026-10-19）

- 外部文件拖入素材默认进入素材，拖入照片默认进入照片。导入队列固定使用拖入时的 API 实例，三文件队列处理中切换模式的测试验证剩余文件不串库，下一次拖入使用新模式。
- 单选与多选图片右键提供「发送到照片」或「发送到素材」。按用户选择执行移动：目标生成新 ID、独立原件和目标模式处理任务；全部复制完成后，在一个事务中发布目标并将源项放入原模式回收站。原资源的模式不修改，原标签／分组／人物关系不拷入目标；名称、说明、来源、评分和私密标记保留。实况的唯一可访问配对视频随同发送。
- 共享服务使用持久化发送计划与操作幂等键；临时复制失败不移动任何源项，同一操作重试不新增目标。未提交的文件复制由 PENDING 计划跟踪，可重试原操作；不冒充跨数据库与存储的原子事务。源版本或权限变化时拒绝提交，需要刷新并重新发送。

## 2026-10-20 照片隐私与私密人物（仅本机）

照片沿用同模式的人工私密标签：设置 → 账号 → 隐私 → 管理私密标签。人物页选择人物，勾选「包含此人的照片设为私密」，该人物当前有效识别所在的整张照片隐藏，合照也一样；不是只模糊脸部。标签与人物任一规则命中即私密，取消一项不能越过其他规则。开启同一照片模式的「显示隐私内容」后，可在人物页或设置内解除人物规则；沿用现有自动关闭时长。

私密结果写入同一个 isPrivate 投影，图库、搜索、时间索引、地图、照片组封面、媒体与 Agent 继续使用既有权限过滤。详情显示私密标签／人物原因；实况配对组件共享保护。编辑副本与替换原件在没有人工私密标签可继承时添加独立「继承私密」标签，避免缺少人脸结果时意外公开；用户可在人工标签规则中管理它。不会复制人脸向量或改原文件。

人物合并保留任一方的私密规则；人脸纠错、后台识别与投影写入同一事务，隐私锁先于人物／分组锁。人工修正保持到当前媒体版本的模型重跑；过期任务／媒体版本不发布结果。私密人物规则只接受浏览器主体和同源写入，主体推导 owner，越权／隐藏人物返回 404，过期人物版本返回 409，PAT 无权修改或查看私密照片。
