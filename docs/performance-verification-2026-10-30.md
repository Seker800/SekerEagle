标签 ALL 的多个索引 EXISTS、相机／镜头 trigram、颜色总数与 ANN 的建议仍需各自 EXPLAIN 和结果完整性对照。不能根据“子查询数量多”推定 GROUP BY 必然更快，或以改成近似检索丢掉精确筛选。日预聚合表、全库筛选计数缓存和审批后台任务未在这轮实现。

## 十、安卓上传、备份与暂停审查（2026-10-30，本地候选）

| 审查结论                  | 核验与处置                                                                                                                                                                                                                                                                                                           |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 分片与文件串行            | 原分片循环确实串行。保留一份文件队列，分片共享最多 3 个在途槽；不同时乘上文件并发。每个缓冲最多 8 MiB，全局至多 24 MiB 分片缓冲；历史较大分片走流式单片，不一次分配 64 MiB                                                                                                                                           |
| 每片必定两次 TCP/TLS 握手 | **不能由 disconnect() 推出，实机对照不支持此结论。** Android 16 模拟器对两个顺序 PUT，旧逻辑和当前路径均复用一条 TCP 连接。沿用平台池，不引入 OkHttp，不将 30–50 秒握手或吞吐减半的推算当实测收益                                                                                                                    |
| 非 seekable 源重复跳过    | 原每片重开并跳过前缀属实；管道 FileInputStream 的 position 也可能不可用。传输现在只打开一次顺序源，已提交分片向前跳过，缺失分片在预算内缓冲并并行上传；seekable 源可快速 skip，不能 seek 时单次向前读，不会按每片重新读前缀                                                                                          |
| 全局 JSON 锁              | json、array、jsonAtEpoch 原来确实把整个网络请求锁住                                                                                                                                                                                                                                                                  |
| 凭据锁收窄                | 移除普通 JSON 请求的整段同步锁；保留凭据、刷新和登录／退出协调，epoch 在发请求及刷新重试时验证。慢 JSON 不阻塞另一个请求、退出后旧响应及旧 epoch 拒绝、私密／原件取消回归通过                                                                                                                                        |
| 手动备份充电条件误用      | 所有手动入口显式带 manual；只绕过充电／低电量空闲条件，Wi-Fi 成本策略继续检查。两个自动入口都不能借手动标志清除用户暂停                                                                                                                                                                                              |
| 暂停销毁与状态丢失        | 暂停先持久化用户意图，立即断开在途连接，保留计数和“已暂停／继续”通知。原 SQLite 检查点 v1/v2 无损升级，按作用域／文件版本保留本轮结果及常数时间计数；恢复不重复累计。未知修改时间的 provider 仍重新哈希，不能把时间未知当内容未变                                                                                    |
| 服务实例竞争              | 原备份执行器改为进程内唯一串行执行器，旧实例不能发布当前实例状态；同实例暂停后立即继续等待旧任务排空。也处理了拒绝迟到自动启动时 Android 的前台服务握手要求，避免 5 秒崩溃                                                                                                                                           |
| guard／写偏好开销         | 账号、暂停、权限和中断守卫持续检查，网络／电池 Binder 查询每秒至多一次；状态、计数、错误、最近 100 条结果合并写入并节流通知，终态强制刷新。没有宣称节省“十几秒”，未做该吞吐测量                                                                                                                                      |
| MediaStore 游标跨上传持有 | 元数据改为 `_id` keyset 每批至多 256 行，先关闭游标再哈希／上传；260 项跨页设备验收通过。SAF 树目录 provider 的遍历仍沿用原实现，不能声称所有 provider 都已经分页                                                                                                                                                    |
| 哈希阶段无字节反馈        | 手动上传的哈希阶段加入节流字节进度；确认入库继续显示独立阶段，不将 100% 上传当作已入库                                                                                                                                                                                                                               |
| complete 超时与重复检查   | 原同步全对象检查及全进程单并发属实，原 complete 路由只给 15 s。保持哈希／媒体校验和检查预算，为两个模式的合法 complete 路由及客户端单独给 660 s；其他 API 仍 15 s。合并本进程同 owner／模式／会话的最终确认，复现的三次并发失败由三次检查／尝试降为一次。不是新的持久异步协议，多 API 副本之间也不宣称共享该内存合并 |
| 下载切后台取消            | 已改为原 NativeTransferManager 应用生命周期持有下载，复用原 NativeUploadService 前台传输服务。后台、页面重建后完成，原件版本、注销、取消及未完成文件清理仍检查。没有新增第二个后台服务；进程被系统终止后仍需重选未完成下载，界面如实说明                                                                             |

本轮没有取消客户端去重 SHA-256 或服务端原文件校验，没有调大检查进程并发，也没有仅延长整个 `/api/` 的超时。普通文件队列仍顺序调度；主要并发在共用分片层。对弱网吞吐提升不报未经控制实验验证的倍数。
