## 实际观察与测量边界

在用户正在使用的 macOS 0.1.7 客户端、公网连接中，只读采集 Performance Resource Timing、fetch 响应头时间及图片 load 后两帧。连接探测约 30.9ms。混合交互样本如下，不能当成标准冷启动或稳定 p95：

| 路径         | 样本数 | 最小／中位／最大，ms |
| ------------ | -----: | -------------------- |
| 照片列表     |      9 | 61／119／1542        |
| 照片派生图片 |    212 | 13／77／251          |
| 素材列表     |      3 | 322／862／1791       |

一次素材文件夹切换的列表响应头为 1232ms。同期 60ms 已有可见图片 load；这是旧内容／已有内容可能仍在展示的证据，**不能作为目标文件夹已完成首屏的时间**。返回列表样本出现四次 58–138ms 列表读取，不能仅凭接口耗时宣称返回已经瞬时完成。

随后显式刷新页面，清空该页面的 JS 内存，保留正常浏览器和磁盘缓存：HTML responseEnd 10ms、DOMContentLoaded／load 48ms。相同参数、均无 cursor 的素材列表连续读取两次：87–323ms（235ms）与 326–558ms（232ms）。LCP 的图片样本在 416ms／496ms；按钮等早期绘制不作为图片首屏。该样本是页面重载，**不是退出进程后的应用冷启动，也不是 NAS 冷磁盘样本**。

这些数据支持先修重复读取和桌面内存缓存缺口；不足以证明列表持久化收益、完整首屏提速比例或所有场景的主瓶颈。暂未完成完整进程冷启、逐张翻图及修复后的现用系统 A/B；不以测试夹具结果冒充真实图库延迟。

## 已实施的修复

### 桌面图片走原共用内存缓存

原 `EagleAssetThumbnail` 只允许 `/api/` 地址进入 `ThumbnailLoadService`。桌面地址是 `sekereagle-media:`，因此素材缩略图跳过原 512 项／128MiB 工作区内存缓存，返回时又经过磁盘及网络重验。

支持新协议的客户端复用同一 blob 加载器、在途合并、LRU、引用释放和主体／模式／私密状态清理。不增加另一套照片组件，不扩大内存预算；已有图片可在调度器忙时直接显示。旧客户端未声明能力时保持原路径，避免旧 CSP 下 fetch 失败。

真实隐藏 Electron 证明 fetch 还需要受控 CORS：只为媒体协议开启 CORS，响应仅允许当前连接服务器的精确 origin，保留凭据和窄响应头暴露；其他来源拒绝。原协议解析、主体校验、版本校验和不可持久化私密图的规则不变。CSP 仍禁止远端脚本、JavaScript eval 和对象；只为既有媒体协议补 fetch 权限。

### 照片派生图片接入原磁盘缓存

新 URL 明确携带 `material`／`photo` 模式段，主进程据此选择 `/api/eagle`／`/api/photos`。键和账号下的命名空间严格分离。历史 v1 命名空间只表示 MATERIAL，继续复用原素材文件；PHOTO 使用独立 v2 空间，不能命中 v1，即使构造相同资源／派生产物编号也不互通。

网页仅在 `mediaCacheVersion === 2` 时使用新协议；旧安装版本与普通浏览器的照片继续使用认证 API。复制图片也保留照片路由。账号统计、清空及资源失效覆盖当前账号的两个模式，不触及其他账号。私密响应仍不进入磁盘缓存；每次磁盘读取仍做原在线授权校验，没有延长时间租约或实现先展示再撤回。

### 启动不再校准自己刚发出的列表请求

原变化观察器首次得到快照时，会把正在读取的初始列表排入再次刷新。现让首次列表最多短暂等待**原有**轻量检查；只有明确仍在等待该检查的读取，才免掉同一次初始校准。其他已存在查询、检查超时／失败后先行的读取，以及重连／后续变更，继续原保守校准。

`VITE_WORKSPACE_STARTUP_CHECK_MS` 默认 250ms，是首屏对轻量检查的最大额外等待预算，不限制列表、照片或操作数量。到期立即执行正常列表读取，检查迟到仍会补校准；接口 503 或其他错误也释放等待。参数由网页构建环境设置；0 表示不给额外等待时间。保护的是启动响应时间，不以等待通知代替权限验证，也不裁剪已加载分页或重置滚动。没有观察器的独立视图及后续读取保持原同步发起行为。

### 统计按媒体请求，而非内部文件读取

面板展示本次连接内的直接本地复用、联网确认后复用、联网读取、等待同批下载和失败数。首次下载写入后的内部 acquire 不算命中；304 只算联网确认，首次下载不计节省字节。同批等待不冒充免联网命中。历史 SQLite 查找计数保留兼容读取，但不再用于展示“命中率”。

探针 `scripts/performance/client-cache-probe.mjs` 仅手动启用，可停止并恢复原 fetch；不随产品加载，不持久化或上报。只保留场景类别、数值时间、状态与结果类别，不记录照片／文件夹名称、URL、查询、账号或凭据。最多保留64个场景、每场景128条请求及4096条资源计时，超过后丢弃最旧记录并显式计数，防止长时间诊断占用无界内存；不是产品操作上限。

## 端到端成本

| 场景               | HTTP 与前端刷新                                               | API SQL／S3／事务                                                                             |
| ------------------ | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 有效内存缩略图     | 每图 0 次 HTTP，不经过磁盘或调度队列                          | 每图 SQL 0、S3 0、业务事务 0；独立会话／变化检查另计                                          |
| 首次照片磁盘未命中 | 每图 1 次原媒体请求，写入本机后展示                           | 原认证和 `getRendition` 读取，1 次对象 GET；没有新增 API 业务写事务；SQL 总次数未现场独立计量 |
| 照片磁盘重验成功   | 每图 1 次条件请求／304，本地提供内容                          | 原权限／当前版本读取及条件 S3 GET 均保持；省传图片正文，不声称省掉 SQL 或网络往返             |
| 正常启动校准       | 原轻量检查 1 次，首列表从重复的 2 次降为 1 次；超时退回原校准 | 每个实际列表请求的 SQL／S3 路径不变；减少一次完整列表读取，完整 SQL 数量未现场计量            |
| 清空当前账号       | 1 次 renderer IPC，内部按 2 个模式 namespace 执行原清理       | API 业务 SQL／S3／事务均 0；原本机 SQLite／文件删除按两个空间执行，认证主体发现可能另有 `/me` |

上述调用数量由测试及源码路径核对；现用页面重载的两次相同 GET 为真实样本。修复后的调用减少是隔离验证结果，未声称正式发布后的实测收益。

## 验证与限制

- RED 测试分别复现模式／路由缺口、统计 99% 假象、桌面已有缩略图仍等待调度器、首次列表被再读；修复后定向 GREEN。最终桌面 178 项、网页相关 198 项、探针 2 项通过，架构门禁及 42 项反例测试通过；变更范围 lint、桌面 typecheck、两端 build 和格式检查通过。
- 真实隐藏 Electron、独立临时 profile、loopback HTTP 及临时 SQLite：两个模式各一次 MISS、一次 REVALIDATED，正文下载共 2 次，条件重验共 2 次，相同编号内容互不串读。使用真实 preload、协议解析、缓存控制器、存储引擎及 CSP／CORS；不是完整生产 API 或真实图库。
- React 实际 sibling 装配顺序、慢检查到期恢复原校准、取消、已有分页／返回缓存、后续变化及权限清理均纳入原定向回归。完整进程冷启和生产网页／客户端配套更新仍需发布验收。
- 本分支基线 `c5a84320` 已含另一项任务的 RED 测试：`accepted-operation.test.ts` 缺实现，批量编辑及元数据回执也在等待另一任务的实现。全网页测试／typecheck／全仓 lint 的相应失败单独记录，不修改它们来制造全通过，不将本轮定向验证说成全仓 CI 成功。

最终全网页复跑为145个文件通过、3个文件失败，1083项通过、3项失败；另有缺失实现导致的导入失败，仍是上述基线文件。全仓lint仅剩该缺失实现测试的4处类型错误；本轮变更范围lint通过。网页typecheck也受这组未完成测试影响，桌面typecheck通过。证据在本工作区`.omx/artifacts/client-cache-experience/`。没有新增依赖副本、Docker镜像或数据卷；已清理本轮Vite／测试缓存，保留可复查源码、构建产物及依赖链接，交付时磁盘约45GiB可用。

## 尚未实施的后续能力

跨进程列表持久化及磁盘图片直接免网展示，需要能验证当前权限和完整结果依赖的服务端协议。`/api/library/changes` 是异步失效提示，不能作为旧列表或旧图片的授权证明；也不能直接公开混合私密写入的全局读取修订来规避边界。当前未保存旧列表后直接展示，未添加分钟数租约，未启用邻图预加载。后续以完整冷启和翻图样本确定收益与配套协议，不以扩大容量替代这些工作。
