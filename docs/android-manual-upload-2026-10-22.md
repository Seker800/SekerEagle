# 安卓手动上传

0.5.0／11 新增原生手动上传，网页与服务端业务接口保持现状。本轮只使用本机隔离服务、合成媒体与模拟器，不连接生产、群晖或 SekerChat。

## 使用

1. 在底部选择照片或素材，打开右上角三个点 → 上传。
2. 通过 Android 系统文件选择器选择一张或多张照片、视频、RAW，最多 100 个文件。
3. 确认页显示“上传到：照片／素材”、文件列表和不可上传项；点击“开始上传”。
4. 面板展示校验、重复检查、分片传输、服务器确认阶段及成功／跳过／失败结果。可取消，或只重试未完成项；已经成功的输入不会重新读取。

不需要启用自动备份，不扫描任何目录，不修改备份开关、规则、PAT 或持久检查点。手机原文件只读，服务器已有相同内容时跳过。服务器普通图库已删除的文件允许手动重新上传，不能凭旧手机备份回执错误跳过。

使用 [Android 官方文档选择流程](https://developer.android.com/training/data-storage/shared/documents-files)，只读取用户明确选择的 content URI，不新增全盘权限，也不新增持久化 URI 授权。系统选择器可展示云提供方；无法确定大小或暂不可读取的文件明确报错，建议先保存到手机再选择。

## 结构与隔离

- NativeGalleryViewModel 冻结打开选择器时的身份与模式；账号／模式变化后忽略旧选择结果。准备、上传、下载使用独立任务状态，防止弹出两个任务面板或将旧结果显示到新身份。
- NativeUploads 负责任务内队列和失败重试；NativeUploadDialog 只呈现状态；NativeUploadApi 将原生会话适配到既有 UploadApi。两模式共用同一实现，没有照片版上传组件或新服务端导入链路。
- 原生会话 epoch 绑定 API 调用和分片写入，上传前再次核实部署／主体作用域，刷新会话不会改变该绑定，重新登录与注销则使旧任务失效。元数据 API 携带本源 Cookie，签名分片 PUT 不携带 Cookie／Authorization，只通过现有受限 gateway URL 转发。
- 直接复用 BackupEngine、MultipartTransport、ApiClient 的签名分片传输和共享格式目录。内容去重、并发去重、格式校验、最终入库与 owner／模式边界仍由已有服务器裁决，DTO 不增加 ownerId。
- MediaCatalog.selected 只解析所选 URI，不调用扫描；扩展名与大小取自共享媒体策略，真实内容由服务端验证。文件读取、哈希和传输使用有界缓冲，不将大型 RAW／视频复制进内存。
- 手动任务使用独立的内存 Journal，不读写自动备份 SQLite 记录；新任务重新检查服务器内容。失败重试保留本任务未确认上传会话，每次重新计算源哈希，内容变化时丢弃旧分片检查点；缺少可靠修改时间的提供方依既有引擎保守重建会话。
- 上传成功后刷新当前模式的查询；不会清空用户的筛选或把相同内容跨模式合并。缩略图等派生处理仍可能在服务端继续执行。

## 取消与恢复边界

取消发生在读取／分片边界，当前网络请求可能需要等待超时；最终已被服务器确认的文件保留。未确认项可重试，重试前先去重核对，以处理“服务端已完成但响应未收到”的情况。取消不会删除手机文件或自动回滚已入库资源。

手动选择和任务记录保存在当前原生进程，屏幕旋转保留 ViewModel；不承诺进程被杀／重启后的自动续传。重新打开后再次选择即可，服务器去重避免重复入库。未完成分片沿用现有服务端会话过期清理，不新增后台扫描或唤醒任务。

## 验证

纯策略先红后绿：选择器只接受 content URI、按 URI 去重、拒绝超量而非静默截断；新任务不复用旧回执；显式重试清除终止错误但保留可恢复会话；源内容变化时不能复用旧分片。

模拟器验证覆盖：

- 系统选择器 Activity Result 契约经 Instrumentation ActivityMonitor 返回 app 自有合成文件，验证多选去重、确认目标、真实完整上传与服务器原件字节一致。
- 两文件首次上传、再次选择重复跳过；服务器回收某文件后手动重新上传形成新的普通图库资源。
- 一项成功、一项格式失败后修正失败文件并重试；已成功输入被移除后重试仍成功，证明未重新读取成功项。
- 同一文件分别上传照片／素材得到独立资源；模式切换丢弃过期的选择回调；自动备份开关和目录规则不变。
- 签名分片不带 Cookie，403 保留“续签而非清登录”语义；外部签名地址被拒绝；会话失效后旧请求在网络写入前被拒绝。
- 原有备份、清理、下载、搜索、多选、返回、会话与媒体安全流程继续回归。

这里验证了选择器启动与真实回调接入，文件列表由测试拦截返回；不冒充在小米实机上逐项点击系统选择器或完成后台行为验收。最终检查结果于下文补充。

最终结果：31 项完整模拟器测试、41 项 JVM 单测通过，手动上传真实 API 流程打包后独立复跑通过；Android lint／编译／构建、根仓库 lint／typecheck／unit test／build、架构与反例测试、格式检查通过。Java core 覆盖率门禁为行 98.11%、分支 86.22%，不代表 Compose 全应用覆盖率。实际确认页与结果页截图已检查；调试包已导出，模拟器运行 0.5.0。网页、后端业务、生产及群晖均未改动。

0.7.1 补充：确认及进度提示前台任务边界，离开应用主动停止，当前进程内可重试未完成项；取消可中断等待中的元数据 HTTP。首次身份核验阶段取消也保留完整重试列表；最终入库重复及已完成会话恢复计入现有内容／跳过，私密内容仍不在原生公开图库展示。见 [审查复核](android-review-2026-10-23.md)。

0.8.0 已按用户要求替换上述前台弹窗限制：系统选定文件后直接加入后台队列，上传不阻挡浏览，也不再因应用退到后台而停止；统一传输页同时展示自动备份。任务列表和手动分片检查点持久化，进程中断后可继续，来源权限失效时需要重新选择。历史 0.5／0.7 记录保留用于追踪，不作为新版交互说明。当前行为见 [统一后台传输](android-background-transfers-2026-10-23.md)。
