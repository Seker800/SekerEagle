# 安卓 0.7.1 审查复核

本次逐条复核用户提供的 0.6.0 审查，代码基线为已经完成目录多选、视频和日期滑块的 0.7.0。只操作本机隔离环境和模拟器；网页界面、生产、群晖与 SekerChat 均未改动。

## 结论与处理

| 原审查意见                         | 复核与本轮处理                                                                                                                                                                                                                                                          |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 批量操作／上传后跳回第一页         | 属实，值得修复。统一刷新当前已加载窗口，原子替换数据，保留稳定资源键和日期跳转的窗口偏移；不重置滚动指令。批量操作、上传完成和回前台共用此流程。                                                                                                                        |
| `drop(index)` 导致取消当前项丢失   | 该判断不成立，Kotlin 的 `drop(index)` 包含当前索引项。新增真实队列测试验证取消和重试。但另一个问题确实存在：首次 `/me` 等待期间取消，尚未进入循环，原实现未记录剩余项。已修复，重试覆盖全部未确认文件。                                                                 |
| 原生端看不到私密内容               | 属实，是目前未实现的能力，不能以增加 cookie 白名单冒充完整私密解锁。账号页和上传确认明确当前原生版仅公开图库；私密内容仍需网页解锁。本轮不扩张私密授权范围。                                                                                                            |
| 私密重复上传显示新增成功           | 属实且值得修复。保留服务端预检的私密隐藏语义，不扩大存在性探测；原生适配消费最终 `duplicate`，计为重复跳过，说明重复文件沿用服务器现有分类，私密内容不会出现在本机图库。预检后发生的普通并发重复也同样处理。仍可能传输一次字节，不为省流量削弱私密边界。                |
| 手动传输没有前台服务／持久队列     | 属实，当前不是持久后台任务。确认及进度明确提示保持前台、进程重启需重新选择；离开应用时主动停止并保留本次运行内的重试队列，旋转不停止。完整前台服务、持久手动队列和进程死亡恢复仍属后续能力，不能宣称已实现。自动备份继续使用现有前台服务及 SQLite，不受此限制说明替代。 |
| 正常退出／错误密码均显示会话失效   | 属实且已修复。无本地凭据时直接显示登录表单；登录 401 提示邮箱或密码错误；只有恢复连接失败提供“重试连接”，正常退出重启不请求 `/me`。                                                                                                                                     |
| 主线程 Keystore 与同步偏好写       | 属实。会话初始化移至 IO，排序／历史／普通备份偏好采用 `apply()`。凭据写入及擦除仍同步持久化，保证注销落盘顺序，不用异步写扩大重启恢复旧凭据的风险；加解密和正常令牌写入在 IO，主动注销的凭据擦除仍是很短的同步安全边界。                                                |
| 旋转丢失筛选草稿及批量标签         | 属实且已修复。草稿和选中标签使用可保存状态，按弹层区分；测试重建组合后仍保留。筛选日期说明也改为沿用当前排序，避免与用户选择的添加顺序矛盾。                                                                                                                            |
| 放大预览画质有限                   | 属实，是当前媒体来源限制。照片信息明确说明预览图与下载原片的区别；保留现有缩放手势，不擅自下载整个 RAW。按需高清切片是后续功能。                                                                                                                                        |
| 全屏磨砂必然造成卡顿               | 静态风险，不是已测得缺陷。没有小米帧时和 GPU 数据，不能声称必然掉帧，也不盲目取消用户要求的磨砂效果；留待小米实机测量。                                                                                                                                                 |
| 回前台不刷新、没有下拉刷新         | 回前台不刷新属实且已修复：认证复核后在非选择、非大图、非编辑、非传输的空闲状态刷新保留位置。另在三点菜单提供“刷新”，可主动更新结果；本轮未增加下拉手势。                                                                                                                |
| 没有磁盘缓存                       | 属实，属于后续优化。现有内存缓存有界且作用域隔离，未以未经保护的磁盘缓存替换。                                                                                                                                                                                          |
| 进程死亡后导航状态丢失             | 属实，当前只保证配置重建保留 ViewModel 导航和可保存的筛选草稿；不宣称整个进程被回收后能恢复大图／滚动／手动任务。完整恢复需要持久导航与重新验证资源，留待独立实现。                                                                                                     |
| 合并全选静默截断                   | 属实且已修复。按原选择与新候选的并集检查 100 项上限并提示，已有选择优先保留。                                                                                                                                                                                           |
| 回收站仍能上传                     | 属实且已修复。菜单隐藏入口，ViewModel 同时拒绝回收站发起选择器，不只依赖界面隐藏。                                                                                                                                                                                      |
| 减少动画／透明度适配               | 固定 `tween` 本身不能证明绕过 Compose 系统动画时长控制；透明度和磨砂的可访问性仍需实机检查，本轮不宣称完整适配。                                                                                                                                                        |
| 旧 WebView User-Agent 固定 0.1.4   | 属实，改为构建版本号，旧备份宿主仍不作为核心图库入口。                                                                                                                                                                                                                  |
| `identity!!`、无仓储时选项永久加载 | 属实，模式切换先校验身份；打开筛选先校验仓储，再修改加载状态。                                                                                                                                                                                                          |
| JSON 请求取消最多等待超时          | 属实，上传元数据及下载前后复核绑定独立取消对象，取消直接断开连接，刷新重试链路也保留取消检查。已验证阻塞 HTTP 在取消后立即结束，不等待 30 秒超时。签名分片继续使用原有有界读取和 guard。                                                                                |
| 完整设备套件没有可信结果           | 原审查时成立，但已被 0.7.0 的 36 项完整通过记录更新。本轮仍重新运行完整套件，不借用旧结果冒充本轮通过。                                                                                                                                                                 |
| 排序缺少 JVM 测试、共享偏好未清理  | 增加默认顺序及独立偏好键的 JVM 检查。日期解析／日期头／真实分页已有设备覆盖；0.7.0 的排序设备测试已经恢复两模式默认值，原文后半条已过时。                                                                                                                               |

## 验证与实际边界

测试先建立缺失能力的 RED 编译检查点，再实现并运行对应 GREEN 设备回归；新增状态回归覆盖三页列表刷新及版本更新、正常退出和错误密码、筛选／批量标签草稿恢复；传输回归覆盖最终重复、阻塞 JSON 取消、首次身份核验取消后的全队列重试，以及取消当前下载后完整重试且原件正确保存。

本机和模拟器通过不能替代小米实机验收。后台持久传输、私密解锁、高清切片、进程死亡恢复、磁盘缓存及磨砂性能尚未完成，本轮未展示这些功能的虚假入口。

最终验证：42／42 项完整模拟器设备回归通过，无失败、无跳过；44 项 JVM 测试通过。全仓库 lint、typecheck、unit test、build、格式与共用架构门禁通过；原生边界及 Android 编译／lint／构建通过。中间一次新增测试没有考虑安卓同名文件自动改名，已修正统计并验证两份原件；另一次旧 WebView 回归触发 Chromium 原生崩溃，重启模拟器后完整套件通过，没有跳过旧回归或关闭安全检查。
