## 0.9.3 搜索与标签检查（2026-10-25）

搜索页的关键词、标签、相机、镜头、导入日期、格式、最低评分、GPS 先编辑为同一草稿，子面板「确定」返回搜索页，「查看结果」才统一发起查询；取消子面板／搜索保留提交前的结果与滚动位置。结果页移除单项条件仍立即更新结果，保留其他条件。关键词提示与既有服务端搜索一致为名称／标签，不再声称搜索描述；不同类别取交集，标签／格式内部任意匹配，日期明确按设备时区的导入日期，含夏令时日界。

修复标签目录超过原 2 MiB 预算失败、全部标签按钮一次性布局造成卡顿，以及标签被格式／摄影接口失败连带阻断。目录读取独立限额为 16 MiB，其他 JSON／媒体限额不变；媒体 MIME 由显式请求类型决定，不能通过增加预算绕过。标签支持名称、服务端拼音及首字母查找，勾选上限 100；相机／镜头同样可搜索且虚拟化，提交／取消按钮固定在面板底部。批量添加／移除标签继续共用选择器，实际应用全部所选标签，不使用搜索的任意匹配文案。各选项独立加载／出错／重试；日期、评分不依赖目录接口。关闭、重试、提交、换模式／身份或退出时取消并断开旧连接，避免慢标签占住请求通道。

## 0.9.1 自定义图片缓存（2026-10-25）

右上角菜单直接进入「缓存设置」，默认上限 512 MB，可输入 0–16384 MB，提供 128 MB／512 MB／1 GB／2 GB 快捷值、当前占用、保存及确认清理；0 关闭持久缓存。容量在照片／素材间共用，超过上限按最近使用顺序淘汰，降低上限立即缩容；清理不删除手机原图、下载或上传任务。内存位图仍独立有界，当前正在显示的图片不会因清理而变灰，也不会由旧下载回填已经清理的缓存。

缩略图和普通预览以设备 Keystore AES-GCM 加密保存到应用私有缓存，重启后在重新认证、取得当前列表／详情后优先复用，不再为缓存命中重新下载图片文件。缓存键包含认证主体作用域（服务、部署、owner）、固定模式路径，以及资源更新时间／媒体与派生版本、格式、尺寸和字节数；同图并发请求合并，内存命中也更新磁盘使用顺序。私密图片、不在已取得元数据内的路径、原图、RAW 编辑源及视频不会写入此缓存。退出或认证失效触发清理，失效会话不能读取内存／磁盘命中。单条缓存至多 16 MiB 加密开销、至多 10 万条索引，避免大容量设置导致无界内存索引。

图库列表仍以服务器授权为准，此功能不宣称完整离线图库；Android 系统可以回收缓存，丢失或损坏时安全重新下载。缓存目录由系统移除后可以自动重建，容量和缓存内容各自跨进程保留。安装包为 `apps/android/release/SekerEagle-0.9.1-android-debug.apk`，沿用旧调试版签名，无需部署服务器。 验证：完整 API 36 arm64 设备套件 65／65 通过，最终设置页／长列表／缓存安全等 8 项定向回归通过，零失败／跳过；写入后强制结束应用进程，再启动读取同一加密缓存成功。JVM 60 项、Lint 零错误（10 个既有警告）、核心行／分支覆盖率 96.9%／84.8%，完整 CI 通过。并发八次只请求一次图片，4200 条元数据索引换出后仍复用磁盘缓存；清理中的下载不使图片变灰且不能回填旧缓存。

## 已确定的产品方向

2026-10-22 用户确认：网页端保持现状，安卓端转为独立原生 App，以小米自带相册为体验标杆。功能分阶段补齐，操作体验优先。用户此前提供的首页、菜单、大图和搜索截图均来自小米系统相册，不能误记为其他相册或仅按通用网页风格处理。

## 边界

- 网页冻结当前功能、布局和已有手机呈现，不回滚此前改动，也不再为安卓体验继续改网页组件或 CSS。网页自身缺陷修复另按具体任务处理。
- 安卓使用 Kotlin＋Jetpack Compose，拥有独立导航、界面、手势和加载状态；共用现有服务器、账号和 API。照片与素材两模式在安卓内部共用通用原生组件与数据访问实现，按模式配置，不复制两套 App。
- 共用业务核心指服务端规则、资源语义与 API 契约；原生图库与登录不嵌入 React；0.9.0 仅按用户明确要求将同一网页编辑画布打包进受限离线宿主。不得复制上传入库、权限、去重或媒体处理的服务端决策。
- 逐步替换核心 WebView 页面。已替换的流程不得跳回网页；未完成的地图、人物等入口先隐藏；编辑仅使用上述受限离线宿主。保留旧预览实现只用于迁移期间回归，不将网页作为新原生流程的功能兜底。
- 复用已验证的 Java 备份核心、SQLite 检查点、Keystore、目录授权和上传恢复，通过明确接口接入 Kotlin；不为了换语言重写整套备份引擎，不复制检查点存储。
- 认证接入先核实既有登录、会话续期、注销与 PAT 契约；原生界面不依赖 WebView Cookie 作为唯一登录来源。会话与仅上传权限的备份令牌职责分开；不扩权、不在 Compose 层存凭据。若确需 API 调整，单独补契约和安全测试。
- 服务 origin／deploymentId／owner／模式共同限定缓存、搜索历史、下载、备份和在途请求。切换身份后停止旧任务、清理界面及内存状态；受保护缓存遵循注销与私密锁定语义。
- 只在本机隔离服务、模拟器及用户的小米手机测试，不部署生产，不连接群晖或 SekerChat。真机使用隔离测试账号和明确选择的手机测试目录；释放空间不自动启用。

## 原生结构与职责

Compose 页面只处理呈现与输入；页面状态及导航统一管理，仓储接口封装现有 API、媒体缓存和备份适配。界面不直接操作 HTTP、SQLite 或删除手机文件。导航、手势、加载与错误语义在照片／素材间共用。具体库版本与构建配置在实施前核查现有工程和官方文档，避免提前锁定未经验证的依赖。

大图普通浏览优先使用派生媒体并有界缓存；仅用户明确下载、分享或后续编辑时按需访问原件。不能为了缩放提前把整个 RAW／视频载入内存。服务端仍为权限、支持格式、去重与资源变更的最终裁决方。

阶段 1 优先验收：

- 长列表滑动、分页与回到列表位置；加载中不闪白、不反复跳位，失败可重试。
- 大图双指缩放、平移、双击缩放与左右切图手势协调，加载／切换期间不展示上一张的错误状态。
- 系统返回先关闭当前菜单或弹层，再回退页面，根页面才退出；返回列表保持位置，旋转和恢复不丢失导航上下文。
- 搜索进入、系统键盘弹出／收起、提交、清空与返回连贯；历史按身份／模式隔离，私密查询不持久化。
- 磨砂、胶囊、字号、触摸区域及动画以用户的小米截图与实机为依据；保留系统字体缩放、深浅色可读性与减少动画设置的适配，不照搬截图的物理像素尺寸。

阶段 2 数据语义：

- 收藏、标签与回收站沿用既有服务端契约；先核实收藏的既有标签方案和私密冲突，不悄悄新增另一套收藏事实源。删除进入服务器回收站；与删除手机本地文件明确分开。
- 手机备份仅处理照片、视频、RAW 和下载图片，目录可选；目标模式按目录固定，浏览模式切换不得改变备份目的地。
- 增量、内容去重与上传恢复继续使用现有引擎；打开自动扫描备份是可选项，不承诺绕过 HyperOS 后台限制或新增未授权定时唤醒。
- 释放空间只删除已复核有服务器备份的手机文件，保留服务器副本；预览、用户确认、系统授权、取消和失败恢复均可验证。

## 小米实机验收方式

每阶段先通过隔离服务契约测试、原生单测和模拟器交互回归，再交付调试包在用户的小米手机验收。模拟器通过不等于实机通过；没有完成实机检查时，阶段保持“待实机验收”，不能以截图检查代替。现有自动模拟器门禁继续拒绝物理手机，不能为真机测试移除安全检查；真机采用单独明确的隔离接入步骤。

逐项记录机型、HyperOS／Android 版本、屏幕刷新率、字体／显示缩放、样本数量、媒体类型和网络条件。与系统相册对照返回层级、手势、动画、排版、响应速度、首屏及长列表流畅度，同时记录慢网、断网、撤销权限、后台恢复和内存压力结果。实测后确定可复现的性能预算，不提前编造帧率或耗时达标结果。实机体验过关再扩展下一阶段。

## 实施纪律

每阶段保留可安装、可回归的版本；构建、原生 lint、类型／编译检查、单测与适用的设备测试通过后交付。改动认证、上传、API 或删除路径时补安全与失败恢复测试；改通用服务端能力继续通过原有 architecture:check 和共用契约。原生模块门禁随实现补充两模式契约及反例测试，不能拿网页 AST 检查通过冒充原生架构已受检。
