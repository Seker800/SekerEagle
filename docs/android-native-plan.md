# 安卓独立原生 App 实施计划

## 已确定的产品方向

2026-10-22 用户确认：网页端保持现状，安卓端转为独立原生 App，以小米自带相册为体验标杆。功能分阶段补齐，操作体验优先。用户此前提供的首页、菜单、大图和搜索截图均来自小米系统相册，不能误记为其他相册或仅按通用网页风格处理。

本文件是安卓后续实施依据，替代先前继续改造响应式网页／WebView 来交付安卓核心交互的方向。0.1 系列是 Java 原生备份与 WebView 图库的历史预览版；0.2.0 已开始独立原生迁移，具体交付范围见末尾状态，尚未完成全部功能和小米实机验收。

## 边界

- 网页冻结当前功能、布局和已有手机呈现，不回滚此前改动，也不再为安卓体验继续改网页组件或 CSS。网页自身缺陷修复另按具体任务处理。
- 安卓使用 Kotlin＋Jetpack Compose，拥有独立导航、界面、手势和加载状态；共用现有服务器、账号和 API。照片与素材两模式在安卓内部共用通用原生组件与数据访问实现，按模式配置，不复制两套 App。
- 共用业务核心指服务端规则、资源语义与 API 契约；不要求 Kotlin 复用 React 组件，也不把现有 TypeScript 代码直接塞入原生界面。不得复制上传入库、权限、去重或媒体处理的服务端决策。
- 逐步替换核心 WebView 页面。已替换的流程不得跳回网页；未完成的地图、人物、编辑等入口先隐藏。保留旧预览实现只用于迁移期间回归，不将网页作为新原生流程的功能兜底。
- 复用已验证的 Java 备份核心、SQLite 检查点、Keystore、目录授权和上传恢复，通过明确接口接入 Kotlin；不为了换语言重写整套备份引擎，不复制检查点存储。
- 认证接入先核实既有登录、会话续期、注销与 PAT 契约；原生界面不依赖 WebView Cookie 作为唯一登录来源。会话与仅上传权限的备份令牌职责分开；不扩权、不在 Compose 层存凭据。若确需 API 调整，单独补契约和安全测试。
- 服务 origin／deploymentId／owner／模式共同限定缓存、搜索历史、下载、备份和在途请求。切换身份后停止旧任务、清理界面及内存状态；受保护缓存遵循注销与私密锁定语义。
- 只在本机隔离服务、模拟器及用户的小米手机测试，不部署生产，不连接群晖或 SekerChat。真机使用隔离测试账号和明确选择的手机测试目录；释放空间不自动启用。

## 原生结构与职责

Compose 页面只处理呈现与输入；页面状态及导航统一管理，仓储接口封装现有 API、媒体缓存和备份适配。界面不直接操作 HTTP、SQLite 或删除手机文件。导航、手势、加载与错误语义在照片／素材间共用。具体库版本与构建配置在实施前核查现有工程和官方文档，避免提前锁定未经验证的依赖。

大图普通浏览优先使用派生媒体并有界缓存；仅用户明确下载、分享或后续编辑时按需访问原件。不能为了缩放提前把整个 RAW／视频载入内存。服务端仍为权限、支持格式、去重与资源变更的最终裁决方。

## 阶段与验收门槛

| 阶段              | 可交付范围                                                                                       | 进入下一阶段的条件                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 0：基础与迁移边界 | Kotlin／Compose 工程、原生登录与会话、模式作用域、导航栈、设计规范、Java 备份适配边界            | 能登录隔离服务、注销与换账号不串数据；确认网页零界面改动，既有备份回归通过         |
| 1：日常看图       | 照片／素材列表、大图、搜索形成完整原生流程；首屏、分页、预取、有界缓存、空／加载／失败与重试状态 | 小米实机对照系统相册验收通过；核心流程不进入 WebView，未完成的管理和高级功能不展示 |
| 2：常用操作与备份 | 系统分享、收藏、回收站、标签；目录选择、增量去重、打开自动备份、进度／取消／重试、释放手机空间   | 操作结果清楚、断网与重启可恢复、两端数据语义一致；真机系统授权与删除确认通过       |
| 3：高级功能       | 按实际使用频率逐项接入地图、人物、编辑等                                                         | 每项独立验收后才开放入口，不以网页拼凑流程                                         |

阶段 1 优先验收：

- 长列表滑动、分页与回到列表位置；加载中不闪白、不反复跳位，失败可重试。
- 大图双指缩放、平移、双击缩放与左右切图手势协调，加载／切换期间不展示上一张的错误状态。
- 系统返回先关闭当前菜单或弹层，再回退页面，根页面才退出；返回列表保持位置，旋转和恢复不丢失导航上下文。
- 搜索进入、系统键盘弹出／收起、提交、清空与返回连贯；历史按身份／模式隔离，私密查询不持久化。
- 磨砂、胶囊、字号、触摸区域及动画以用户的小米截图与实机为依据；保留系统字体缩放、深浅色可读性与减少动画设置的适配，不照搬截图的物理像素尺寸。

阶段 2 数据语义：

- 收藏、标签与回收站沿用既有服务端契约；先核实收藏的既有标签方案和私密冲突，不悄悄新增另一套收藏事实源。删除进入服务器回收站；与删除手机本地文件明确分开。
- 手机备份仅处理照片、视频、RAW 和下载图片，目录可选；目标模式按目录固定，浏览模式切换不得改变备份目的地。
- 增量、内容去重与上传恢复继续使用现有引擎；打开自动扫描备份是可选项，不承诺绕过 HyperOS 后台限制或新增未授权定时唤醒。
- 释放空间只删除已复核有服务器备份的手机文件，保留服务器副本；预览、用户确认、系统授权、取消和失败恢复均可验证。

## 小米实机验收方式

每阶段先通过隔离服务契约测试、原生单测和模拟器交互回归，再交付调试包在用户的小米手机验收。模拟器通过不等于实机通过；没有完成实机检查时，阶段保持“待实机验收”，不能以截图检查代替。现有自动模拟器门禁继续拒绝物理手机，不能为真机测试移除安全检查；真机采用单独明确的隔离接入步骤。

逐项记录机型、HyperOS／Android 版本、屏幕刷新率、字体／显示缩放、样本数量、媒体类型和网络条件。与系统相册对照返回层级、手势、动画、排版、响应速度、首屏及长列表流畅度，同时记录慢网、断网、撤销权限、后台恢复和内存压力结果。实测后确定可复现的性能预算，不提前编造帧率或耗时达标结果。实机体验过关再扩展下一阶段。

## 实施纪律

每阶段保留可安装、可回归的版本；构建、原生 lint、类型／编译检查、单测与适用的设备测试通过后交付。改动认证、上传、API 或删除路径时补安全与失败恢复测试；改通用服务端能力继续通过原有 architecture:check 和共用契约。原生模块门禁随实现补充两模式契约及反例测试，不能拿网页 AST 检查通过冒充原生架构已受检。

当前状态：0.2.0 已实现阶段 0／1 的本机原生候选版，包括原生登录／续期、双模式列表、派生媒体查看、双击与双指缩放、左右分页、搜索和返回；Java 备份与清理通过原生入口继续利用。阶段 1 尚待小米实机验收，不能据模拟器结果扩展为已达到系统相册的性能与手感。视频当前仅展示封面；系统分享、收藏、标签、回收站的新原生管理入口及高级功能继续按后续阶段接入。详见 [首版验收记录](android-native-verification-2026-10-22.md)。

2026-10-22 用户进一步授权补齐常用能力：0.3.0 增加原生标签／摄影／格式／导入时间筛选、长按多选、批量标签和评分、回收站及恢复。共用服务端契约和原生装配边界不变，网页继续冻结；此授权允许阶段 1 实机验收前推进上述能力，不代表实机性能已过关。功能与尚未覆盖范围见 [筛选多选验收](android-native-controls-2026-10-22.md)。

2026-10-22 后续体验修正：0.3.1 将查找条件从“视图”移到放大镜搜索页，结果顶部显示可逐项移除的条件胶囊；同类标签／格式为任选，不同类别同时满足。视图只保留显示方式，不改变网页与服务端边界。见 [搜索筛选修正](android-search-filters-2026-10-22.md)。

2026-10-22 用户追加下载：0.4.0 接入大图单张原件下载和选择模式批量下载，使用同一原生队列、授权传输与 MediaStore pending 发布，继续遵守仅用户明确下载时访问原件的边界。进度、取消、失败重试及验证见 [原件下载说明](android-downloads-2026-10-22.md)。

2026-10-22 用户追加手动上传：0.5.0 通过系统文件选择器接入原生确认和队列，复用备份上传引擎、现有去重与入库 API，手动任务不启用自动备份、不扫描目录、不复用持久备份回执。模式与主体冻结、安全和验收见 [手动上传说明](android-manual-upload-2026-10-22.md)。

## 2026-10-23：备份目录、视频与快速滚动（0.7.0）

- 手机相册改为“添加手机相册”：只显示尚未添加的目录，勾选多个后按“添加（数量）”追加；取消不会改变已有列表，已有模式／递归设置保留。其他文件夹使用安卓逐个目录授权，选中后追加，可连续添加；它与相册选择属于同一备份列表。
- “备份全部照片和视频”覆盖已授权系统媒体库中的照片、视频、RAW 和下载图片，也包含以后新增的相册。开启时暂时覆盖自选媒体目录，关闭后恢复原列表；目标照片／素材可选。用户另外授权的目录仍保留，系统未收录的 RAW 不会被冒充为已经扫描。全部备份、原列表和回执均按原账号／部署／服务隔离。重叠媒体目录按最具体目录只枚举一次。
- 视频使用安卓 MediaPlayer 硬件／系统解码能力，支持原生播放、暂停、进度拖动和按比例显示；切页和退出释放播放器，后台和音频焦点丢失时暂停。仅流式读取当前版本的 MP4 播放副本，最多保留 512 KiB 应用读取窗口，不缓存整片、不用原视频兜底。没有播放副本时显示未就绪提示；不承诺设备不支持的编码能够播放。
- 主图库滚动时出现右侧微型滑块，停止滚动后自动隐藏；按住时展开轨道背景、年份和完整年月日，松手定位。共用 API 按设备时区、当前模式和排序聚合全库公开资源；二分查找日期、日内偏移定位，避免只导航已加载的 60 项或只能到当天开头。定位后继续向较早照片翻页，向上拖动补入较新资源。搜索、筛选和回收站隐藏全库导航。
- 网页源码和默认布局保持不变；只使用本机临时数据库、对象存储和模拟器，未部署生产、未连接群晖。

验收：本机 API 验证两种模式、两种时间顺序、时区日边界和日内偏移；36 项完整模拟器回归及 43 项 JVM 测试通过，Java 核心覆盖率门槛通过。原生测试实际解码合成 MP4、暂停与拖动进度，验证 206／Range／MIME、错误重定向和注销后缓存读取拒绝；目录追加保留旧设置，全部备份覆盖新增目录。已检查深色宿主中的滑块与视频截图及备份列表。全仓库 lint、typecheck、unit test、build、格式及架构门禁通过。小米真机仍待验收。

补充实测：通过正常上传 API 向隔离环境的照片与素材分别导入合成视频，两端均生成当前版本 MP4 播放副本，认证 Range 返回验证通过；已在实际原生大图中确认视频画面与进度播放。混合图库的缩放测试明确选择照片，不再假设首页第一项一定是图片。
