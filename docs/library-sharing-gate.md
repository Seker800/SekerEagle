# 素材／照片共用逻辑门禁

目的：两种模式隔离业务数据，共用通用实现；修复通用功能时只维护一份代码。门禁落在仓库命令和 CI 中，约束后续开发与 agent，不依赖记住聊天记录。

## 2026-10-22 安卓原生边界

用户确定安卓以 Kotlin＋Jetpack Compose 独立呈现，网页冻结当前界面；理由是手机手势、导航、键盘和加载体验需要由原生统一管理。共用边界为服务端业务核心与 API 契约，不要求跨技术栈共享 React 组件；安卓照片／素材内部的通用组件、数据访问和备份引擎仍必须共用，禁止模式分叉。既有 Web／API 门禁和反例测试保持原样，不新增豁免。此文表格中的 React 装配约束继续适用于 Web，不把它错误扩展为禁止原生界面；当前 AST 门禁不覆盖 Kotlin，原生实现阶段需补对应契约与反例测试。计划变更本身不修改门禁程序或宣称 Kotlin 已受检。详见 [安卓原生计划](android-native-plan.md)。

## 共用范围与允许差异

| 能力         | 必须共用                                                                  | 允许差异                                                                               |
| ------------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 工作区与图库 | `SekerEaglePage`、瀑布流、缩略图、缩放、查看器                            | 左侧入口、名称、照片时间排序、相似组折叠与组内切换、通用布局策略参数及右侧摄影时间刻度 |
| 筛选         | `EagleQuickFilterBar`、共享筛选状态与字段目录、规则引擎                   | 照片通过字段目录增加相机、镜头、GPS、人物                                              |
| 管理操作     | 上传、编辑、标签、分类、回收站、媒体读取的客户端工厂与应用服务            | 由不可变模式限定路由、资源和缓存作用域                                                 |
| API          | 资产、上传、AI 标签、向量、处理任务 Controller 的继承方法及同一服务注册表 | 路由前缀、固定模式绑定；维护调度只注册一次                                             |
| 摄影领域     | 不接管通用图库和筛选器                                                    | EXIF、人脸、人物、地图、照片组、版本观察者                                             |

相机格式目录与预算集中在 `library-core`，RAW／视频处理集中在 `media-core`；两种模式不得分别增加上传白名单或解码器。RAW 传感器输入预算与 RGB 显影输出预算分开，显影副本和原片尺寸分开传递；当前版本 `PREVIEW/edit` 无损副本复用既有鉴权派生媒体读取与编辑保存，普通预览排除 edit 副本，避免图库意外加载大图。

共用不表示数据共享。owner × mode、私密、回收状态、版本与上传会话隔离继续由现有安全与数据库测试验证。浏览器采集、旧 Eagle 导入入口及桌面原文件拖出当前仍有素材专属边界，不在本门禁中强行变成照片能力。

## 门禁如何工作

照片编辑沿用既有 `PhotoEditor` 与 Worker、共用上传客户端及 `EagleUploadService`；两模式只绑定路由与查询键。来源声明、私密继承和重试均进入既有上传实现，不新增照片专属保存 Controller 或并行编辑器。原编辑器的布局与像素算法保持一份。

`npm run architecture:check` 只读源码，以 TypeScript AST 检查：

- App 只装配一个共用工作区；共用瀑布流、缩略图、筛选栏、查看器及上传／编辑 hooks 各有一个装配点，不能直接放入按模式判断的分支。
- 图库只定义一份通用卡片，内部不能按模式增加日期等展示分支。无障碍标签与标题措辞允许不同；照片组角标由实际组数据决定。
- 瀑布流算法、缩略图、查看器与快捷筛选状态保持模式无关；无障碍文案允许不同。模式作用域与摄影字段可见性属于各自适配层。
- Web／API 通用 Eagle 模块不能反向导入摄影目录或摄影 API，工作区页面是显式组合入口。检查普通 import、重导出、动态 import 与 require。
- 照片的五个通用 Controller 必须保持空继承，不覆盖方法或构造函数；共用 provider 注册表必须完整复用，仅排除全局维护调度实例。新增摄影 provider 或改变注册方式须明确调整边界规则。
- 缺失必要入口、源码解析失败均报错；不是找不到文件就跳过。错误包含文件、规则和修改方向。注释中的假代码不会触发规则。

`npm run test:architecture` 用内存副本故意制造重复渲染、模式分支、日期覆盖、反向依赖、方法覆盖、服务替换、缺失入口等变化，断言门禁拒绝它们，不修改实际源文件。检查器的行、分支、函数覆盖率分别要求至少 80%。

`npm test` 另外包含两组运行时契约：

- API：确认五组 Controller 的每一个路由使用同一处理函数，照片适配器实际注册，路由／守卫元数据一致，两个模块完整且不重复地注册同一批通用 provider，并分别绑定固定模式。新增基类路由自动进入此契约。
- Web：六类客户端工厂暴露相同操作；列表／搜索、标签修改、回收／恢复、规则计数、AI 标签、向量、处理任务及隐私请求保持方法、载荷、凭据与结果语义一致，只有作用域路径不同。

这些检查保护已定义的结构与行为，不证明任意代码的语义完全等价，也不替代浏览器验收、owner／mode 隔离测试或代码评审。间接布尔变量、任意运行时动态装配、CSS 覆盖及未经列举的新能力仍需审查；不能把“门禁通过”解释为所有差异自动合理。

## 本地与 CI

```sh
npm run architecture:check
npm run test:architecture
npm run ci:check
```

现有 GitHub Actions `check` job 执行 `ci:check`，结构门禁位于最前，失败立即返回非零；全量单测也执行反例与运行时契约。仓库脚本不修改 GitHub 分支保护配置，是否禁止合并由仓库对必需检查的设置决定。

普通修复应修改共用实现后验证两种模式。确实新增摄影能力时，优先通过现有字段目录、组数据、摄影模块或工作区组合接入。若必须调整装配边界，先在北极星和本文记录原因，再修改契约并增加能区分合理扩展与分叉的反例；不要删除检查或放宽成按文件名一律豁免。

## 2026-10-19 横排时间线

用户明确更新照片首页为横向等高排版与右侧日期跳转。允许在工作区选择通用布局策略，布局 hook 仍只有一个装配点且不感知模式；共享卡片不增加日期分支。摄影时间刻度在组合层接入，使用 owner 与 PHOTO 作用域的全库月索引和既有分页游标；不允许另建照片版缩略图、选择、查看器或上传链路。

大图定位操作使用共用按钮、定位状态及服务端游标逻辑。两个模式仅按既定日期排序与工作区装配返回对应首页，不派生照片专属通用查看器或 Controller。

2026-10-19 用户授权的跨模式「发送到」是共享写服务的显式例外：从源路由推导另一目标模式，通过独立资源与对象复制实现移动，禁止原地改模式、复制关系记录或放宽普通接口作用域。两套 Controller 继续继承同一方法。

2026-10-19 年月分隔：工作区提供模式无关的 sectionKeys 给同一个横排布局，算法只处理分段键、标题区域与行边界，不读取摄影日期或模式。标题在卡片外独立虚拟化；日期取值与年月格式化仍由摄影适配层负责。素材不提供分段元数据时布局完全不变，不能复制第二套图库、卡片或选择逻辑。

2026-10-20 正式照片编辑：保持一个共享工作区编辑会话与现有 PhotoEditor，通用查看器、详情和单选菜单仅转发编辑请求；组内照片复用同一入口。摄影元数据通过既有资源契约映射为水印字段，不在通用 Eagle 模块反向依赖摄影模块，不新增上传或保存接口。

跨库发送的私密状态通过目标模式独立人工标签维持，沿用共用发送服务和私密投影锁；不新增照片专用发送实现。源标签、分组仍不跨库共享。

门禁同时追踪常量模式别名及别名链，并扫描摄影目录中的额外共用 Controller 子类；混合具体视图状态的组合表达式仍由既有组合契约和运行时测试约束，不声称静态 AST 检查能证明任意程序等价。

单张与照片组图片统一复用 `EagleImageViewer` 与共用 `EagleViewerShell`，视频共享外壳；组内缩略图条与组操作由摄影包装层通过插槽装配，不能复制查看器或引入模式条件版通用渲染。

快捷筛选布局继续由同一组件管理；仅默认固定字段与 localStorage 键按模式配置，照片默认相机、镜头、标签、格式。按模式重建该组件的临时交互状态以关闭旧弹层并读取对应布局，不建立摄影版筛选器或第二套规则状态；保留已有两种模式的自定义存储。

编辑草稿、成片配方与批量应用继续共用已有编辑器、渲染 Worker、Controller 和上传服务；参数契约下沉 library-core 供 API 校验与 Web 使用，不反向引用 Web。批量编排是编辑应用层，不增加摄影版编辑器、上传 Controller 或持久化旁路。

2026-10-20 成片时间与照片组：沿用既有 LibraryRevisionObserver 的摄影装配，增加成片发布前锁定与发布后事务事件，PHOTO 观察者拥有时间／摄影信息继承及归组；共用上传只发送受 owner／模式约束的来源事件，不反向导入摄影模块、不新增 provider 或 Controller。Worker 按持久化的继承标记保护拍摄信息，并重新计算成片像素分析。卡片角标仍由实际组数据决定，排序说明位于工作区组合层，不在通用卡片中增加模式分支。

2026-10-20 编辑预览：同一共享会话冻结当前版本的普通预览、高清来源及高清尺寸，交互不读取原片，保存按需读取高清来源；水印使用图库已有摄影元数据。缺少可靠预览／尺寸的历史资源保留既有路径，RAW 高清来源仍为专用显影副本，不引入第二套渲染器或新 API。

## 2026-10-20 照片智能整理

允许摄影模块注册 PhotoAgentService，负责冻结范围、建议和补充位置；它通过共用回收事务函数组合审核，不覆盖 EagleService 或任一共用 Controller。只读／建议 API 通过 PAT scope 控制，审核写入口仅浏览器可用。MCP 为独立客户端适配器，只调用现有认证 API，不建立数据库旁路；照片整理界面仅在工作区组合层装配。共用资产投影可携带版本匹配的补充位置字段，城市规则加入现有共享筛选目录；地图明确区别城市级与 GPS。门禁及反例需同步验证允许摄影 provider、拒绝替换共用 provider。

## 2026-10-20 人物隐私

照片沿用人工私密标签与同一个隐私可见开关，新增人物的私密规则。私密结果是当前版本人工标签、当前有效人脸所属私密人物的并集；实况同标识组件保守共享保护。API 与 worker 共用后端 library-persistence 中的事务投影，不在浏览器公共 library-core 引入数据库依赖，不覆盖共用 Controller 或 provider。人物合并保留任一方私密规则；纠错与分析写回必须在同一事务更新投影，锁顺序为隐私、人物。人工纠错在同一媒体版本的模型重跑中保留。

摄影人物入口只管理人物规则，通用图库、搜索、地图、媒体与 MCP 继续读取共用 isPrivate。编辑副本通过独立人工私密标签保留来源保护，不复制人脸分析；不自动删除、模糊人脸或将尚未分析的照片全部隔离。识别可能漏检，敏感照片仍可人工加私密标签。实施和测试限独立本机环境，不部署现用服务。

照片隐私复核：原件替换继续使用共用上传服务，按隐私 → 资源锁序保存旧实况组件的独立私密标签并同步投影；不引入摄影版上传分支。两个模式的私密标签保存共用快照比较，拒绝过期草稿；照片投影使用资源集合成员判断，避免与全库中间结果逐行连接。类型入口不依赖构建产物，独立临时库覆盖替换并发、实况双向替换及十万记录基准。

## 2026-10-21 一次性共享相册导入

导入脚本是现有认证上传协议的 PHOTO 客户端，不新增摄影版上传 Controller／provider。处理进度扩展写在共用 EagleUploadService.getSession，素材与照片返回同一契约；owner 与模式限定、无权会话返回 404 由共用测试覆盖。只读源目录仅作为一次性导入输入，不参与图库日常读取；SQLite 是客户端检查点，不替代 PostgreSQL 业务事实。

2026-10-21 入库优先调整：视频封面与可选播放转码在共用 worker 中拆分，沿用既有 GENERATE_THUMBNAIL／GENERATE_PREVIEW、owner／模式／版本与租约；仅播放任务不阻塞封面可浏览状态。普通照片输入与 RAW 解码输出采用独立共用预算，不建立照片专属上传器。

## 2026-10-21 安卓备份

安卓为独立平台适配器，加载同一 Web 页面，原生目录访问、扫描与上传队列不替代共用图库或 API provider。内容预检作为共用上传 Controller 的新增方法，由 PHOTO 空继承同步获得；认证主体决定 owner、装配决定模式，返回值不暴露私密资源标识。格式和预算由 library-core 生成，安卓不维护第二套格式目录。既有新增基类方法契约自动覆盖该路由，不放宽门禁。测试与模拟器仅连接新建的本机测试工作台，禁止访问生产及群晖。
