# 后台受理与界面阻塞修复（2026年11月2日，本地候选）

用户要求耗时操作统一后台排队，不能因其他后台任务占用业务锁而卡住界面。本轮修复受理、执行与终态对账整条链路；未切换现用服务，运行版本以 `current-runtime.md` 为准。

## 修复范围

| 操作                                                                       | 受理与执行                                                   |
| -------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 批量／单项标签、评分、名称、说明、来源、颜色、隐私；标签及标签组管理       | 原操作队列的METADATA_COMMAND，同一批次发布事务               |
| 向量审核、扫描、重试、处理任务补齐和重试                                   | 原操作队列，独立执行器调用原业务能力                         |
| 人物改名、私密、合并、分配、审核、扫描；照片组创建、合并、移除、更新和扫描 | PHOTO显式注册领域处理器，复用共享队列与原业务事务            |
| 照片助手单项／整批审核、手动处理、撤销及发送                               | 后台调用原审核与发送journal，发布前后复核主体、权限和租约    |
| 查重扫描、清理、忽略与恢复忽略                                             | 扫描发现和清理计划生成移到后台；API不展开全库或等待业务锁    |
| 批量编辑成片                                                               | 一次持久受理，后台创建原媒体渲染任务；浏览器不再逐张渲染上传 |
| 旧删除／恢复入口                                                           | 返回原删除／恢复队列回执，避免兼容入口继续同步执行           |

读取、认证、暂停及处理设置等短控制操作继续即时返回。媒体解码、模型推理、对象移交仍由原专属工作边界执行；没有在API启动业务定时器或第二套执行器。

## 受理与正确性

API仅做非锁定的作用域读取、封闭命令检查、命令幂等锁和持久化通知。受理成功返回HTTP202和真实操作回执；数据库不可写时仍会明确失败，不能把“后台排队”理解为网络／数据库故障时也成功。后台等待图库锁期间，界面可关闭弹窗并继续选择、浏览或提交下一笔操作。

原operation/item表、领取、租约和 `publishMetadataBatch` 是唯一元数据发布编排。业务只在传入事务中执行规则。共享注册器不能反向导入PHOTO；摄影模块和独立执行器显式装配PHOTO处理器。未知命令、错误模式、跨owner及私密撤权均失败关闭。

连续提交评分和说明时，后笔只允许沿受理时确认的前序操作及其已提交版本回执继续，外部独立写入仍产生冲突。支持请求ID的入口只接受同ID同完整参数；批量成片等入口在响应丢失后可用原ID重试，不重复产生业务结果。媒体版本仍需匹配。

批量渲染的公共配方／LUT只在所属操作保存一份，渲染记录以owner／mode约束外键引用，worker读取时再验证；不按照片数重复保存多MB参数。未选中滤镜的目标保留原滤镜。旧浏览器成片／草稿缺少后台来源时，按去重滤镜ID补入可验证的preservedLuts参数表，每个操作只存一份；缺少数字表时明确失败，不悄悄替换为默认滤镜。操作完成表示原媒体任务已成功入队，成片是否完成继续由媒体任务进度表示，不把入队说成渲染完成。

取消须持久保存停止意图，与动态展开在同一操作行上串行化；取消后不得新建待执行子任务。重试失败项时才显式清除停止意图，已取消项保持取消；界面只重试失败项。已开始的原子发布仍按原事务边界完成或回滚；SEND已领取并开始复制的发送单元继续按原journal原子发布，停止排队只取消尚未开始的尾项。

## 界面与隐私

受理只登记操作，不清空草稿或伪造业务结果。终态按当前owner、模式和可见性重新读取受影响事实，合并全部已加载页、详情及组成员；分页、游标、滚动和无关草稿保持。照片组结构变化只替换原页组投影，不重排资源列表。

事实接口每次内部读取100项，前端自动续批，非用户数量配额。隐私相关操作终态先取消并清空对应PHOTO人物／人脸／审核／统计等旧可见性投影，再重读；活动观察者仍保留，403／404或暂时离线都不会继续显示旧私密信息。其他主体、模式、列表分页及不依赖可见性的草稿保持。任务中心继续显示真实失败、取消和重试结果。

## 资源与成本口径

没有增加产品操作数量限制，去掉原批量资源100／1000、照片助手审核200／手动100、照片组500等人工拆批约束。数据库按命名语句预算自动分批；元数据执行沿用现有批次及事务预算。请求体仍由 `EAGLE_OPERATION_BODY_LIMIT`（默认32MB）保护API解析内存，批量成片亦复用此边界；超过时明确413，调整同名环境变量。单张编辑原5MB边界保持，未提高媒体像素／内存或任务并发预算。

本机隔离PostgreSQL、合成数据，SQL含事务控制语句，非NAS、非生产p95：六万资源一次添加标签受理127SQL／1事务、约1.72秒；首个健康执行量子442SQL／2事务，零S3。这里没有将首个量子冒充六万项全部执行成本；内部自动续做，冲突拆分另有成本。测试同时约束完整六万项入队和公共LUT参数只存一份。

千组查重清理受理7SQL／1事务、约7–8毫秒，计划在后台原事务生成；准备47SQL／2事务，约175–194毫秒；千组执行32批、64事务，MATERIAL为1216SQL、PHOTO为1184SQL，均零S3。`operation-protocol-performance.test.mjs` 记录并约束准备和逐批成本，包含动态展开和发布的取消串行锁；没有声称后台计划生成消失或S3物理删除已包含在元数据成本内。扫描每份缺失当前预览仍需原一次S3读取；已存在当前指纹不重复读取原件。

每次写操作一次受理HTTP。批量粘贴未选中滤镜时，另有一次自动的批量只读上下文请求，仅返回缺少持久来源的去重滤镜ID，浏览器按需提供本地LUT；不逐资源请求配方，不上传整套本地LUT库。此只读预检每个内部数据库批次先读资源和当前配方两条SQL，存在自定义滤镜时再读一条来源投影，零写事务、零S3；来源投影不读取LUT字节。worker每份引用成片另有一次所属操作SQL，只投影实际滤镜的一张数字表，不把整个多滤镜参数表传入每个任务；实际原图读取、渲染与成片发布仍有原媒体任务成本。终态资源事实为 `ceil(受影响且已加载资源数/100)` 次HTTP，数据库投影复用原作用域读取，零S3；若照片组拓扑改变，另按已加载页数重读组投影。任务进度沿用原观察，不每次进度重放列表。PHOTO领域面板终态按实际已挂载查询合并失效；没有声称所有领域刷新均为固定一次SQL。

## 验收证据与边界

真实Chrome和独立Electron各覆盖PHOTO／MATERIAL：持有业务隐私锁时，标签、评分、说明与批量成片仍返回202；等待时工作区可选、弹窗可关，解除锁后正确发布，两笔连续元数据正确，原件哈希保持，页面异常为零。标签受理为50–175毫秒、批量成片350–815毫秒，均为小合成图库单次样本，不代表六万项受理耗时。可重复脚本为 `scripts/testing/background-queue-browser.mjs`，只连接隔离 `photo-workbench`。

真实数据库回归随 `test:library-integration` 进入原CI入口，覆盖业务锁等待、主体撤权、私密范围、租约接管、崩溃续行、冲突隔离、幂等、六万项入队、LUT共享和PHOTO领域入口。取消与动态展开须专门覆盖领取之后的竞争窗口，不能用取消未领取任务代替。

本轮新增操作协议、共享渲染参数及取消意图迁移；未来发布须API、operations、worker、网页和迁移配套，并执行最终API镜像验收。此文不授予发布权限，不表示已在用户图库执行或测量清理。
