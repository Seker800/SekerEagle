# 任务中心共用核心（本地重构候选）

本轮在独立分支 `codex/task-center-core` 实现，未部署生产，也没有修改现用模型或固定安卓图库。当前运行状态仍以 `current-runtime.md` 为准。

## 现在由谁决定

- 原来的任务表仍保存事实，没有新增一份中央任务队列。
- `library-core/task-engine` 决定等待条件和展示状态；`media-task-lifecycle` 负责媒体租约、完成、失败退避和恢复预算。分类与协议类型在 `task-scheduling`，依赖单向，不让展示模型反向参与执行。
- `library-persistence` 将共用守卫编译成 SQL，在取前 50 个候选之前筛选。候选缓存只保存提示；每次领取仍重新校验，并用租约版本 CAS 争抢执行权。
- API 适配各来源的事实，返回权威 `presentation`。网页只做筛选、选择、文案与操作，不重新设计状态顺序。旧 API 在升级过程中仍通过同一个共用核心解释。
- 群晖媒体和 Mac 向量继续使用独立的资源名额，资源池与既有优先级、公平轮次不变。统一管理规则不意味着串行执行所有任务。

## 媒体状态如何变化

| 触发                     | 守卫                                           | 结果                                           |
| ------------------------ | ---------------------------------------------- | ---------------------------------------------- |
| 领取                     | 到期 PENDING 或过期 PROCESSING；租约版本仍匹配 | PROCESSING，递增租约及尝试数，记录本次开始时间 |
| 成功发布                 | 固定 owner、模式、资源版本及 PROCESSING 租约   | 在原业务发布事务内完成任务与产物发布           |
| 可重试失败               | 当前执行租约仍匹配，未超预算                   | PENDING，指数退避                              |
| 永久错误或预算耗尽       | 当前执行租约仍匹配                             | FAILED，沿用原失败结算及依赖传播               |
| 模型离线、拥塞或传输等待 | 当前执行租约仍匹配                             | 回到等待，退还本次业务失败次数                 |
| 进程中断／租约过期       | 原租约过期，独立恢复预算未耗尽                 | 换新租约恢复；旧执行器不得迟到发布             |
| 连续中断恢复达到三次     | 再次需要回收过期租约                           | 明确失败并保留记录；人工重试重置恢复预算       |

恢复预算与图片失败次数独立，避免模型网络问题被当成坏图片。处理服务心跳失联时，尚未过期的租约也会明确显示等待服务，不把旧租约当作持续计算的证据。暂停是领取策略，已领取的步骤仍正常收尾，不直接把数据库中的运行事实改成“停止”。

## 界面和记录

默认显示当前任务。列表横向对齐类别、状态、排队、执行、失败和等待原因，类别下显示执行位置；选中后在详情区查看步骤、重试／暂停及最近转换。窄屏将详情放到列表下面，列表可横向滚动。沿用 App 主题，不增加假窗口装饰或没有数据来源的速度／预计时间。

已完成记录通过独立只读入口按需读取，不加入十秒轮询。完成数量是既有任务事实的累计数，不冒充“今天完成”或实时速率。

新增 `EagleMediaJobEvent` 只保存状态转换、租约、尝试、中断次数和时间，不保存文件名、原始错误或模型地址。数据库触发器保证所有既有媒体发布器、重试与失效操作在同一事务内留证；普通心跳不生成记录，事务回滚也回滚记录。它不是可调度队列。记录从迁移后开始，不伪造旧历史；源任务删除时级联清除，不作为永久审批审计。

最近记录只读取当前认证 owner、固定模式、当前媒体版本和允许访问的照片，最多 30 条。切换私密权限、模式或身份使用独立查询键；私密照片不会因已有缓存继续出现在公共视图。

## 本轮边界

媒体与向量首先接入共用执行转换和恢复预算；其他来源接入同一等待与展示决策，仍保留各自的领域事务和租约协议。上传由上传执行器处理，人工审批必须由人确认，历史导入不冒充正在运行的任务。没有新增 Agent 任意修改状态或绕过审批的权限。

后续扩展其他执行来源应提供事实和业务结果，复用共用守卫；不在页面或新适配器中再写一套优先规则，也不复制任务表。新增任务类型需同时验证领取、等待解释和恢复行为。

## 验收证据（2026-10-26）

- 真实 PostgreSQL 验证全部 1024 种等待守卫组合，SQL 的可运行判断与核心决策一致。
- 并发领取只成功一次，旧租约发布失败，回滚不留下转换，心跳不刷历史，重复中断有上限，人工重试重置恢复预算，重试编辑成片保持原照片可浏览。
- owner／模式／私密／媒体修订隔离、历史升级与完整数据库恢复验证通过。
- 5 万条合成积压下，12 次查询未经候选缓存约 7054 ms，使用缓存约 1702 ms；有界候选重新校验执行计划约 1.9 ms。此为本机调度证据，不能换算成生产推理吞吐。
- 真实 worker 验证：NAS 输入阻塞时，向量仍可完成，正常退出会等正在执行的 NAS 任务结束。
- 核心决策与执行转换单元覆盖：行 99.1%、分支 98.3%；桌面及 390 像素窄屏浏览器验证无页面错误和整页横向溢出。

发布须将迁移、API、worker、网页作为同一候选验证；本文件不代表上线授权。升级前备份按现用运行手册执行，不能只换网页或只换 worker。

## 第二轮逻辑与耦合复查

- 展示计算只读取任务事实。它不再读取上一次的展示结果，避免暂停改为继续后仍保留旧分区。消费端通过唯一 `resolveTaskPresentation` 尊重 API 的权威结果，旧服务端兼容也只在这一入口计算。
- Mac 需求由同一个 `taskNeedsModel` 描述。图片向量和语义文件夹的描述分析都会等待离线宿主，使用已有向量的文件夹匹配仍可继续；不能因模型离线把整个文件夹通道停掉。
- 到达恢复上限后返回明确的 `EXHAUSTED` 动作，不同时提供可领取的写入数据。失败结算同时校验租约版本和原过期时间界限；任务如果在检查后续上心跳，结算必须返回零条，不传播失败或改写资源状态。
- 失败命令改为具名参数，错误、永久性、时间及过期条件不依赖位置猜测。保留仍被操作队列复用的卡片样式，只删除确认无使用者的样式。

复查范围仍限于本地候选，不修改现用服务器、模型或固定测试图库；业务执行名额、顺序及审批权限没有变化。

第二轮验收：全量单元测试、lint、typecheck、build、格式检查、架构门禁和开源就绪检查均通过；真实 PostgreSQL 的隔离、历史升级、数据库恢复、5 万条积压调度以及双通道 worker 回归均通过。新增心跳竞态回归确认续租后不会被过期快照误判失败。核心决策与独立媒体生命周期合计覆盖率为行 97.37%、分支 97.66%、函数 96%，均超过 80% 门槛。

## 第三轮审计补齐

单次图片／文字请求断连不再把全局模型能力写成 OFFLINE。只有健康探针负责 READY／OFFLINE／DRIFTED；任务失败走自己的 availableAt 退避，其他可运行向量继续补位。HOST_BUSY／UPLOAD_TIMEOUT 为 1–30 秒，真实请求断连为 30 秒；均保留业务失败预算。智能文件夹复用同一请求退避分类，仍按自身失败时才递增的约定保留 attempts，不模拟一次虚假的领取增量。

容量等待通过 MODEL_BUSY 呈现为「等待模型空闲」，是任务等待原因，不是新的宿主健康枚举。只有截止时间仍在未来时才成立，过期后恢复可领取；不额外引入全局冷却锁。共用 mediaTaskFactsSql 定义依赖失败、依赖未完、待重试和容量等待事实，领取与概览均消费它；taskWaitReasonSql 在真实概览查询中使用，不再仅存在于测试。其他来源复用 taskBackoffFactsSql 提供退避事实。

历史仍按需读取当前可见资源的完成统计；查询成本会随完成量增长，尚未测得生产规模下的时延。本轮不新增汇总表、不自动删除历史；后续应先测量，再决定是否按权限及当前版本约束维护汇总。页面局部安排文案、各非媒体来源的租约统一和 Agent 调度命令仍是后续范围。

第三轮验收：全量单元测试、typecheck、build、lint、格式、架构和开源检查通过；最终文案与请求退避重构另经定向回归。真实 PostgreSQL 的 16 项任务中心测试通过，包含全部 2048 种守卫组合、依赖优先于繁忙、私密隔离与容量等待过期后的领取／展示一致性。真实 worker 在第一张请求断连后、第二次健康探针之前完成另一张向量，同时保持群晖输入阻塞和优雅退出验证；历史升级及完整数据库恢复通过。

五万条合成积压的 12 次调度测得未缓存约 9896 ms、缓存约 1785 ms，仍为两次发现和十二次有界校验；有界查询执行约 1.07 ms。不同轮次的绝对时间受测试机状态影响，本轮不是相对于生产的吞吐提升证明。修改的核心决策／SQL 编译／请求退避模块行覆盖率均为 100%，分支分别为 97.09%／100%／94.44%。没有访问生产、真实模型或固定测试图库。

## 剩余建议的价值判断与收尾

本轮用户要求先判断是否值得修改，而不是机械完成审计清单。修复历史表格缺完成数；历史模式只展示完成数量，去掉其无意义的运行／排队／失败零列。暂停、重试能力和执行安排由 taskGroupManagement 统一计算，API 提供权威 management；模型警告由 taskOverviewModelIssue 提供，页面只合并两库的警告结果。旧 API 仍复用核心入口，不另写兼容规则。

增加最近活动时间：聚合已通过 owner／模式／私密／当前版本过滤的任务源更新时间；一般来源使用 updatedAt，地图使用 dirtyAt，审批使用 reviewedAt／createdAt。反映状态修改或心跳活动，不表示每一项都在推进，也不把普通任务写入当成一次新的状态转换。界面只在有事实时显示，不为旧响应补造时间。

十万资源、五十万完成任务的独立 PostgreSQL 实验：公开查询返回 450,000 条完成量，四次耗时 523／500／486／483 ms；含私密返回 500,000，耗时 521／539／529／510 ms。测量的是本地候选查询，不是群晖实测，也不保证更大规模时延。历史已脱离十秒轮询，当前没有足够收益支持新增汇总表、失效维护或自动删除策略；保留按需真实聚合。原始合成证据在本地 .omx/artifacts/task-history-benchmark.json。

不实施的项目及理由：

- 执行者身份：现有任务没有绑定执行器实例；把全局心跳中的某台机器套到某个任务上会伪造归属。当前单 worker 与两个资源通道无需为显示随机实例号扩展数据库；本轮先用真实活动与转换记录解决停滞可见性。若将来支持多 worker 接管，再在领取事务中持久绑定实例并记录转换，而不是猜测。
- 非媒体租约字段：lockedAt 是最近续租时间，lockedUntil／leaseUntil 是到期时间，名称差异对应真实语义；已有 fencing 与各领域发布事务。仅为统一字段重写会扩大迁移和回归面，没有已证实的行为收益。本轮不改存储协议。
- Agent 调度命令：这是新增授权能力，并非当前调度缺陷。固定优先级、公平轮次和人工暂停已经解决当前安排；没有具体干预用例证明 Agent 改写调度带来收益。本轮不扩张 PAT 或审批权限，不提供任意改状态的入口。

最终候选复测（包含最近活动聚合）：同一十万资源／五十万完成任务规模，公开查询四次为 547／508／509／493 ms，含私密为 533／523／531／636 ms；完成数量仍为 450,000／500,000。这个按需成本仍不足以支持本轮增加汇总表，后续生产若有明确慢查询证据再评估。

本轮验收：全量单元测试、typecheck、build、lint、架构、格式和开源检查通过；最终界面改动另经网页类型检查、构建和 36 项定向回归。真实 PostgreSQL 17 项任务中心、114 项既有业务隔离、13 项操作队列、7 项调度专项、真实 worker 双通道与历史升级／完整恢复均通过。最近活动新增跨 owner／模式／私密／旧媒体版本隔离回归；已完成审批不再误显示为「待审批 0」。核心任务决策模块行覆盖率 99.13%、分支 97.92%。仅独立分支本地候选，未 push 或部署生产。
