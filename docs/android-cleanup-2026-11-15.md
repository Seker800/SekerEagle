# 安卓释放空间分批与时间筛选（2026-11-15）

## 现场问题

用户第二次“释放空间”时界面长时间停在“正在检查/正在核对”，扫描完成显示约 13GB 后点击又提示“检查结果已过期”；同时感觉有 500 项和 10GB 两个上限。只读检查结论：

- **500 是计划硬上限**：`CleanupScreen` 在 `entries.size() >= 500` 后不再加入计划，扫描仍继续枚举整个媒体库；释放完成后计划被清空，下一次必须重新全量检查。没有 10GB 常量；13GB 正好是 500 项约 26MB/项的结果，码率更大的批次会更大。
- **每个文件整份重读并重算 SHA-256**：`CleanupEngine.check()` 调 `file.hash.read()`；每个文件还单独发一次 `POST /uploads/check-content`。扫描和删除前复核各做一次，SAF 文档在真正删除前再做第三次。
- **60 秒计划过期**：`activate()` / `prepareDeletion()` 检查 `now - plannedAt > 60_000`，超过就清空计划；切换标签页的 `onDetachedFromWindow()` 也会清空。慢扫描之后用户很难在 60 秒内完成确认，所以出现“13GB 可释放但一点就过期”。

按 500 个、约 13GB 估算，旧实现是约 26GB 读盘/哈希、约 1,000 次 HTTP 请求、数千次游标查询；6 万张图库需要重复 120 轮。

## 新交互

1. **检查一次，保留计划**：扫描一次后把全部符合条件（已确认备份、文件 size/mtime 未变、服务器仍有副本、可写、时间筛选）的文件保存在内存中的 `CleanupSession`；切换标签页返回仍可继续，不再有 60 秒过期。
2. **时间筛选**：释放范围可选“全部 / 7 天前 / 20 天前 / 30 天前 / 90 天前”，按文件日期（`date_modified`/`last_modified`）筛选，日期未知的文件在启用筛选时保留。选择变化会清空旧计划并提示重新检查，不会偷偷沿用旧结果。
3. **分批释放、自动继续**：计划不再有 500 项总上限；删除按每批最多 500 项或 10GB（十进制，取先到者）切分。每批系统确认完成后保留剩余计划，按钮变成“继续释放剩余 N 个”，不需要重新扫描。500 只是每批大小，不是总量。
4. **删除前轻量复核**：每批只做已确认收据 + 文件 size/mtime/可写检查，并用一次批量接口确认服务器副本；不再重读原文件。变化的项目从计划中跳过并提示，不再让整批失败。
5. **进度与取消**：检查时显示已扫描/已确认数量，服务器确认显示进度；释放时显示本批数量与容量、剩余数量与容量。忙碌时提供“取消本次操作”，取消扫描不保留半成品，取消批次保留计划。

## 校验模型

- 默认使用备份台账中 **已确认** 的收据哈希（`confirmed` + 64 位哈希）作为内容标识；清理时只复核文件当前 size/mtime 未变（`BackupEngine.Stable`）和服务器仍返回该副本。
- 不再在清理时重读整文件；这是速度提升的关键。原来的严格 `CleanupEngine.check()`（整文件哈希 + 单文件远端确认）保留给需要强校验的其他调用，清理页面改用新的 `local()` + 批量确认。
- 服务端新增 `POST /api/{photos,eagle}/uploads/check-content-batch`，每批最多 500 个 `{sha256,size}`；一条 SQL 使用行值 `IN` 查询，owner 由认证主体推导，模式、删除/回收、私密过滤与单文件接口一致；返回与输入顺序一致的布尔数组。
- 单文件 `check-content` 保持不变，旧客户端和其他插件不受影响；服务端可先于新安卓客户端部署。

## 验证

- 安卓 JVM：新增 `CleanupPolicyTest`（时间边界、未知日期、项数/字节分批、超大单项）与 `CleanupEngineTest.local`（不读取原文件、缺收据/文件变化拒绝），全部通过。
- API：`EagleUploadService.checkContentBatch` 单测通过；真实 PostgreSQL 测试验证 owner/模式/size/私密与 500 条批量结果一致；已注册进 `test:library-integration`。
- 未执行：安卓实机/模拟器交互回归、系统删除对话框的 500 项/10GB 分批观察、生产部署。

## 限制与后续

- 时间筛选目前按文件日期，不读取 EXIF 拍摄时间；相机原片的文件日期通常接近拍摄时间，编辑/下载过的文件会更接近最后修改时间。若坚持按拍摄日期，需要在媒体查询中单独取 `DATE_TAKEN` 并处理无值的情况。
- 系统删除对话框仍是每批一次用户确认；这是 Android scoped storage 的安全要求，不能后台静默删除媒体。批量大小取 500/10GB 是当前设备验证过的安全值。
- 计划只保存在当前 Activity 进程内，应用被杀后需要重新检查；重新检查已是一遍轻量扫描。
