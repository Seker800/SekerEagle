# 页面读取效率优化（2026年11月1日）

> 后续发布：2026-11-01 用户授权后，本文候选已随固定源码 df6d3688305a 配套上线；生产版本、成品验收、两端检查、保护与回退见[效率生产发布](production-efficiency-release-2026-11-01.md)。下文的“本地候选／未部署”保留为实施阶段记录，不表示最新运行状态。

本轮按用户要求以最新代码为基线，目标是减少打开人物、统计和智能文件夹时的等待。起点为 `52d12023`，本地分支为 `codex/read-path-efficiency`。线上旧版本的响应时间不作为本轮前后对照；本轮没有生产部署、迁移、模型或处理策略调整。

## 实现与边界

- 人物目录仍按已命名优先、不同照片数、人物ID进行准确排序和分页。移除为所有人物构造有序人脸数组的步骤；选出25项（24项展示与一个续页哨兵）后，再在同一SQL中以LATERAL为每项取一张代表人脸。复用已有索引，私密标记、无可见照片的私密人物、媒体版本、重复人脸和回收状态保持原规则。没有缓存计数，也没有新表。
- 统计先按日期、相机、镜头及设备身份汇总频数，再物化图表输入；镜头JSON身份在聚合之后构造。总数、未知日期、设备排行、其他设备桶和日／周／月／年图表都按频数求和。全库设备选项仍从可见全库生成，不错误收缩为当前日期或设备筛选的结果。每次查询重新读取当前事实，不增加缓存过期窗口。
- 智能文件夹将完整过滤树通过原 `colorSearchPlan`／`compileSearchPredicate` 编译到排名SQL内，避免先取250项再在卡片读取时淘汰。正常只领取当页加一项，卡片仍用原读取及序列化再次校验；并发变更造成缺项时保留补齐循环。颜色计划允许没有颜色叶子的合法筛选；不是另写一套规则解释器。父子文件夹的混合普通成员、相关度与同分顺序、快照切换、游标和照片堆叠保持原协议。

没有修改网页组件、前端缓存TTL、选择、滚动或刷新协议，没有引入独立统计服务、缓存表、队列、产品数量限制或全局数据库参数。

## 对照与完整成本

本机Docker tmpfs PostgreSQL16／pgvector、六万份合成照片；存储为测试适配器，未请求真实模型或用户对象。基线源码固定为 `52d12023`，对照使用相同数据库和事实，六次交替运行并核对完整返回值相等。下表中位数按两个中间样本的均值，取整到毫秒；是暖缓存的查询调用样本，不是HTTP、NAS、冷缓存或p95。

| 场景                                      | 基线        | 当前        | 可确认的收益                                                     |
| ----------------------------------------- | ----------- | ----------- | ---------------------------------------------------------------- |
| 六万份同日同设备统计                      | 139ms       | 50ms        | 物化的图表输入60000行降到1行                                     |
| 六万份跨2190日、多设备统计                | 183ms       | 105ms       | 完整结果相等，日期和设备聚合后减少后续物化与遍历                 |
| 1000人物、每人10份照片的目录              | 75ms        | 75ms        | 代表头像仅为25项选择；没有测得明显总耗时改善，不申报页面提速倍率 |
| 1000份语义候选、后200份满足评分、首屏10份 | 4轮排名查询 | 1轮排名查询 | 不再重复读取并淘汰前面的250项候选；200份结果完整分页且顺序相等   |

统计仍为一次SQL、零显式事务、零S3、一次前端GET；所需基础资源／摄影事实的全库读取没有消失，只减少其后重复工作。不同日期与设备组合接近照片数时，压缩收益会降低，不能把60000→1推广到任意图库。

人物目录的排名及代表选择仍为一次SQL，原RepeatableRead事务和当前页Prisma投影保持；后者可拆为多个关系SQL，因此不将整个HTTP请求称为一条SQL。S3直接请求零，头像由浏览器按原逻辑读取；前端一次目录GET，翻页仍只追加新页。准确全局照片数计数仍需读取可见人脸和资源，故本轮不承诺人物页首次打开的等待已全部消除。

智能文件夹的正常排名SQL从与拒绝候选轮数相关，降为每页一次；卡片投影也从多轮候选投影降为一次当页投影。快照读取、文件夹与子级读取、实况与照片堆叠追加查询仍存在，混合普通成员在必要时还有一次补读；并发失效时可能增加轮次，不能将整个请求称为一条SQL。无新增事务、模型或S3直接请求，前端仍一次列表GET，不重放已加载页。

## 回归与验收

RED `1b75b4f8` 在真实数据库复现三个成本问题。GREEN `cce2cd6a` 的专项验证通过：统计六万输入压缩、人物两页无重叠、代表头像只处理25项、私密／版本／回收／重复人脸、无照片私密人物、跨主体、游标隔离、智能文件夹稀疏筛选和200项完整分页。

`read-path-performance.test.mjs` 已接入原 `test:library-integration` 串行套件，以实际中间行数、代表选择次数和排名次数约束成本，未以固定毫秒阈值替代资源验证。统计原真实数据库专项通过，覆盖日历、设备交集、未知信息、私密／主体／模式／旧版本与镜头身份；智能文件夹原专项通过，覆盖混合树、原子切换、内容预览、增量、租约和实际worker。

原智能文件夹专项的竞态夹具在此前空间切换后没有恢复当前空间，导致旧快照未激活即进入竞态测试。本轮显式恢复该夹具空间，并增加竞态前快照确已激活的断言，保留原切换与旧意图不得复活的检查；没有放宽业务守卫。

大库夹具准备期间的字段／版本／向量形状修正及一次主动取消的自有测试清理属于夹具失败，不冒充业务RED。后续夹具先准备统计信息，再创建关联事实；清理先删除所属子记录再删除合成资源，不连接或清理现用图库。
