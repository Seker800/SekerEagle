## 2026-11-01 原图重复副本核验（待最终镜像与生产验收）

整文件 SHA 无法识别仅 EXIF／容器元数据不同的备份。当前真实 PHOTO 库只读快照 63186 项、整文件重复零；缩略图指纹完全一致有1217组，最多五份，但这不是删除证据。抽取三组14份原件，存储哈希全部正确、各组分别4／5／5个不同文件哈希且完整定向解码像素各仅一个哈希。只读下载副本在诊断结束后删除；真实资源不清理。

候选发现沿用缩略图指纹；近似匹配与平坦同指纹桶只决定核验范围，不决定清理。首次检查每个缺失缩略图一个S3 GET，每16项一个持久批次、两路小图计算。候选原件每份一个GET、一次流式临时文件写入并校验SHA；只顺序解码一份原件，完整像素直接输入摘要、不收集输出数组、不读取语义向量。原件核验每四项一个队列批次，一次领域读取与一次集合UPDATE／完成事务，认证及租约领取／续租／进度统计沿用共用执行器；最终一次投影发布事务。阶段展开按500项createMany，缓存查询也按500项，属于内部摊销，不是用户选择上限。已有正确原图证据再次检查不读取原件。列表仍≤12条SQL、一个只读事务、零S3；全选清理一次POST，清理仍每组一个原回收事务、零S3，不回放主图库已加载分页。真实端到端SQL数和耗时以本轮验收记录为准，不把上述领域语句数冒充完整执行器成本。

资源预算与到顶行为：`EAGLE_DUPLICATE_ORIGINAL_MAX_BYTES`默认512MiB，限制单份临时原件磁盘写入，超限为可重试错误、不生成证据；`EAGLE_DUPLICATE_ORIGINAL_MAX_PIXELS`默认6500万，保护Sharp原生解码与RGBA输出内存，超过时计入未核验且不允许画面相同清理；`EAGLE_DUPLICATE_ORIGINAL_TIMEOUT_MS`默认120000，防止挂起的对象读取／核验占据唯一名额，超时失败可重试。单帧八位JPEG／PNG之外返回不支持，仍允许整文件哈希查重。`EAGLE_OPERATION_MEMORY_LIMIT`默认768MiB，为原512MiB执行器的原图单解码留空间；不得提高解码并发来追求进度。Mac合成6021万像素JPEG核验139ms／单进程峰值369MiB，只证明本机像素预算可运行，不冒充NAS吞吐；现用执行器约306MiB，故须再做最终镜像内存验证。NAS只读现场可用约5053MiB，调整仅执行器上限，不修改PG、用户暂停、模型或其他服务。

## 2026-10-31 相似人物分轮排序（本地候选）

每次读取一批锚点并分别获取本轮两个近邻；游标在锚点遍历结束后自动进入下一轮，因此不是人物或操作数量限制。一次请求以一个只读事务执行语句超时设置、候选查询、最多一次证据查询和一次人物及其预览的 Prisma 读取（后者可能拆成多条 SQL）；该 API 不访问 S3、不写入业务数据，前端只在批次耗尽时发下一次请求。显示当前配对需读取两张预览，是否命中浏览器缓存由运行时决定。用户确认本身沿用已有写事务和刷新，未做整库逐页预加载。实库约 2900 个人物的最终候选 SQL 一次只读采样返回 16 组、耗时 2.37 秒；仅候选 SQL、单次采样且不含网络、证据和页面渲染，不是 p95 或完整请求时间。全部轮次随人物数增长而增加请求与计算，不能将此采样当全库遍历耗时保证。

> 目的：防止「每一层都合理、合起来不可用」。批量操作、后台任务、进度刷新、跨库复制类改动，都必须能回答一条数据和一个批次的端到端成本。
> 本文的数字是**评审用的建议值**，owner 可以直接调整；调整时在文末记录原因和日期。它约束的是「不要出现局部最优、整体灾难」，不是把每个数字变成不可改的硬门禁。

## 1. 计数单位

- **SQL 语句数**：按一条 / 一张 / 一批统计，不用「大概很快」代替。
- **S3 请求数**：HEAD、COPY、GET、PUT 分开统计。
- **事务数与持锁时间**：尤其是 privacy advisory lock、行锁。
- **前端请求数与上下文**：是否重置分页/滚动/选择。
- **墙钟时间**：p50 / p95，注明数据规模和 MinIO 位置。

## 3. 怎么测量（只读）

1. **S3**：MinIO 的 `minio_http_requests_total`（按 method/API），或 `mc admin trace`（若本机有 `mc`）；统计一次发送的 HEAD/COPY 次数，与「对象数 × 2」对照。
2. **SQL**：Prisma 查询日志或 `pg_stat_statements`；按 operation/asset 过滤，统计单张语句数与耗时。
3. **墙钟**：浏览器或 `curl -w '%{time_total}'`；发 1 张、10 张、100 张，记录数据规模与图片像素。
4. **前端**：Network 面板看 assets/operations 请求频率；检查缓存 `pages` 是否被截成 1、滚动是否跳。
5. **锁**：发送时 `pg_stat_activity` 看 `wait_event='advisory'` 和事务时长。

## 4. 评审要求

- 涉及批量/后台/进度的 PR，描述里写一条「成本追踪」：单张 SQL、S3、事务数；一批的总量和墙钟估算。
- 超过预算时，二选一：优化，或在本文更新预算并写明测量数据与取舍；不能只把超时调大。
- 新上限按 `docs/product-frame.md` 的规则写清「防谁、到顶 UX、env 开关」。
- 不能用「代码看起来是 O(1)」代替实测；也不能用单张小图代替高像素样本。

## 5. 当前已知基线（2026-10-31 复核）

- 单张照片金字塔 74–355 个 tile（1200 万–6100 万像素），每 tile 3 次 S3；加原图/预览约 230–1073 次。
- 发布事务里 `transferFactIncludes` 约 18 条关系查询，逐标签 `findUnique`/`upsert`；单张约 20–100 条 SQL。
- SEND 通道在 `af2c7384` 基线一次只领 1 张；照片之间串行，4 路并发只在单张内部。
- 前端每发布一张把列表 pages 截成 1 并整页重拉（约 4 秒一次）；operations 每 1.5 秒轮询。

## 2026-10-31 删除结果自动同步修订

用户明确否定“后台完成后手动加载更新”。两个模式共用原查询缓存，删除、恢复、清空和发送成功发布后自动重取当前活跃查询，保留读取中的全部旧页、卡片及滚动；未打开的查询只失效，返回时再更新。服务端部分失败时以真实列表结果为准，不能按入队选择把失败项一起隐藏。

成本：原操作入队、领取与发布的SQL、事务、S3成本不变；本次前端不直接新增写事务或S3操作。每轮列表读取最多为当前已加载P页各一次GET（后续游标按新结果重建，避免删除造成分页缺口），另有当前活跃计数／关系查询各一次；并非一张删除一轮。一次状态响应合并同模式进度，中间发布每模式至多10秒启动一轮，整批结束立即同步；在途读取不取消，期间新发布合并成随后一轮，保证最终事实不漏。没有打开的历史筛选不发请求。大量已加载页仍有P次读取成本，本轮未引入服务端增量协议，不能声称常数成本或实测大库延迟；不得以截成第一页或要求手动刷新规避成本。

## 2026-10-31 即时删除与撤销候选（未发布）

本轮用户要求暂不推送生产。删除主图库采用一次意图投影及一次终态回执应用，终态不再重新读取P页资产。回执按原SQL批次配置分页（默认512个操作项、自动继续）；每页一次作用域操作读取、一次状态聚合、一次回执读取，另按同一内部SQL批次读取当前资源成员状态（包括失败、跳过和已不存在的项），无S3请求，不返回描述、对象键或人脸／EXIF。当前活跃计数、标签与查重结果按同轮终态合并校准；恢复或发送目标最多补读当前列表首窗口并合并旧页，不丢页或旧游标。查重列表仍须按同一个新revision重建已加载组分页，成本与主图库局部更新分别记录，不能冒充全系统常数请求。

撤销准入为短事务：权限读取与幂等关系复用、取消未领取项并登记一个恢复控制项；实际资源恢复留在独立进程，按既有元数据批次执行，无直接对象存储I/O。控制项按源已提交事实原子替换，失败、跳过、取消项不恢复；版本变化单独失败。显式外键防跨owner／模式补偿，唯一关系防重复撤销。新增迁移仅增加可空关系、唯一索引、作用域外键及动作CHECK，现用生产尚未迁移。

隔离六万选择诊断复现：重复IN批次在未分析的新图库选择了低估owner范围的通用预备计划，原120秒准入预算耗尽；禁用JIT没有改善。保持相同数据、批次和120秒预算，仅事务级值相关计划的对照为8.442秒、478条SQL、0次存储复制（另含一个诊断SET语句），不是生产p95。候选对超过内部SQL批次的选择采用SET LOCAL plan_cache_mode=force_custom_plan，不改变全局规划器、权限或用户数量；最终未插入诊断包装器的回归另行记录。

最终无诊断包装器的隔离回归：六万项一次入队8.787秒／479条SQL／0次S3复制（另一次并行构建期间为11.493秒）。这是本机合成数据单次结果，不是NAS或生产p95。六万库查重首屏176.998毫秒／12条SQL，100组清理准入14条SQL／0次对象读取，既有预算未放宽。测试以同一数据库串行执行隔离夹具，Prisma查询事件在测量前后排空，避免上一阶段异步日志污染SQL计数。

独立operations新增一条PostgreSQL LISTEN连接，API没有监听、后台执行或轮询定时器。每次入队、重试、撤销与查重准入在原事务内多一个固定通知SQL；通知仅含模式，提交后唤醒对应执行器。断线保留原5秒恢复轮询并重连，不丢意图。`EAGLE_OPERATION_WAKEUP_CONNECT_TIMEOUT_MS`默认3000毫秒，限制连接占用启动等待；到顶后继续原轮询并重连。`EAGLE_OPERATION_WAKEUP_RETRY_MAX_MS`默认30000毫秒，限制失败重连频率占用；到顶按此间隔重试，任务继续由原轮询发现。两项均可用同名环境变量调整，不改变用户选择数量。
