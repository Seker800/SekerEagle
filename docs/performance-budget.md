## 2026-11-01 推荐审核模型隔离与批量发布（本地候选）

已有推荐是数据库中的人工审核事实，不依赖模型在线。侧栏改用仅含未分类数量与待审数量的 `review-summary`：每次读取2条计数SQL、零事务、零S3、零模型请求。取消侧栏和推荐列表的10秒定时轮询；进入审核／待分类、窗口重新可见及相关修改完成后按需读取。模型与队列全量概览仅由处理设置页使用。标签统计读取失败不能禁用已保存的推荐卡片，首次计数失败显示未知，不以0冒充空库；网关错误使用普通请求失败文案。

人工批量确认与拒绝共用 `reviewSavedSuggestions`，一批一个原事务，复用原owner／mode／私密守卫及隐私发布原语。确认读取保存的快照距离，不重算向量；人工标签关联保留来源和建议ID。媒体版本、当前嵌入／中心和参与推荐开关失效时整批回滚；重复同动作请求返回既有结果，反向动作冲突。原先逐条事务可能在网关超时前提交部分结果，本实现不再产生这种半批结果。

隔离loopback PostgreSQL的40项确认实测：MATERIAL 16条SQL、1事务、20.64毫秒；PHOTO 15条SQL、1事务、18.60毫秒，SQL包含BEGIN／COMMIT，S3和模型请求均为0。拒绝实测单测约束为整批1事务、1次状态更新，读取关系SQL另计。未提高事务时限或增加选择上限；历史DTO的100项限制不是本次新增，不能据此声称无限大选择性能。前端每次审核后重取当前建议和标签各1次，拒绝另失效侧栏轻量计数；确认沿用关系缓存失效，其中含计数，其他活跃关系查询各按原规则刷新，不截断资源分页。上述耗时为本机合成数据，不是NAS或p95。

验证：双模式30k历史建议索引回归、模型完全不可用、40项原子确认、跨owner／模式404、过期媒体版本整批回滚、审计关联、私密传播、同动作重复／并发、反向动作冲突通过；审核发布模块覆盖率100%行／92.11%分支／100%函数。网页195项相关测试、完整lint／typecheck／build通过。全仓单测已运行，架构测试因工作区其他读取缓存源码依赖摄影扩展失败；全库集成在两张其他新增表缺少模式不可变触发器处失败，本次专属真实数据库回归独立通过。不据此宣称全仓门禁通过。本次无生产部署、迁移、模型重启、处理策略变更或真实推荐写入。

## 2026-11-01 原图重复副本核验（已上线，首次完整核验已完成）

最终镜像、生产网页／真实桌面路径已通过，证据、真实首轮状态与成本见[严格重复副本验收](duplicate-originals-2026-11-01.md)。像素核验的首次成本不可用缩略图耗时代替；复查复用当前媒体证据。本轮60072项非私密范围检查完成，确认1235组／2184份冗余，首轮3012秒；最终实库复查9.734秒、build／publish两步、原图及缩略图读取任务零，结果保持1235组／2184份；单次后台观测含一秒进度轮询，不是HTTP或界面p95。后续实时任务状态从任务中心读取。

候选发现沿用缩略图指纹；近似匹配与平坦同指纹桶只决定核验范围，不决定清理。首次检查每个缺失缩略图一个S3 GET，每16项一个持久批次、两路小图计算。候选原件每份一个GET、一次流式临时文件写入并校验SHA；只顺序解码一份原件，完整像素直接输入摘要、不收集输出数组、不读取语义向量。原件核验每四项一个队列批次，一次领域读取与一次集合UPDATE／完成事务，认证及租约领取／续租／进度统计沿用共用执行器；最终一次投影发布事务。阶段展开按500项createMany，缓存查询也按500项，属于内部摊销，不是用户选择上限。已有正确原图证据再次检查不读取原件；已证明PIXEL_LIMIT且当前元数据仍超过当前预算的候选同样复用排除证据，提高预算时才重新读取。列表仍≤12条SQL、一个只读事务、零S3；全选清理一次POST，清理仍每组一个原回收事务、零S3，不回放主图库已加载分页。真实端到端SQL数和耗时以本轮验收记录为准，不把上述领域语句数冒充完整执行器成本。

资源预算与到顶行为：`EAGLE_DUPLICATE_ORIGINAL_MAX_BYTES`默认512MiB，限制单份临时原件磁盘写入，超限为可重试错误、不生成证据；`EAGLE_DUPLICATE_ORIGINAL_MAX_PIXELS`默认6500万，保护Sharp原生解码与RGBA输出内存，超过时计入未核验且不允许画面相同清理；`EAGLE_DUPLICATE_ORIGINAL_TIMEOUT_MS`默认120000，防止挂起的对象读取／核验占据唯一名额，超时失败可重试。单帧八位JPEG／PNG之外返回不支持，仍允许整文件哈希查重。`EAGLE_OPERATION_MEMORY_LIMIT`默认768MiB，为原512MiB执行器的原图单解码留空间；不得提高解码并发来追求进度。最终NAS镜像60217344像素复杂JPEG核验1.222秒／单进程峰值438.2MiB；Linux镜像254MB RGBA噪声PNG为5.851秒／417MiB，真实扫描执行器内存样本568.7MiB，均不是实库p95。调整仅执行器上限，不修改PG、用户暂停、模型或其他服务。

## 2026-10-31 相似人物分轮排序（本地候选）

每次读取一批锚点并分别获取本轮两个近邻；游标在锚点遍历结束后自动进入下一轮，因此不是人物或操作数量限制。一次请求以一个只读事务执行语句超时设置、候选查询、最多一次证据查询和一次人物及其预览的 Prisma 读取（后者可能拆成多条 SQL）；该 API 不访问 S3、不写入业务数据，前端只在批次耗尽时发下一次请求。显示当前配对需读取两张预览，是否命中浏览器缓存由运行时决定。用户确认本身沿用已有写事务和刷新，未做整库逐页预加载。实库约 2900 个人物的最终候选 SQL 一次只读采样返回 16 组、耗时 2.37 秒；仅候选 SQL、单次采样且不含网络、证据和页面渲染，不是 p95 或完整请求时间。全部轮次随人物数增长而增加请求与计算，不能将此采样当全库遍历耗时保证。

> 目的：防止「每一层都合理、合起来不可用」。批量操作、后台任务、进度刷新、跨库复制类改动，都必须能回答一条数据和一个批次的端到端成本。

## 3. 怎么测量（只读）

1. **S3**：MinIO 的 `minio_http_requests_total`（按 method/API），或 `mc admin trace`（若本机有 `mc`）；统计一次发送的 HEAD/COPY 次数，与「对象数 × 2」对照。
2. **SQL**：Prisma 查询日志或 `pg_stat_statements`；按 operation/asset 过滤，统计单张语句数与耗时。
3. **墙钟**：浏览器或 `curl -w '%{time_total}'`；发 1 张、10 张、100 张，记录数据规模与图片像素。
4. **前端**：Network 面板看 assets/operations 请求频率；检查缓存 `pages` 是否被截成 1、滚动是否跳。
5. **锁**：发送时 `pg_stat_activity` 看 `wait_event='advisory'` 和事务时长。

## 2026-10-31 删除结果自动同步修订

用户明确否定“后台完成后手动加载更新”。两个模式共用原查询缓存，删除、恢复、清空和发送成功发布后自动重取当前活跃查询，保留读取中的全部旧页、卡片及滚动；未打开的查询只失效，返回时再更新。服务端部分失败时以真实列表结果为准，不能按入队选择把失败项一起隐藏。

成本：原操作入队、领取与发布的SQL、事务、S3成本不变；本次前端不直接新增写事务或S3操作。每轮列表读取最多为当前已加载P页各一次GET（后续游标按新结果重建，避免删除造成分页缺口），另有当前活跃计数／关系查询各一次；并非一张删除一轮。一次状态响应合并同模式进度，中间发布每模式至多10秒启动一轮，整批结束立即同步；在途读取不取消，期间新发布合并成随后一轮，保证最终事实不漏。没有打开的历史筛选不发请求。大量已加载页仍有P次读取成本，本轮未引入服务端增量协议，不能声称常数成本或实测大库延迟；不得以截成第一页或要求手动刷新规避成本。
