## 提交交接与权限

原事务在语句级 PostgreSQL NOTIFY 中交接 owner、模式、能力及公开可见性，不携带资源内容、对象键、数量或模型输入。API 只有一个 LISTEN 连接及可丢弃的内存标记；没有新增修订表、每资源修订写入或独立业务事务。回滚不通知，晚提交仍能发现；断联返回 503、保留界面，重连 LISTEN 注册完成后更换 epoch，覆盖断联期间的提交。

认证主体决定 owner；素材／照片的私密授权分别验证原签名 cookie。公开与含私密标记独立递增，私密资源／分组修改不推动公开标记。资源、标签、人物、位置、目录、推荐、队列、设置及 Agent 各自的原表仍拥有事实。地图构建租约仅为含私密范围的进度提示；公开源变化启动原地图观察，观察到终态后停止，不能把构建租约当公开照片变化。

通知只是失效提示，原 HTTP API 仍校验 owner、模式、私密权限和当前版本。计数丢失通过 epoch 校准恢复，不用事件序号或时间戳当事务提交水位。语句交接字段排除心跳／租约及大向量，媒体正向领取保留原全局 NOTIFY 锁争用豁免，不能因展示刷新重新串行化领取事务。

## 后台执行

独立 operations 复用现有通知及持久队列，恢复检查完成后才排下一轮。空闲退避到 30 秒；通知到来立即唤醒，积压按原车道连续处理。`EAGLE_OPERATION_POLL_MS` 是原恢复基准；显式配置慢于 30 秒时保留该配置，不把恢复时效参数变成用户数量限制。默认基准 1000 毫秒，空闲间隔依次增加到 30000 毫秒。

业务 worker 的地图／目录变更接入原通知与调度器，移除额外 15 秒地图唤醒；语义目录空闲恢复由 5 秒改为 30 秒，有剩余提交工作仍及时继续。心跳、续租、用户暂停、时间窗口、版本及租约恢复保持原职责。模型调度器自身健康检查不在本次“页面零模型请求”的承诺内。

## 已取得的测量

证据在本任务工作区 `.omx/artifacts/refresh-efficiency-20261101/`。记录不含 cookie、令牌或凭据。

- 优化前线上展开处理详情、向量标签未激活的连续 600 秒：网页向量 summary **61 次**、处理 jobs **60 次**、处理 summary **60 次**；两模式任务中心另有 **53／45 次**。旧 summary 每次约 10 条业务 SQL 加一次模型探测，是源码逐项计数；网关日志不能直接测 SQL 或模型次数，不能把推算称为独立实测。
- 优化前网页空闲 600 秒：时间轴 **20 次**、文件夹 **10 次**、两模式 operations 各 **10 次**、会话 **10 次**。当时线上有颜色后台工作，数据库全客户端增量包含该工作，不能归因给页面。
- 优化前桌面样本期间用户正在编辑；只能保留原始分类，不作为干净空闲对照。首次网页后台样本由调试标签取得，条件不充分，不能作为隐藏通过证据。
- 优化后六万项隔离图库，Chrome 与真实 Electron 各连续空闲 600 秒：每端共用 changes **10 次**、会话 **10 次**；完整列表、时间轴、人物、地图、向量概览等定时重读 **0 次**。六万项是实际合成数据库行，不声称六万份真实照片或模型／S3吞吐。
- 独立测试 Electron 最小化 600 秒：所有请求 **0 次**；使用独立应用 profile，没有操作用户日常桌面窗口。
- 六万项隔离库中的原 512 项 SQL 批次：无本次通知的 UPDATE **69.745 ms**，带通知 **80.665 ms**，其中语句通知 **13.451 ms／1 次**。单项通知 **0.721 ms／1 次**。这是本机交替样本，缓存冷热不同，不能由 WAL 差异推断通知减少或增加了多少业务 WAL，也不是生产 p95。

- 新 progress 接口为 **7 条业务读取**（含存量心跳），不读标签、未分类或建议聚合，也不请求模型。兼容 summary 保留原输出。认证 SQL 另计。
- 原执行器批次新增 **0 条调用端 SQL**、**0 个独立事务**、**0 个资源修订写入**、**0 次 S3**；数据库触发器工作与 NOTIFY 并非零成本，已单独测量。六万项整批入队／执行沿用现有隔离性能回归，不用一次无界六万行 UPDATE 代替原自动 SQL 分批。
