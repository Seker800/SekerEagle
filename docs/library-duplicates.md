# 图库查重清理

本地候选，2026-10-31。网页与桌面通过共用图库导航的「查重清理」进入；素材和照片分别按整库范围检查，不沿用图库搜索／筛选，入口明确说明范围；权限与私密可见性沿用原工作区。尚未部署现用图库，也没有扫描或清理现用照片。

## 实际使用

- 打开后立即显示已有文件哈希找到的完全重复项，不必先等待视觉检查。
- 「检查新内容」只为缺失／过期的视觉指纹排队；已有当前指纹复用。图片预览未就绪会明确计数，不能把没检查完当成没有重复。
- 检查在原独立主动操作进程中继续，关闭网页不影响执行。原任务中心可停止等待中的批次、查看错误和重试失败项；重试会重新发布视觉结果。
- 点击组卡片展开比较文件名、格式、像素、大小、入库／拍摄时间、评分、标签、说明、来源及实况／编辑副本提示。「放大比较」复用现有查看器，可在组内左右切换。
- 勾选始终表示保留。完全重复默认推荐一份，可自行更改；近似图片默认全部保留，只清理明确取消勾选的成员，未加载成员仍然保留。任何一组都必须留至少一份。
- 完全重复支持一次清理全部组，确认页显示组数和保留／清理数量。近似图片不能全库自动清理。
- 确认只提交持久命令，执行前再次核对账号、私密授权、租约、保留项和清理项版本、实况组件。变更冲突保留原件并在任务中心报告。
- 完全重复的独有人工标签和最高评分复制到保留项；说明、来源和编辑关系保留在原资源，比较页可检查。所有移除项进入原回收站；清空前不声称已经释放空间。
- 忽略结果持久保存，可切换「查看已忽略」恢复检查；成员或媒体版本变化后可以重新出现，普通改名／标签编辑不会清除忽略决定。
- 后台只展示小进度，不刷新、截断或滚动原图库。查重结果由「刷新结果」显式更新；分页遇到图库变化会要求刷新，避免重复或漏组。

## 依据与边界

完全重复使用已有 SHA-256 与文件大小；不同名字不影响判断。私密／公开边界不混组，两个库不混查。视觉近似使用当前缩略图的方向归一化 dHash、空间颜色、画幅和对比度；六个完整哈希分段用于查找候选，没有先截断候选数量。每个成员直接满足参考图条件，不用传递相似度串成长链。完全相同文件组的推荐参考图仍可与另一个压缩／转格式版本组成独立近似组。

视觉匹配不等于文件相同：连拍、RAW／JPEG、原片／成片可能都值得保留。没有用语义搜图向量或摄影分组推断可以删除。明显裁剪、旋转、较重编辑和低对比度图像可能查不到；当前机制优先减少错误候选，未宣称识别所有变体。原件不为查重而下载或重新解码。

流程参考：

- [Apple Photos 重复项整理](https://support.apple.com/guide/photos/remove-duplicates-pht5a3157c1d/mac)：分组审核、保留信息、可恢复移除。
- [digiKam Similarity View](https://docs.digikam.org/en/left_sidebar/similarity_view.html)：后台视觉指纹、只更新新增／变更内容、明确参考图与组内比较。这里没有照搬它的全对全比较，也不把相似度当文件相同。

## 运行与资源

沿用 `apps/api/dist/asset-operation-executor.js`，不在 HTTP API 启动后台循环。原操作表新增 `DUPLICATE_SCAN` 和 `DUPLICATE_CLEANUP`，扫描有独立车道，不占发送／回收的领取车道。索引、结果和忽略决定均按 owner／固定模式持久保存，结果读取再次核对当前权限与媒体版本，并用当前行版本生成审核凭据；普通元数据编辑复用视觉证据。

内部视觉批次为 16 张，读取并发为 2，用于限制网络缓冲和解码峰值；这是后台工作单位，用户不用拆批。单张读取超时 10 秒，缩略图解码最多 400 万像素。`EAGLE_DUPLICATE_PREVIEW_MAX_BYTES` 默认 2097152，保护每个预览读取缓冲；超出预算或预览损坏会使该批失败，可在任务中心重试，原件不受影响。通过该环境变量可为实际较大的缩略图调整字节预算。发布使用一条批量 UPSERT 验证当前 owner／模式／媒体版本，避免逐图重复读取数据库。

原操作的 `EAGLE_OPERATION_DB_BATCH_SIZE`、`EAGLE_OPERATION_SEND_CONCURRENCY` 和 `EAGLE_OPERATION_POLL_MS` 继续生效。查重资源与清理内部按 500 项摊销查询／写入，组内成员、组列表每次展示 24 项；没有产品数量配额。算法与结果存储不向执行节点引入数据库凭据。

升级必须包含两个新迁移和新的 API／独立执行器。原存储接管也补齐了「只有当前存储所有者的原件对象键唯一」约束；源所有权释放、目标独立派生记录创建、源派生记录退役在同一事务，失败整体回滚。历史复制计划保留原路径，测试通过预升级持久计划验证复制中断、版本变化和过期。生产切换仍须遵守现用运行文档中可信 worker 先支持接管标记的顺序，不能让旧 worker 清理已接管字节。

## 验收证据

证据在 `.omx/artifacts/duplicate-cleanup-20261031/`，仅隔离数据：

- 真实 PostgreSQL 六万资源，100 组完全重复；首屏实测约 136–148 毫秒，12 次 SQL（包括只读事务与 Prisma 关系读取）。这不是 NAS 生产延迟或 p95 承诺。
- 同一次提交 100 组：准入实测 12–13 次 SQL，一次准入事务；原件／派生对象存储请求均为零。后续每组一笔可恢复清理事务，内部租约领取和进度查询另计；没有每几组一个前端请求。
- 单个 1201 成员组一次审核并处理 1200 项，数据库读取与写入内部分批。
- 六万随机视觉指纹的纯分组实测约 0.33 秒；持久视觉分组在独立执行器执行，HTTP 不重复计算。
- 扫描准入一次 POST；每个新指纹最多一次当前缩略图 GET，当前指纹复查零 GET；每 16 张批量发布一笔事务。视觉组完成后一次原子结果发布。
- 页面初次一次结果 GET；每页至多 48 个缩略图地址，展开才读取组内成员。执行进度沿用现有小型轮询；完成后一次显式刷新结果，不重建原图库分页。
- 后端查重模块的隔离数据库测试，行覆盖约 99%、分支覆盖约 85%、函数覆盖 100%。真实 HTTP 验证会话、Origin、严格 DTO、跨库 404、独立执行进程、真实对象存储检查、清理和恢复。
- Chrome 实测双模式入口、组内比较、放大切换、确认及返回；界面截图为隔离的合成照片。

完整 lint、typecheck、unit、build、架构和数据库恢复结果，以本任务最终日志为准。

最终核验：完整 lint、typecheck、unit test、build 和架构门禁通过；共用数据库集成、历史升级及完整恢复通过。最后一次查重数据库专项为 15 项通过，模块覆盖率为行 99.10%、分支 85.66%、函数 100%；最后一次图库／查重／操作队列／工作区前端回归为 139 项通过。最终真实 HTTP 样例完成了 5 张图片的对象存储检查、重复项清理和回收恢复；Chrome 最终构建检查没有控制台错误。元数据改名不丢失视觉候选／忽略决定，隐私修订立即撤掉旧缓存均有回归。
