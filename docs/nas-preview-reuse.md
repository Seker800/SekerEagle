# 群晖现有预览的小批复用

这是一次性导入后的有界运维入口，不是外部目录图库。它只读挂载共享空间，复制派生 JPEG 到 SekerEagle 的 MinIO；日常浏览和 2B 输入仍从托管存储读取，源缓存消失不会影响已经复制的结果。

`apps/worker/src/synology-preview-pilot.ts` 接收私有冻结清单、只读共享空间根目录以及 `--plan` 或 `--apply`。清单包含原导入认证主体的 ownerId 与 1–100 个精确媒体版本，每项有 assetId、sha256、mediaRevision，以及 source 的相对 path、size、mtimeNs、inode、device。来源是已完成导入的 journal，不能使用浏览器 DTO 提供的 ownerId。

执行前运行安全目标检查。先计划，检查清单资源全部属于同一主体、PHOTO、当前未删除版本、相同原片 SHA；来源文件指纹必须仍与导入记录一致。拒绝符号链接、目录穿越、过期／损坏缓存、未应用的方向与比例不一致。不会重新散列全部原片；利用已校验的导入回执和稳定文件指纹，并确认托管原片存在、大小一致。

`--apply` 保留已完成的封面；对其余清单资源只重试现有渲染任务，沿用租约，并通过和普通 worker 相同的媒体发布事务登记。小批应用时先优雅暂停常驻 worker，完成或失败后恢复，避免重复处理。临时容器使用现有部署的同一私有运行环境，源目录只读，退出后自动移除。禁止删除存储卷或更改原片。

直接复用 SM、M、XL 的 JPEG 字节，记录实际 MIME 和宽高。256／512 是现有缩略图档位名称，不表示来源 JPEG 恰好是对应像素；群晖 M 常为 320×427，XL 常为 1280×1707。此方式省去重新解码原片和再编码，但不能提升既有缓存的质量，也可能比 WebP 占用更多空间。摄影参数从原片补读；不从缓存猜测相机、镜头或日期。RAW 编辑仍由原有链路负责，本次应用仅接受 JPEG／HEIC／HEIF，有动态组件时暂留原处理流程。

2026-10-23 实测：冻结最新 100 张，未向旧照片找替代样本。100 张缓存有效；96 张已有封面保留，4 张从群晖复制并发布，单张约 1.4–1.9 秒。12 个托管 JPEG 与来源逐字节散列一致；100 张原片标识、SHA、大小、尺寸、创建时间和添加时间保持不变；新增摄影时间、相机字段可用。浏览器大图正常，使用其中一个托管 JPEG 调用原有 2B 服务，约 1.9 秒返回有效的 1024 维归一化向量。本次没有全库切换、RAW／视频试跑或启用人脸／8B 标签，不能将 4 张测速外推成全库完成时间。

2026-10-23 后续修正：首页曾将未完成媒体分析的旧视频按入库时间排到最前面，导致“小批最新拍摄照片”和首页并非同一批。来源 journal 的日期独立补入 chronologicalAt，原有可靠捕获元数据及编辑继承优先；没有拍摄时间时使用已记录的来源文件日期，非法来源日期不伪造。按统一后的图库顺序冻结后续封面清单，已完成封面不重复处理；持续任务保留逐批检查点，不依赖 Mac 连接。右侧刻度复用相同字段，并定期刷新其全库索引。

原始尺寸缺失时，通过既有只读 ExifTool 标签读取补充尺寸、方向，不使用缓存分辨率冒充原图。RAW 的高清编辑来源及单文件动态组件保留独立版本维护任务 `photo-source-details-v1`；它不阻塞已复制的静态预览及向量输入，失败不将可浏览照片标成处理失败。普通 worker 和副本发布仍共用发布事务；维护阶段只补 RAW 编辑派生或动态组件，不重新覆盖已复制的普通 JPEG 预览，也不清空已有摄影信息。视频仍使用原来的封面及待转码任务。
